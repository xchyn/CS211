1.Where Class 10 left off: an object full of garbage

In Classes 9 and 10 you built the class Point1: two private double members, a set method to fill them in, two accessors, and a print. It was a real type. You could declare objects of it, call methods on it, and pass it to functions. And both of those classes ended with the same nagging footnote: the data members hold nothing meaningful until you call set.

Today that footnote gets fixed. But first, look straight at the problem, because a lot of students never quite believe it until they see it print.

Worked Example— a brand-new object, straight out of the box

This is exactly the Point1 class from Class 10, with a main that creates one object and immediately asks it what it holds. No set call anywhere. Decide what you think it prints before you open the toggle.

point1_uninit.cpp
// point1_uninit.cpp -- Class 10's Point1, with no constructor at all
#include <iostream>
using namespace std;

class Point1 {
public:
    double getx() const { return x; }
    double gety() const { return y; }
    void set(const double &a, const double &b) {
        x = a;
        y = b;
    }
    void print() const {
        cout << "print x,y " << x << " " << y << endl;
    }
private:
    double x, y;
};

int main() {
    Point1 dpt;
    dpt.print();
    cout << "get: " << dpt.getx() << " " << dpt.gety() << endl;
    return 0;
}

The professor's summary of this slide is worth quoting: "The compiler constructed the object dpt, but the values of x and y are uninitialized. The compiler does not automatically initialize the values of the data members. Hence this is a weak point in the design of the class Point1."

Note carefully what did not go wrong. The object exists. It has the right size. You can call its methods. The compiler built it. It simply built it without putting anything sensible inside.

So the compiler does construct objects for you, even when you never asked it to. It has to — Point1 dpt; has to mean something. What it uses is a function you never wrote.

Definition— constructor

A constructor is a special member function that the compiler calls automatically, exactly once, at the moment an object of the class is created. Its job is to put the object into a valid initial state.

You never call a constructor by name the way you call set or print. You trigger it, by declaring an object, by writing new, or by building an array. The compiler supplies the call.

If you write no constructor at all, the compiler generates one for you — the implicitly generated default constructor. That is the one that ran above, and the reason the output was garbage is that it does almost nothing.

(b) State the rule the implicitly generated default constructor follows.

The compiler-generated default constructor default-initializes every data member, and what that means depends on the member's type:

  • A member of class type gets its own default constructor called. string has one, and it produces the empty string, so name is reliably "".
  • A member of built-in type (int, double, char, any pointer) gets nothing at all. Its memory is left exactly as it was found.

That is why Point1, whose members are two doubles, came out as noise, and why a class made entirely of strings and vectors appears to behave itself even with no constructor. The second case is more dangerous than the first, because it lulls you into thinking the compiler initializes things.

The fix is the same in both cases: write your own constructor and take control.

2.The default constructor

To specify explicit rules for constructing an object, you write a constructor. C++ has several different kinds; we start with the simplest, the one that takes no arguments.

Definition— default constructor

A constructor is recognized by the compiler by two features, and both must be present:

  1. Its name is the same as the name of the class.
  2. It has no return type — not void, not int, nothing. The return type is not merely optional; writing one turns the function into an ordinary method that happens to share the class's name.

A default constructor is a constructor that additionally takes no input arguments. It is the constructor the compiler uses for a declaration like Point3 dpt;.

Worked Example— Point3: Point1 plus a default constructor

The class below is the professor's Point3. It is Point1, character for character, with four lines added at the top. Compare the output with the one in §1.

point3.cpp
// point3.cpp -- Point1 plus a default constructor
#include <iostream>
using namespace std;

class Point3 {
public:
    Point3() {              // default constructor
        x = 1.1;
        y = 2.4;
    }
    double getx() const { return x; }
    double gety() const { return y; }
    void set(const double &a, const double &b) {
        x = a;
        y = b;
    }
    void print() const {
        cout << "print x,y " << x << " " << y << endl;
    }
private:
    double x, y;
};

int main() {
    Point3 dpt;
    dpt.print();
    cout << "get: " << dpt.getx() << " " << dpt.gety() << endl;
    return 0;
}
print x,y 1.1 2.4
get: 1.1 2.4

Same on every machine, every run, forever. That is the difference a constructor makes.

Three things to see in those four lines:

  • Point3() — the name matches the class exactly, including capitalization, and there is no void in front of it. Those two facts are what tell the compiler this is a constructor.
  • The empty parentheses make it the default constructor.
  • Inside the body you assign to the data members by their plain names, exactly as you would inside set. A constructor is a member function, so it has full access to the private section.

The professor adds an aside worth repeating: "This is just a simple demo example. In real life applications it would be more usual to initialize x and y to zero." The values 1.1 and 2.4 are chosen only so you can tell at a glance that the constructor ran.

Nothing in main changed. There is no call to Point3() anywhere in the program you wrote. The compiler inserted it when it saw Point3 dpt;.

Key Idea— there is only one

Because the default constructor has no input arguments, it is unique. Two functions can only be overloaded if their parameter lists differ, and "no parameters" is a single possibility. So a class has at most one default constructor, and may have as many non-default constructors as you like, provided their argument lists differ.

Common Mistake— the empty parentheses that build nothing

To create an object using the default constructor you write the declaration with no parentheses at all:

Point3 dpt;       // correct: one object, built by the default constructor
Point3 dpt();     // WRONG: this declares a FUNCTION

The second line is a function declaration — a function called dpt that takes nothing and returns a Point3. No object is created. The next line you write then fails with a message that looks unrelated to the real mistake:

vexing.cpp:13:15: warning: empty parentheses were disambiguated as a function declaration [-Wvexing-parse]
   13 |     Point3 dpt();      // NOT an object
      |               ^~
vexing.cpp:13:15: note: remove parentheses to default-initialize a variable
vexing.cpp:14:9: error: request for member 'print' in 'dpt', which is of non-class type 'Point3()'
   14 |     dpt.print();
      |         ^~~~~

Read "which is of non-class type" as "you thought this was an object; it is not." Modern g++ names the trap for you in the warning; older compilers do not, which is why this puzzle has its own nickname in the C++ community — the most vexing parse.

Quick Check 13.2

For each of these, say whether it is a legal constructor for class Point3, and if not, what it actually is.

(a) void Point3() { x = 0; y = 0; }

Not a constructor. It has a return type, so the compiler treats it as an ordinary member function that happens to be named Point3 — which is itself illegal, because a member function may not have the same name as its class. g++ rejects it with "return type specification for constructor invalid".

This is the single most common way students break a constructor. If your constructor "never runs", check for a stray void.

(b) Point3() { x = 0; y = 0; } written in the private: section.

A perfectly legal constructor — it just cannot be used from outside the class, so Point3 dpt; in main will not compile. That is a real and occasionally useful design; we build one in §6.

(c) point3() { x = 0; y = 0; } (lowercase p).

Not a constructor. C++ is case-sensitive, so the name does not match the class. What you have written is an ordinary member function whose return type is missing, and g++ rejects it:

qc_c.cpp:5:5: error: ISO C++ forbids declaration of 'point3' with no type [-fpermissive]
    5 |     point3() { x = 0; y = 0; }
      |     ^~~~~~
qc_c.cpp: In member function 'int Point3::point3()':
qc_c.cpp:5:30: warning: no return statement in function returning non-void [-Wreturn-type]

Read the second message carefully: the compiler is calling it a member function returning int, not a constructor. Whenever g++ starts talking about a return value for something you believe is a constructor, the name is wrong.

(d) Two constructors in the same class: Point3() { x = 0; y = 0; } and Point3() { x = 1; y = 1; }.

Illegal. Both are default constructors, both take no arguments, so nothing distinguishes them. g++ says "'Point3::Point3()' cannot be overloaded with 'Point3::Point3()'". This is the Key Idea above, seen from the compiler's side: there is only ever one default constructor.

The wrap-up for all four parts: the compiler decides "this is a constructor" using only the name and the absence of a return type. Get either one wrong and you have silently written something else.

3.Non-default constructors and which one the compiler picks

A default constructor gives every object of the class the same starting values, which is rarely what you want. Usually the caller knows what the object should hold. So you write a constructor that takes arguments.

Definition— non-default constructor

A non-default constructor is a constructor with one or more input arguments. It is sometimes called a parameterized constructor. Its arguments come from the declaration that triggers it: Point4 pt43(a, b); passes a and b to the two-argument constructor.

A class may have many of them, as long as their parameter lists differ — this is ordinary function overloading, applied to constructors.

Here is the professor's Point4: one default constructor and two non-default ones, in a single class.

point4.cpp
class Point4 {
public:
    Point4()                    { x = 0; y = 0; }
    Point4(double a)            { x = a; y = a; }
    Point4(double a, double b)  { x = a; y = b; }
    double getx() const { return x; }
    double gety() const { return y; }
    void set(const double &a, const double &b) {
        x = a;
        y = b;
    }
    void print() const {
        cout << "print x,y " << x << " " << y << endl;
    }
private:
    double x, y;
};

Definition— converting constructor and explicit

A constructor that can be called with exactly one argument also defines an implicit conversion from that argument's type to the class type. It is called a converting constructor. Anywhere the compiler needs a Point4 and is handed a double, it may silently build one.

Putting the keyword explicit in front of the constructor switches that off. The constructor can still be called directly, but it will no longer be used behind your back.

Worked Example— a function that takes a Point4, handed a number

show takes a Point4. Two of these three calls pass it something that is not a Point4 at all. Predict what happens.

explicit_demo.cpp
void show(Point4 p) {          // takes a Point4 BY VALUE

}

int main() {
    Point4 pt(1.0, 2.0);
    show(pt);                  // obvious: pt is already a Point4
    show(7.5);                 // surprising: 7.5 becomes Point4(7.5)
    show(3);                   // even more surprising: int -> double -> Point4

All three compile and run. The second and third calls each construct a temporary Point4 on the spot, using Point4(double), and pass it to show. Nothing in the call site tells you a constructor ran.

Sometimes that is a pleasant convenience — it is why you can write string s = "hello"; even though "hello" is not a string. Sometimes it hides a genuine bug: if show were deposit(Money) and you passed a raw double, you would want to be told.

class Point4 {
public:
    Point4()                            { x = 0; y = 0; }
    explicit Point4(double a)           { x = a; y = a; }
    Point4(double a, double b)          { x = a; y = b; }
    // ... rest unchanged
};

4.Write one constructor and you lose the free one

This section is one sentence long and it is worth more exam points than anything else on this page.

Key Idea— the rule to memorize

If you write any constructor for a class — even a non-default one — the compiler will not generate a default constructor for you.

Put the other way round, in the professor's words: "The compiler automatically generates a default constructor only if we do not write any constructors for the class."

It is perfectly reasonable to design a class this way. You are not obliged to supply a default constructor; all of your constructors may be non-default. The consequence is simply that every object of the class must be created with arguments. As the notes put it, this is a common programming practice and there is nothing wrong with it — a BankAccount with no owner and no balance is arguably a bug waiting to happen, and refusing to build one is a defensible design.

What catches people out is that the loss of the default constructor is silent until something needs it. Here is Point5, which has exactly one constructor:

class A { public: int n; };

(b) B b;

Compiles. A default constructor is written explicitly, so it is used. b.n is 0. This is the version you want.

(c) C c;

Does not compile. C has a constructor — a non-default one — so no default constructor is generated, and none is written. "no matching function for call to 'C::C()'". Writing C c(5); works fine.

(d) D d;

Compiles. D writes both, so both are available.

The pattern across all four: the only class that gets a free default constructor is A, the one that wrote none. The moment a class declares any constructor, the free one disappears — and if you still want default construction, you have to write it yourself. This is the difference between (b) and (c), and it is the single most repeated trap in this course.

5.Arrays of objects, new and delete

You have been declaring arrays since CSCI 111 and allocating them with new since Class 8. Can you do the same with a class you wrote yourself? The professor poses the question and answers it carefully: "The obvious answer should be yes, but the correct answer is not always."

Key Idea— the array rule

You can declare an array of objects only if the class has a default constructor, and you may not pass constructor arguments in the array declaration.

The reason is simple once you see it: Point4 arr[10]; creates ten objects at once, and the syntax gives the compiler no way to say which arguments go to which element. So it uses the only constructor that needs no arguments.

6.Private constructors

The professor asks a short question here: "Can a constructor be private?" and answers it immediately: "Of course a constructor can be private. Anything can be private." The follow-up question is the interesting one — what does a private constructor mean?

Definition— private constructor

Just as private restricts access to the data members of a class, a private constructor restricts the ability of outside code to instantiate objects of the class at all.

The class itself — its own member functions — can still use it. Everyone else cannot. So you control not only what the outside world may do to your objects, but whether it may make them.

The original slide is four bullets of prose with no code. The demonstration below is written for these notes, because the idea is much easier to believe once you have seen it fail and then seen the way through.

  • In Class 25, when we build abstract base classes, the professor prefers protected constructors for exactly this reason: a base class should be constructible by its derived classes but not directly by anyone else. protected is the "private, except to derived classes" access level, and it arrives in Class 19.
Quick Check 13.8

A class is written with all of its constructors private and no other member function that creates objects.

(a) How many objects of that class can the rest of the program create?

None. Every path to creating an object goes through a constructor, and every constructor is unreachable from outside. The class becomes a container for static members and nothing else — occasionally that is exactly what someone wants, and more often it is a bug.

(b) In the Point6 listing above, why can create call the private constructor when main cannot?

Because create is a member of Point6. Access specifiers work per class, not per object: every member function of the class can reach every member of the class, private ones included. main is not a member of anything, so it only gets the public section.

This is the same rule that lets print() read the private x and y — you have been relying on it since Class 10 without needing to name it.

7.Member initializer lists

Every constructor written so far does its work in two steps. First memory is allocated for the data members; then, inside the function body, values are assigned into that memory. C++ offers a way to do it in one step: set the value at the same time the member is created.

Definition— member initializer list

A member initializer list is written between the constructor's parameter list and its body, introduced by a colon:

Point4a(double a, double b) : x(a), y(b)
{
    // function body -- often empty
}

The colon : signifies the start of the list. Each entry names a data member and gives, in parentheses, the value it is to be initialized with. After the list ends, the braces enclose the function body, which may be empty.

The professor's notes call this memberwise initialization. The standard term is member initializer list (he uses that phrase too); "memberwise" on its own usually means something else in C++, namely memberwise copying, which is Class 14.

Here is Point4 rewritten as Point4a. Nothing else about the class changes, and to any code outside the class the two behave identically.

Worked Example— the same three constructors, written the other way

Compare these three constructors with the ones in §3, line for line.

point4a.cpp
// point4a.cpp -- Point4 rewritten with member initializer lists
#include <iostream>

class Point4a {
public:
    Point4a()                   : x(0), y(0) {}

    Point4a(double a, double b) : x(a), y(b) {}

    double gety() const { return y; }
    void set(const double &a, const double &b) {
        x = a;
        y = b;

    double x, y;

And for the bottom two rows it is not a matter of efficiency at all; it is the difference between compiling and not compiling.

Key Idea— when the list is mandatory

You must use a member initializer list for:

  1. a data member declared const;
  2. a data member that is a reference;
  3. a member of a class type that has no default constructor; and
  4. from Class 20 onward, passing arguments to a base class constructor.

Item 4 is why the professor introduces this topic here at all: "Memberwise initialization is significant in some circumstances. We shall require it when we discuss the subject of inheritance for C++ classes."

Reason 1 should feel familiar. Back in Class 1 you saw that const double E = PI; is legal but const double E; E = PI; is two errors, because a const must be initialized where it is created and can never be assigned afterwards. A constructor body runs after the members have been created, so any assignment there is too late:

Quick Check 13.9

A class holds a student's ID number, which must never change once the object exists:

class Student {
private:
    string name;
    const int idNumber;
    int credits;
};

(a) Why can this class not have a compiler-generated default constructor?

Because the compiler's default constructor would leave idNumber uninitialized, and a const member may not be left uninitialized — there would be no later opportunity to give it a value. The compiler therefore defines the implicit default constructor as deleted, and Student s; fails with "use of deleted function". The same is true of a reference member.

(b) Write a constructor that takes a name and an ID and starts the student at zero credits.

    Student(const string &n, int id)
        : name(n), idNumber(id), credits(0) {}

idNumber has to be in the list. name and credits could legally be assigned in the body instead, but putting all three in the list is both shorter and one operation cheaper for name.

(c) Can addCredits(int n) change idNumber? Can it change credits?

It can change credits; it cannot change idNumber. Attempting the latter gives "assignment of read-only member 'Student::idNumber'" — the same phrasing you met in Class 1 for a const variable.

Wrap-up. Marking a member const is a design statement: this value is fixed for the lifetime of the object. It costs you the compiler-generated default constructor and forces every constructor to name it in the list. That is a fair price for having the compiler enforce the rule everywhere, forever.

Initialization happens in declaration order — always

Key Idea— the list does not control the order

Data members are initialized in the order they are declared in the class, not in the order they appear in the initializer list. In Point4a, x is declared first, so x is initialized first — even if you write : y(b), x(a).

The professor's note says of writing it out of order: "It does not matter: x is still initialized first and y second." That is correct as a statement about the language, but it is not quite the whole story, because g++ warns:

  • A compiler error is not a runtime event. If pt44 is present, no output appears — not even the lines for the objects that were fine.
  • The professor's slide describes pt44 as "commented out" while printing it uncommented. If an exam hands you a listing like this, comment the offending line out, note the error in the margin, and continue — which is precisely what the instruction on his trace questions tells you to do.
  • pt42 works only because Point4(double) is not explicit. Adding that keyword would turn pt42(i) into an error too — the conversion would still exist but would no longer be applied automatically.

Problem 2 — Arrays and dynamic allocation (from the course notes)

Still with Point4, and with Point5 (which has only Point5(double, double)):

(a) Which of these compile? Point4 arr[10]; · Point4 arr2[10](a, b); · Point5 arr3[10];

Only the first. Point4 has a default constructor, so ten objects are built with it. The second is illegal for every class — you may not pass constructor arguments in an array declaration. The third fails because Point5 has no default constructor.

array_err.cpp:18:31: error: array must be initialized with a brace-enclosed initializer
   18 |     Point4 array_pt43[10](a, b);      // ERROR
      |                               ^

(b) Rewrite the illegal Point4 arr2[10](a, b); two different legal ways.

Either name each element in a brace-enclosed list, or default-construct and then fill:

// (i) brace-enclosed initializer -- one constructor call written per element
Point4 arr2[3] = { Point4(a, b), Point4(a, b), Point4(a, b) };

// (ii) default-construct, then set in a loop
Point4 arr3[10];
for (int i = 0; i < 10; ++i) arr3[i].set(a, b);

Both print print x,y -3.6 5.4 for every element. Version (i) needs no default constructor but is only practical for a handful of elements; version (ii) scales to any size but requires one. For ten identical elements a vector is nicer than either: vector<Point4> v(10, Point4(a, b));

(c) Write the dynamic-allocation program: one Point4 built with the default constructor, one with the two-argument constructor, an array of three, all printed and all released. Give the output.

Plan. Three allocations, three releases, and the release form has to match the allocation form: delete for the two singles, delete [] for the array. Print through -> for the pointers to single objects and through subscripting for the array.

dynamic.cpp
// dynamic.cpp -- new and delete for a user-defined class
#include <iostream>
using namespace std;

class Point4 {
public:
    Point4()                   { x = 0; y = 0; }
    Point4(double a)           { x = a; y = a; }
    Point4(double a, double b) { x = a; y = b; }
    void print() const { cout << "print x,y " << x << " " << y << endl; }
private:
    double x, y;
};

int main() {
    int n = 3;
    double a = -3.6;
    double b = 5.4;

    Point4 *ptr40 = new Point4;          // default constructor
    Point4 *ptr43 = new Point4(a, b);    // non-default constructor
    Point4 *arr40 = new Point4[n];       // default constructor, n times

    ptr40->print();
    ptr43->print();
    for (int i = 0; i < n; ++i) {
        arr40[i].print();
    }

    delete ptr40;
    delete ptr43;
    delete [] arr40;
    return 0;
}
print x,y 0 0
print x,y -3.6 5.4
print x,y 0 0
print x,y 0 0
print x,y 0 0

Things to notice.

  • new Point4 and new Point4(a, b) both allocate one object; only the second passes arguments. new Point4[n] cannot pass any, so it insists on a default constructor.
  • Under valgrind --leak-check=full this program reports "All heap blocks were freed — no leaks are possible". Drop the delete [] arr40; and you leak three objects at once.
  • Notice what is not here: any code that frees memory automatically when the objects die. Every delete is written by hand, and forgetting one is silent. Class 14's destructor exists to take that job away from you.

Problem 3 — Rewrite with member initializer lists (from the course notes)

Rewrite the three constructors of Point4 to use member initializer lists instead of assignments in the body, then answer: if the two-argument constructor is written Point4a(double a, double b) : y(b), x(a) {}, in what order are the members actually initialized, and does the program still produce the right answer?

Plan. Each body assignment x = a; becomes a list entry x(a), moved in front of the braces and after a colon. Once every member is in the list, the body has nothing left to do and is written {}.

point4a.cpp
class Point4a {
public:
    Point4a()                   : x(0), y(0) {}
    Point4a(double a)           : x(a), y(a) {}
    Point4a(double a, double b) : x(a), y(b) {}
    double getx() const { return x; }
    double gety() const { return y; }
    void set(const double &a, const double &b) {
        x = a;
        y = b;
    }
    void print() const {
        cout << "print x,y " << x << " " << y << endl;
    }
private:
    double x, y;
};
print x,y 0 0
print x,y -3.6 -3.6
print x,y -3.6 5.4

The reordered version. Members are initialized in declaration order, and x is declared before y. So writing : y(b), x(a) changes nothing about what happens: x is still initialized first, y second, and the program still prints print x,y 1.5 2.5 for Point4a p(1.5, 2.5);.

It does, however, produce a warning:

reorder.cpp:9:15: warning: 'Point4a::y' will be initialized after [-Wreorder]
    9 |     double x, y;                                  // but x is declared first
      |               ^
reorder.cpp:6:5: warning:   when initialized here [-Wreorder]
    6 |     Point4a(double a, double b) : y(b), x(a) {}   // written y first
      |     ^~~~~~~

Things to notice.

  • The course notes say of the reordered list, correctly, "It does not matter." For two independent doubles it truly does not. The warning exists because the moment one member's initializer mentions another member, it matters enormously — see the Rect example in §7, which prints garbage for exactly this reason.
  • House rule for this course: write the list in declaration order, every time. It costs nothing and removes a whole category of bug.
  • set keeps its body assignments. It is not a constructor; the members already exist by the time it runs, so assignment is the only option there anyway.
  • A partial list is legal: Point4a(double a, double b) : x(a) { y = b; } compiles and behaves identically. Use it when a member's value needs several statements to work out.

Problem 6 — Write C++ statements (added)

Do not write a complete program; give a single line, or a few lines, of C++ for each task. Assume the Point4 class of §3 is available and that a and b are doubles.

Two arguments, so the two-argument constructor. No =, no new, and no empty parentheses anywhere.

(b) Declare an array arr of five Point4 objects.

All five are built with the default constructor. This line is only legal because Point4 has one; you cannot supply arguments here.

Point4 *r = new Point4[5];

Lecture Summary
  • A constructor is called automatically when an object is created. The compiler recognizes it by two features: the name matches the class and there is no return type.
  • A default constructor takes no arguments and is therefore unique — a class has at most one. Non-default constructors take arguments and a class may have as many as it likes, provided the argument lists differ.
  • If you write no constructor, the compiler generates a default one that default-initializes each member: class-type members get their own default constructor, built-in members get nothing and hold garbage.
  • The compiler picks a constructor by matching the arguments. It will apply standard conversions to find an acceptable match (int to double), and reports no matching function when none exists. A one-argument constructor also defines an implicit conversion; explicit switches that off.
  • Write any constructor and the free default constructor disappears. The compiler generates one only if you write none at all. Symptom: "no matching function for call to 'C::C()'".
  • Arrays of objects, and new T[n], require a default constructor and cannot be given constructor arguments. A single new T(args) can. Pair delete with new and delete [] with new[].
  • A private constructor restricts who may create objects at all, not just who may touch the data.
  • A member initializer list — : x(a), y(b) before the body — initializes members as they are created rather than assigning afterwards. It is required for const members, reference members, members whose class has no default constructor, and (from Class 20) base classes.
  • Members are initialized in declaration order, never in list order. Write the list in declaration order so the two agree.
