Classes I — Building Your Own Type

Four things you can do with any value in C++ — create it, copy it, assign it, destroy it — and the syntax that lets you build a type of your own that does all four.

1.A class is a type you write yourself

Class 1 gave you the vocabulary: a class is a blueprint, an object is an instance built from it, attributes are its data and methods are its behavior. Today that stops being vocabulary and becomes syntax. This is the class where C++ finally reaches the subject in the course title.

Start from something you already trust. Here is what you can do with an int:

int i, j, k;          // 1. CREATE: three int variables, in one statement
double x, y, z;       //    ...and three doubles

// 2. COPY: f(i) hands f a copy of i, if f takes its parameter by value

i = j;                // 3. ASSIGN: i already existed; now it holds j's value
x = y;

// 4. DESTROY: when i, j, k go out of scope they cease to exist

Four operations. You have used all four since your first program without once thinking of them as a set. The design decision at the heart of C++ is that a class you write yourself supports exactly the same four. Nothing about your own type is second class.

MyClass obj1, obj2, obj3;   // 1. CREATE (instantiate) three objects

// 2. COPY: pass an object to a function by value and it is copied

obj1 = obj2;                // 3. ASSIGN one object to another

// 4. DESTROY: objects are destroyed when they go out of scope,
//             and the memory allocated for them is released
Definition— instantiate, object

To instantiate a class is to create one object from it. The verb and the noun go together: Point apt; instantiates the class Point, and the thing it produces — apt — is an object of that class.

For a built-in type we say "variable"; for a class we usually say "object". They are the same idea. An object is a variable whose type you wrote.

Key Idea— the frame for the whole semester

Create. Copy. Assign. Destroy. Those four words are the syllabus for the second half of this course. Today the compiler does all four for you, silently and for free. Starting in Class 13 you will learn to take each one over yourself, in exactly this order, and every exam in this course asks you to write at least one of them.

It is worth seeing the map now, because it turns "a pile of unrelated topics" into "one topic, four times":

Today we use all four and write none of them. That is not laziness; it is the point of §5.

Quick Check 9.1

Consider this fragment, which uses only built-in types:

int a = 5;                  // (i)
int b = a;                  // (ii)
int c;
c = a;                      // (iii)
{
    int d = 9;              // (iv)
    c = d;                  // (v)
}                           // (vi)

(a) Label each of the six marked points with one of create, copy, assign, destroy. Two of them deserve two labels.

PointOperationWhy
(i)createa did not exist before this line; it is brought into being with the value 5.
(ii)create and copyb is brand new and starts life holding a duplicate of a. Both things happen in one statement.
(iii)assignc already existed. Its old value is overwritten. This is not a copy in the technical sense — the object was already there.
(iv)createA new variable inside the inner block.
(v)assignAgain, c already exists.
(vi)destroyThe closing brace ends d's scope. d is gone.

The distinction between (ii) and (iii) looks like hair-splitting for an int. For an object it is the difference between two entirely different functions you will have to write — the copy constructor and operator= — so start making the distinction now.

(b) A function is declared void f(Point p); and called as f(a);. Which of the four operations happens at the call, and which happens when f returns?

At the call: create and copy. The parameter p is a new object, created and filled with a duplicate of a. That is precisely what "call by value" means — the mechanism you took apart in Class 2, now applied to an object instead of an int.

When f returns: destroy. p goes out of scope and ceases to exist. Whatever f did to p dies with it, which is why a is unchanged back in the caller.

For a Point holding two doubles this costs 16 bytes of copying and nobody notices. For an object that owns a megabyte of dynamic memory it is a very different story, and that is the problem Class 14 exists to solve.

2.Declaring a class: class Point

Here is the entire syntax, in five lines. Read it, then we will take it apart word by word.

class Point {
public:
    double x, y;
};
Definition— class, data member

At its simplest, a class is a container of data. The declaration above says: there is now a type called Point, and every Point contains two coordinates, x and y, both of type double.

A variable declared inside a class is called a data member of that class. (Class 1 called these attributes; C++ calls them data members, and so will the exams.) x and y are the two data members of Point.

Now the pieces:

PieceWhat it does
classThe keyword that starts a class declaration. Lower case, always.
PointThe name you are inventing. From this line on, Point is a type name and may be used anywhere int or double could be. Capitalizing class names is a convention, not a rule — but follow it.
{ … }The class body. Everything the class contains goes between these braces.
public:An access specifier. Everything written after it is visible to the outside world.
double x, y;Two data members. Ordinary declaration syntax — a type, then a comma-separated list of names, then a semicolon.
;The terminating semicolon. Not optional. See below.

Two things this declaration does not do, both worth saying out loud. It does not set aside any memory — a blueprint is not a house. And it does not give x and y any values; there are no values yet, because there is no object yet.

The keyword public

The keyword public means all the items in the class are visible to outside applications. Any other part of the program can read or write the values of x and y. That is a strong statement, and by the end of next class you will think it is usually a bad idea — but for today it is exactly what we want, because it lets us look at the mechanics of a class without anything getting in the way.

There are two other access specifiers, private and protected. private is the one that makes encapsulation real, and it arrives in Class 10. protected only starts to matter once classes inherit from one another, in Class 19.

Common Mistake— forgetting public: entirely

If you leave the public: line out, the class still compiles — but every member of a class is private by default, so the first line of main that touches apt.x fails:

nopublic.cpp: In function 'int main()':
nopublic.cpp:10:9: error: 'double Point::x' is private within this context
   10 |     apt.x = 2.5;
      |         ^
nopublic.cpp:5:12: note: declared private here
    5 |     double x, y;
      |            ^

The word private in an error message when you never typed the word private is a reliable sign of exactly one thing: a missing public:. Note also that the errors land in main, several lines below the actual omission — the class itself is perfectly legal.

That semicolon after the closing brace

Key Idea— };

A class declaration is terminated by a semicolon. The semicolon after the closing brace looks peculiar — and it is peculiar — but it is necessary. The code will not compile without it.

Functions end with a plain } and no semicolon. Classes end with };. You will get this wrong. Everyone does, several times, and then never again.

The reason is that C++ lets you declare variables in the same statement that declares the class, like this:

class Point {
public:
    double x, y;
} origin, corner;         // legal C++: declares the class AND two objects

Because that is allowed, the compiler cannot know the declaration is finished until it sees a semicolon. The feature itself is obscure and we shall never use it in this course — but the semicolon it forces on everyone is not optional.

Worked Example— leave the semicolon off and read the error

Your professor's advice on this point is one word: try it. So here it is, tried. This file is correct in every respect except that the class ends with } instead of };. Before you open the toggle, guess which line number the compiler will blame.

// nosemi.cpp -- the terminating semicolon after the class has been left off
#include <iostream>

}

    apt.y = 2.0;

Modern g++ handles this one gracefully: a single error, pointing at the exact character, with the missing ; drawn underneath. Older compilers — and g++ itself, if the mistake is tangled up with anything else — report a cascade of nonsense starting at int main, several lines below the real problem.

That is the general lesson about compiler errors and it is worth more than the specific one: the reported line is where the compiler noticed, not necessarily where you erred. When an error points at a line that is obviously fine, look upward.

Data members can be any type

Nothing restricts a class to two doubles. A class can contain data members of any type — int, string, arrays — and it can even contain objects of other classes.

Worked Example— a class with three different member types

A Book needs a title, a page count and a price, and no two of those are the same type. Predict all three lines of output — one of them has a formatting trap in it that we met back in Class 3.

book.cpp
// book.cpp -- a class whose data members are not all the same type
#include <iostream>
#include <string>
using namespace std;

class Book {
public:
    string title;
    int    pages;
    double price;
};

int main() {
    Book b1;
    b1.title = "The C++ Programming Language";
    b1.pages = 1368;
    b1.price = 59.99;

    Book b2;
    b2.title = "Effective C++";
    b2.pages = 320;
    b2.price = 39.50;

    cout << b1.title << ", " << b1.pages << " pages, $" << b1.price << endl;
    cout << b2.title << ", " << b2.pages << " pages, $" << b2.price << endl;
    cout << "pages together = " << b1.pages + b2.pages << endl;
    return 0;
}
The C++ Programming Language, 1368 pages, $59.99
Effective C++, 320 pages, $39.5
pages together = 1688

The trap is on line two: 39.50 prints as 39.5. cout drops trailing zeros from a double by default, which for a price is exactly the wrong thing. Fixing it needs fixed and setprecision(2) from Class 3 — and noticing that you need to fix it is the real skill.

Two structural points. First, b1 and b2 are two separate objects, each with its own title, its own pages and its own price; setting b2 had no effect on b1. Second, b1.pages + b2.pages is ordinary int arithmetic — once you have reached a data member with the dot, it is just a variable like any other.

A class can also hold objects of another class. A line segment is two points:

segment.cpp
// segment.cpp -- a class whose data members are objects of another class
#include <iostream>
using namespace std;

class Point {
public:
    double x, y;
};

class Segment {
public:
    Point a, b;          // two Point objects live inside every Segment
};

int main() {
    Segment s;
    s.a.x = 0.0;
    s.a.y = 0.0;
    s.b.x = 3.0;
    s.b.y = 4.0;

    cout << "from (" << s.a.x << ", " << s.a.y << ")"
         << " to (" << s.b.x << ", " << s.b.y << ")" << endl;
    return 0;
}
from (0, 0) to (3, 4)

Read s.a.x from left to right: take the object s, get its member a (which is itself a Point), then get that object's member x. The dots chain as far as the nesting goes. Note that Point must be declared before Segment, because the compiler has to know how big a Point is in order to lay out a Segment.

3.Objects, and the dot operator

The declaration created a type. Now use it.

Definition— the dot operator

The dot operator . is the "member of" operator for a C++ class. The expression apt.x means the data member x inside the object apt.

It is an ordinary operator with an ordinary result: apt.x is a double variable, and you can do anything to it that you can do to a double. Read it, write it, add to it, pass it to a function.

Notice the shape of it: the object goes on the left, the member name goes on the right. Not the class — the object. Point.x is meaningless, because the class has no x; only the objects do.

Worked Example— the first complete class program

This is your professor's first class program, and it is deliberately as small as a class program can be. Predict both lines of output exactly — and be careful with the second one.

point_first.cpp
// point_first.cpp -- declare a class, create one object, use the dot operator
#include <iostream>
using namespace std;

class Point {
public:
    double x, y;
};

int main() {
    Point apt;

    apt.x = 2.5;
    apt.y = 2.0;

    cout << apt.x << endl;
    cout << apt.y << endl;
    return 0;
}
2.5
2

The second line is 2, not 2.0. apt.y really does hold the double value 2.0, but cout drops trailing zeros. This is the Class 3 formatting rule, and it costs points on exams every single term. When you are asked to write down what a program prints, write 2.

Now the structure, statement by statement:

StatementWhat happens
class Point { ... };Declares a type. No memory is set aside. The compiler now knows that a Point is two doubles.
Point apt;Creates — instantiates — one object. This is what occupies memory: 16 bytes of it, on the stack, in main's frame. The type name goes first, exactly as in int n;.
apt.x = 2.5;Reaches inside apt and writes 2.5 into its x. The dot operator is on the left of an assignment here, which is fine — apt.x names a variable.
cout << apt.xReaches inside apt and reads its x. Same operator, other direction.

One more observation that matters more than it looks. Nowhere in this program did we tell the compiler how to make a Point. We never wrote a function to build one. And yet Point apt; worked. That is §5.

Quick Check 9.3

Using the Point class from the program above:

(a) Write the statements that create two objects, p and q, set p to (1, 2) and q to (9, 9), and print both.

    Point p;                                       // create
    Point q;                                       // create
    p.x = 1.0;   p.y = 2.0;                        // set p

The two declarations can also be combined into Point p, q; — exactly as with int. Either is correct.

(b) How many copies of the variable x now exist in memory?

Two. One inside p, one inside q. Data members are per-object; that is the entire reason objects exist. Writing to q.x cannot possibly affect p.x.

The class itself has no x at all. If it did, all objects would share it, and the whole idea would collapse.

(c) A student writes Point.x = 5.0;. What is wrong, and what does g++ say?

Point is a type, not an object. Asking for the x of a type is like asking for the street address of the word "house". The dot operator needs an object on its left.

classdot.cpp:8:10: error: expected unqualified-id before '.' token
    8 |     Point.x = 5.0;
      |          ^

The fix is to name an object: apt.x = 5.0;. If you find yourself wanting to store one value shared by all objects of the class, C++ does have a feature for that — static data members, in Class 16 — and it is spelled quite differently.

4.Born with garbage: uninitialized data members

Every program on this page so far has been careful to set both members before reading either one. That was not an accident. Here is what happens if you do not.

Worked Example— printing a Point nobody set

This program creates a Point and immediately prints it. What are the two numbers? Commit to an answer — most people say "0 and 0" — and then look.

uninit.cpp
// uninit.cpp -- reading data members that were never set. Undefined behavior.
#include <iostream>
using namespace std;

class Point {
public:
    double x, y;
};

int main() {
    Point apt;                 // x and y are NOT zero -- they hold whatever was there
    cout << "x = " << apt.x << endl;
    cout << "y = " << apt.y << endl;
    return 0;
}

First, compiling it with -Wall is already informative:

uninit.cpp: In function 'int main()':
uninit.cpp:12:27: warning: 'apt.Point::x' is used uninitialized [-Wuninitialized]
   12 |     cout << "x = " << apt.x << endl;
      |                           ^
uninit.cpp:11:11: note: 'apt' declared here
   11 |     Point apt;                 // x and y are NOT zero -- they hold whatever was there
      |           ^~~

It compiles anyway — a warning is not an error — and here are two consecutive runs of the same executable on the same machine:

x = 0
y = 6.95296e-310
x = 0
y = 6.95293e-310

Those numbers are representative, not reproducible. On your machine you will get different ones, and you may well get different ones on two runs in a row, as happened here. That is the whole point.

Notice how cruel the x = 0 is. It looks like the members are initialized to zero, and a student who tests only x walks away believing something false. The zero is not a guarantee; it is whatever bytes happened to be sitting at that address, and this time they happened to be zeros.

Definition— undefined behavior

An operation has undefined behavior when the C++ standard places no requirement at all on what happens. The program may print garbage, print something plausible, crash, or behave differently every time it runs. The compiler is not obliged to warn you, and it is allowed to assume you never do it.

Reading a variable that was never given a value is undefined behavior. It is not "reading zero", and a program that appears to work is not evidence to the contrary.

Warning— every object on this page is born uninitialized

A class with public data and no constructor — which is every class on this page — leaves its data members indeterminate from the moment the object is created until something assigns to them. Point apt; does not zero anything out. It reserves 16 bytes and hands them to you exactly as they were.

So there is a rule for today, and you must apply it by hand every time:

  • Set every data member before you read any of them.
  • Set them all. Setting apt.x and forgetting apt.y is the common version of this bug, and the half that works hides the half that does not.
  • Compile with -Wall. g++ catches the simple cases, as it did above.

This is not a permanent state of affairs. In Class 13 you will write a constructor — a function the compiler calls automatically at creation — and from then on Point apt; can guarantee (0, 0), or whatever else you decide. Every class you write after Class 13 will have one, and this whole category of bug disappears. Today we are working without a safety net, deliberately, so that you can see what the net is for.

Quick Check 9.5

Consider these two fragments, both using class Point { public: double x, y; };.

// fragment A
Point p;
p.x = 3.0;
cout << p.x + p.y << endl;

// fragment B

q.x = 3.0;
q.y = 4.0;

(a) What does fragment B print, and what does fragment A print?

Fragment B prints 7. Both members were set, the arithmetic is ordinary, and the trailing .0 is dropped by cout.

Fragment A has no answer. p.y was never set, so p.x + p.y reads an indeterminate value and the behavior of the whole program is undefined. "It prints 3" is wrong. "It prints 3 plus garbage" is closer, but the honest answer on an exam is undefined behavior — p.y was never initialized.

(b) A classmate runs fragment A, gets 3, and concludes that data members start at zero. What is the flaw in the reasoning?

They tested one machine, one compiler, one build, one run. Undefined behavior is allowed to look correct — that is what makes it dangerous rather than merely annoying. The same binary produced two different values for y on two consecutive runs in the worked example above.

The reasoning error has a name worth carrying with you: absence of a symptom is not evidence of correctness. In C++ a large fraction of the worst bugs are of exactly this kind, which is why we lean on -Wall, on tools like valgrind, and from Class 13 on constructors that make the question impossible to ask.

5.What the compiler writes for you

Go back to point_first.cpp and notice what is missing. We declared two data members and nothing else — no functions of any kind. And yet Point apt; created an object, and when main ended that object was cleaned up. Somebody did that work.

Key Idea— the four free functions

If you do not specify explicit rules for a class you define, the compiler automatically generates functions to perform these operations by default:

  1. Create (instantiate) an object.
  2. Copy an object — recall "call by value".
  3. Assign an object — recall x = y.
  4. Destroy an object when it goes out of scope.

The same four from §1. This is why a class with no functions in it is still a usable type.

And the compiler throws in more than that. It also knows how to build, without being told:

  • arrays of objects — Point corners[3];
  • pointers to objects — Point *p;
  • new and delete for your class, so objects can live on the heap
  • sizeof, so you can ask how big one of your objects is
Warning— the default is not always what you want

The compiler's automatic versions of those four operations are simple-minded: they work member by member. For a Point made of two doubles that is precisely right, and you should not write a line of your own.

The moment a class contains a pointer to memory it owns, the defaults become actively wrong. Copying member by member copies the pointer, so two objects end up pointing at the same block; the first one destroyed frees it and the second is left holding a dangling pointer. That failure is the reason Classes 13–15 exist, and writing the four functions correctly is this professor's single most frequent exam question. For today, the defaults are exactly right — enjoy it.

sizeof on a class you wrote

You write sizeof(Point) in the same way you write sizeof(int). There is one surprise in it.

Worked Example— the size of an object is not always the sum of its parts

Point holds two doubles; Tag holds a char and an int. Work out all six numbers before you reveal them. One of them is not what arithmetic says.

sizes.cpp
// sizes.cpp -- sizeof works on a class you wrote, exactly as it works on int
#include <iostream>
using namespace std;

class Point {
public:
    double x, y;
};

class Tag {
public:
    char letter;
    int  count;
};

int main() {
    cout << "sizeof(double) = " << sizeof(double) << endl;
    cout << "sizeof(Point)  = " << sizeof(Point)  << endl;

    cout << "sizeof(char)   = " << sizeof(char)   << endl;
    cout << "sizeof(int)    = " << sizeof(int)    << endl;
    cout << "sizeof(Tag)    = " << sizeof(Tag)    << endl;

    Point apt;
    apt.x = 1.0;
    apt.y = 2.0;
    cout << "sizeof(apt)    = " << sizeof(apt)    << endl;
    return 0;
}
sizeof(double) = 8
sizeof(Point)  = 16
sizeof(char)   = 1
sizeof(int)    = 4
sizeof(Tag)    = 8
sizeof(apt)    = 16

Point is 16, which is 8 + 8, exactly as expected. Tag holds a 1-byte char and a 4-byte int — that is 5 bytes of data — and sizeof(Tag) comes back 8.

The extra three bytes are padding. The machine reads a 4-byte int fastest when it sits at an address divisible by 4, so the compiler leaves a three-byte hole after letter to line count up, and then rounds the whole object up to a multiple of 4 so that arrays of Tag stay aligned too.

Key Idea

The size of an object is not necessarily the sum of the sizes of its data members. Always use the sizeof operator and do not attempt to outsmart the compiler. Any program that computes an object's size by adding up its members by hand is a program that will break on some machine, some day.

Last line: sizeof works on an object as well as on a type name, and sizeof(apt) is sizeof(Point). Note also that the size does not depend on the values — every Point that ever exists is 16 bytes.

The honest answer is "probably 24, and I would use sizeof rather than trust that."

That is the right prediction on every mainstream compiler, and it is still a prediction. The rule from the worked example stands: use the operator, do not do the arithmetic in your head and bake the answer into your program.

6.Copy and assign, today

§5 claimed the compiler gives you copy and assignment for free. Let's watch it happen, because "for free" turns out to mean something very specific: member by member.

Definition— memberwise copy

The compiler's default copy and default assignment both work the same way: they copy each data member of the source object into the corresponding data member of the destination, one at a time, using that member's own copy rules.

For a Point, that means b.x = a.x; and b.y = a.y; and nothing else. The two objects are afterwards completely independent — changing one cannot touch the other.

7.The dot operator's precedence

The dot is an operator, so it has a place in the precedence table, and its place is very near the top.

Key Idea— the precedence rule
  1. The dot operator has higher precedence than +, -, *, /, ++ and --.
  2. Only the parentheses () and bracket [] operators have higher precedence than the dot.

Practically: the dot goes first. Whatever else is in the expression, the member is fetched before anything is done to it.

For the arithmetic operators this is the only sane arrangement, and it is why nobody ever notices it. The dot in apt.x and apt.y binds more strongly than the +, so apt.x + apt.y is the sum of the two members. It could not reasonably mean anything else — the alternative reading, apt.(x + apt).y, is not even grammatical.

The last row is where the rule stops being invisible. If p is a Point *, then *p.x does not mean "dereference p, then take x". The dot outranks the *, so the compiler tries to take the member x of the pointer p and then dereference the result — and pointers have no members.

8.apt.x++ and --apt.y

Arithmetic was the easy case. Now combine the dot with ++ and --, which Class 3 taught you to distrust. This combination — member access plus increment inside an output statement — is the exact shape of this professor's output-prediction exam questions, so it is worth being slow and careful here.

The rule from §7 does all the work. Take apt.x++:

Procedure— reading apt.x++ and --apt.y

For apt.x++:

  1. First apply the dot operator and get apt.x — the double variable living inside apt.
  2. Then apply the ++ operator, incrementing the value of x in apt.

For --apt.y, in spite of the -- being written first:

  1. First apply the dot operator and get apt.y.
  2. Then apply the -- operator, decrementing the value of y in apt.
  3. The -- does not apply to the object apt. It would make no sense to "decrement the object apt" — and the compiler would reject it, because you have not told it what that would mean.

Written out: --apt.y is --(apt.y), never (--apt).y.

There are four such expressions for each member — ++apt.x, --apt.x, apt.x++ and apt.x-- — and the prefix/postfix distinction is exactly the one from Class 3, unchanged: all four step the member by 1, and what differs is the value the expression hands back. Prefix hands back the new value, postfix the old.

Why the language requires it. C++ lets you declare objects in the very statement that declares the class:

class Point {
public:
    double x, y;
} origin, corner;      // declares the class AND two Point objects

Because that is legal, the compiler cannot tell that the declaration is over until it sees a semicolon. The feature is obscure and we will never use it in this course — but the semicolon it forces on everybody is mandatory.

Things to notice.

  • No executable is produced. This is a compile-time error, so nothing runs.
  • g++ 13 reports it cleanly, at the right character, and even draws the missing ;. That is a modern luxury. Tangle this mistake up with anything else — a missing brace, say — and you get a cascade of errors starting well below the real problem.
  • The mirror-image mistake is putting a semicolon after a function body, where it does not belong. Functions end with }; classes end with };.

Problem 3 — Write C++ statements (from the Summer 2024 Midterm)

Do not write a complete program; give a single line, or a few lines, of C++ for each task. You are given the following class:

class Point {
public:
    int x, y;
};

(a) Declare a Point object a and set its value to (3, 4).

    Point a;
    a.x = 3;
    a.y = 4;

Three statements, not one. There is no way to write Point a(3, 4); until we have constructors in Class 13 — and on the exam where this question was set, constructors had not been covered either, so the three-line answer was the expected one.

(b) Declare a pointer p that dynamically allocates memory for a Point.

    Point *p = new Point;

The type of the pointer is Point * and new Point returns exactly that. Note that no parentheses are needed after Point — and note that the object it creates has, once again, two indeterminate members.

(c) Copy the data in a into the Point that p points to.

    (*p).x = a.x;
    (*p).y = a.y;

The parentheses around *p are compulsory: the dot outranks the *, so *p.x would be parsed as *(p.x) and rejected (§7).

A shorter answer also works, because the default assignment copies member by member:

    *p = a;                // assign the whole object at once

Both are correct. The exam's own answer key gives the member-by-member version, plus the p->x = a.x; spelling that we meet in Class 10.

(d) Print the Point that p points to, in the form (3, 4).

    cout << "(" << (*p).x << ", " << (*p).y << ")" << endl;

The original exam supplied the class with a print() method and asked for p->print();. Both the method and the arrow are Class 10 material, so here we do the printing by hand — which is what the method would have done anyway.

(e) Release the memory for p.

    delete p;

Plain delete, not delete [] — one object was allocated with new Point, not an array with new Point[n]. Getting that pairing wrong is undefined behavior, and it is worth points on this professor's exams every term.

Here are all five parts assembled into a program that compiles, runs, and gives back every byte it allocated:

statements.cpp
// statements.cpp -- the five statements of the exam question, assembled into a program
#include <iostream>
using namespace std;

class Point {
public:
    int x, y;
};

int main() {
    Point a;                                  // (a)
    a.x = 3;
    a.y = 4;

    Point *p = new Point;                     // (b)

    (*p).x = a.x;                             // (c)
    (*p).y = a.y;

    cout << "(" << (*p).x << ", " << (*p).y << ")" << endl;   // (d)

    delete p;                                 // (e)
    return 0;
}
(3, 4)

This question is worth 15 points, 3 per part, with no partial credit — and it is the same five tasks every single term, with the class renamed (Point, Rectangle) and the numbers changed. It is the cheapest 15 points on the paper if you have practiced it, and the answers are short enough to write from memory. Practice it until it is automatic.

Problem 5 — Write a complete C++ program (added)

Write a complete C++ program that does the following. Declare a class Rectangle with two public double data members, width and height. In main, let the user enter width-and-height pairs until they enter 0 0, storing each rectangle in a vector. Then print how many rectangles were entered, the total area, the average area, and finally every rectangle whose area is strictly greater than the average. If no rectangles were entered, say so and stop.

Plan. This is the professor's Problem 1 shape from every midterm — sentinel-controlled input loop, store into a vector, compute an aggregate, print a filtered subset — with a class in place of a plain int. Four stages:

  1. Declare the class above main, with public: and the closing };.
  2. Read the first pair before the loop, then loop while the pair is not the sentinel, reading the next pair at the bottom of the body. Build a local Rectangle, fill both members, push_back it.
  3. Guard the empty case before dividing by n — dividing by zero here would produce nan and a nonsense report.
  4. One pass to total, then a second pass to print the ones above average. Two passes are needed because you cannot compare against an average you have not finished computing.
rect_report.cpp
// rect_report.cpp -- read rectangles until 0 0, report the ones above average area
#include <iostream>
#include <vector>
using namespace std;

class Rectangle {
public:
    double width, height;
};

int main() {
    vector<Rectangle> shelf;
    double w, h;

    cout << "Enter width and height pairs (0 0 to stop): ";
    cin >> w >> h;
    while (!(w == 0 && h == 0)) {
        Rectangle r;
        r.width  = w;
        r.height = h;
        shelf.push_back(r);
        cin >> w >> h;
    }

    int n = shelf.size();
    if (n == 0) {
        cout << "No rectangles entered." << endl;
        return 0;
    }

    double total = 0.0;
    for (int i = 0; i < n; ++i) {
        total = total + shelf[i].width * shelf[i].height;
    }
    double average = total / n;

    cout << "count   = " << n << endl;
    cout << "total   = " << total << endl;
    cout << "average = " << average << endl;

    cout << "above average:" << endl;
    for (int i = 0; i < n; ++i) {
        double area = shelf[i].width * shelf[i].height;
        if (area > average) {
            cout << "  " << shelf[i].width << " x " << shelf[i].height
                 << " has area " << area << endl;
        }
    }
    return 0;
}

Things to notice.

  • vector<Rectangle> works with no effort on your part. A vector can hold objects of a class you wrote for exactly the reason §5 gave: the compiler already generated the create, copy, assign and destroy operations that the vector needs in order to store and move its elements.
  • push_back(r) stores a copy of r. The local r is destroyed at the bottom of each loop iteration and the vector's copy lives on — §6 in action.
  • The prompt appears once and the typed numbers are not echoed back, so the output above starts with the prompt and the report on the same line. That is normal for a program reading from the keyboard, and it is what the professor's own sample transcripts look like.
  • total / n is double / int, so the division is floating point. If you had made total an int you would get integer division and a wrong average.
  • Strictly greater: the 3 x 4 rectangle has area exactly 12, below the average of 14, and is excluded. Test a case that lands exactly on the boundary — the professor's own rubrics make a point of it.
  • Points on this question are awarded per stage: standard beginning and ending, declaring the storage, reading the input, computing the aggregate, printing the filtered subset. Write every stage even if one of them is wrong.

Lecture Summary
  • C++ supports four operations on every type: create, copy, assign, destroy. A class you write yourself supports all four, exactly as int does. Those four words are the plan for Classes 13–15.
  • A class declaration is class Name { public: ...members... };. It declares a type and sets aside no memory. The semicolon after the closing brace is mandatory; leaving it off gives "expected ';' after class definition".
  • A variable declared inside a class is a data member. Members may be any type, including objects of other classes. public: makes everything after it reachable from outside; without it, members are private and unreachable.
  • Point apt; instantiates an object — this is what occupies memory. The dot operator reaches a member of an object: apt.x reads or writes the x inside apt. The object goes on the left, never the class name.
  • With no constructor, a new object's data members are indeterminate, not zero. Reading one is undefined behavior. Set every member before you read any. Constructors fix this in Class 13.
  • The compiler generates create, copy, assign and destroy for you, plus arrays of objects, pointers to objects, new/delete, and sizeof. The defaults work member by member — right for a Point, wrong the moment a class owns a pointer.
  • sizeof(Point) is written like sizeof(int), and the size of an object is not necessarily the sum of its members' sizes — padding. Never compute it by hand.
  • The dot operator has higher precedence than + - * / and ++ --; only () and [] outrank it. So --apt.y means --(apt.y), and *p.x means *(p.x) — which is why you must write (*p).x.
  • apt.x++ applies the dot first and then increments the member. Inside a cout chain the operands go strictly left to right and the side effects carry forward to the next line — the Class 3 rules, unchanged.
