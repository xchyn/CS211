How to use these notes
  1. Predict before you reveal. Every worked example shows you the program but hides its output behind a Show Output & Explanation toggle. Decide what it prints first, then open the toggle. Reading the answer straight away feels faster and teaches you almost nothing.
  2. Do the Quick Checks as you go. They sit between concepts, not at the end, because each one tests the thing you have just read. Every one has a full worked solution behind a Show Answer toggle.
  3. Use the Show all / Hide all buttons at the top of each page. Hide all before a revision pass turns the page into a problem set; Show all turns it back into a textbook.
  4. Type in the orange boxes. Each in-class exercise has a live-coding area pre-loaded with starter code. It does not compile or run anything — use Copy and paste into your own compiler when you want to actually run it. Anything you type is lost when you reload the page.
  5. Print a page and the answers stay hidden. Whatever is closed on screen is left out of the printout, and the live-coding boxes print as blank ruled boxes, so a printed page works as a worksheet.
  6. Every output shown is real. Every program on these pages was compiled with g++ and run; the output blocks are what it actually printed.

What the course covers

A quick refresher on CSCI 111 material, then file I/O, vectors, pointers, C++ classes with constructors and destructors, static data and methods, namespaces, operator overloading, friendship, inheritance, templates, and a short introduction to the Standard Template Library. The same nine box types appear on every page, always in the same color. After the first class you should be able to tell what a box is for without reading its header.

Learning Objectives

Indigo, once at the top of every page. What you should be able to do by the end of the class. Read it first, and read it again afterwards as a self-test.

Definition— the term being defined

Blue. A term is always defined in one of these before it gets used casually. If a word suddenly seems to have arrived from nowhere, look back for the blue box.

Worked Example— what it demonstrates

Green. A complete, runnable program. The code is visible; the output and the explanation are hidden behind a toggle so you can predict first.

Procedure

Purple. A recipe you can follow step by step — how to compile, how to decide between two designs, how to write a class from a problem statement.

Key Idea

Amber. The one sentence worth leaving the room with. If you remember nothing else from a class, remember the amber boxes.

Common Mistake

Red. A bug you are actually going to write, or a place where something that looks right compiles and then does the wrong thing. Red boxes are where the marks go missing.

Quick Check

Cyan. A short exercise placed right after the concept it tests. Eight to twelve per class, numbered by class — Quick Check 7.3 is the third in Class 7. Full worked solution behind the toggle.

Practice Problems

Magenta, once near the end of each page. Longer, exam-shaped problems with complete worked solutions: the plan first, then the code, then the verified output, then the things worth noticing.

Lecture Summary

Slate, once at the very end. A bulleted recap plus a one-line hook into the next class. A good place to start if you missed a session and need to catch up quickly.

4.Getting the code to run on your own machine

Every program on these pages compiles as it stands. You will need a C++ compiler; the notes use g++, and every output block came from a run of exactly this command:

g++ prog.cpp -o prog
./prog

If you leave out -o prog, the compiler names the executable a.out instead, and ./prog will tell you there is no such file. That is not a bug in your program.

One optional extra is worth knowing about. Adding -Wall turns on warnings, which catch real bugs that the language technically permits — an int silently swallowing a double, a variable used before it is set:

g++ -Wall prog.cpp -o prog

Warnings are not errors: the program still compiles and runs. But they are almost always right, and a few pages in these notes use them deliberately to show you a bug the compiler noticed. You do not need the flag to follow along.
