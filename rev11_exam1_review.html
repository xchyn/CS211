1.What Exam 1 actually looks like

Exam 1 is next class. It covers Classes 1 through 10 — the C++ refresher, references and parameter passing, the increment operators and loop control, file I/O, vectors, pointers, dynamic memory, and your first two classes on classes. Today is not new material. Today is the same material, re-sorted into the four shapes the paper uses, so that when you turn it over nothing on it is a surprise.

One thing worth knowing now rather than in November: every exam in this course is cumulative. Each one may draw on everything up to the day it is given. That matters most for pointers and dynamic memory — they are on this paper, and they are underneath almost everything on the next two. Material you learn properly this week you will not have to learn twice.

Start with the paper itself, because a lot of exam anxiety is really just not knowing what the questions look like. Here is the actual structure of this course's Exam 1.

Key Idea— the whole exam is code in, code out

There is no true/false on this paper. No multiple choice. No "define encapsulation in your own words." Every single question either asks you to write C++ or asks you to say exactly what C++ prints. Studying by re-reading definitions is therefore the least efficient thing you could do tonight. Studying by writing the four question types out by hand, on paper, without a compiler, is the most efficient.

How the marking actually works

The two halves of the paper are graded on opposite principles, and knowing which is which changes how you should spend your last ten minutes.

Warning— output prediction is all or nothing

On Question 3, each of the five lines is worth 2 points, with no partial credit. 3678 earns 2 points; 3679 earns zero. There is no credit for "the right method." Four digits, all four correct, or nothing.

The same rule holds for four of the five parts of Question 2. The rubric for the Fall 2023 paper allows one point of partial credit on parts (d) and (e) — the copy loop and the two delete statements — "for answers that are almost correct except for a tiny error," and nowhere else.

Practical consequence: on a trace question, re-derive, do not re-read. Skimming your own trace a second time will not catch the error, because you will make the same mistake the same way. Work the line again from the top on scratch paper and compare the two answers.

Key Idea— write-code questions pay for the signature alone

The rubrics for the write-code questions pay you before you have written any logic at all:

  • 1 to 2 points for the "standard beginning and standard ending" — the #include lines, using namespace std;, int main() {, and return 0; with the closing brace. That is up to 20 % of Question 1 for four lines you can write in fifteen seconds.
  • 2 points for the title line of any function you are asked to write — just the signature, spelled correctly, with the right return type and parameter list.
  • Then points per functional stage: reading the input, computing the thing, printing the thing. Each one is marked on its own.
  • And a standing instruction to the grader: "If a program follows a different (but reasonable) plan, try to award partial credit for meeting similar goals in the program."

So: never leave a write-code question blank. If you cannot finish it, write the includes, the main, the signature and the parts you are sure of. A half-written Question 1 is worth several points. A blank one is worth zero.

Procedure— how to spend the fifty minutes
  1. Two minutes. Read all four questions before writing anything. You are looking for which one you can do fastest, not for the answers.
  2. Do the cheap points first. On every write-code question, write the includes, main, return 0; and the function signatures immediately, for every question, before solving anything. That is 4–6 points banked in about a minute.
  3. Then Question 3, the trace, while you are fresh. It is short, it is worth 10 points, and it is the one that punishes a tired brain hardest.
  4. Then Questions 2 and 4, which are mostly recall.
  5. Question 1 last, because it is the one that rewards partial work — if the clock beats you, the fragments still score.
  6. Last five minutes. Re-derive line (a) of the trace from scratch. Check every new has a matching delete. Check every class body ends with };.

2.Passing data to a function

This is the topic that never gets its own question and shows up in every answer. Every function you write on this paper — the product function in Question 4, any helper you invent for Question 1 — forces the choice, and the signature is where the first points are.

Definition— the four parameter forms, compressed

All four of these come from Classes 1, 2 and 7. Restated in one place:

  • Call by value, void f(int n) — the parameter is a brand-new local variable holding a copy. The function cannot touch the caller's variable.
  • Call by reference, void f(int &n) — the parameter is another name for the caller's variable. One object, two names. Writes land on the original.
  • const reference, void f(const string &s) — no copy is made, and the function promises not to modify it. The right default for anything bigger than a number.
  • Pointer parameter, void f(int *n) — the function receives an address. It can change the caller's variable through *n, but the call site must write & and the pointer may be null.
Worked Example— three swaps, one of which does nothing

The oldest example in the course, and still the fastest way to check that the distinction is solid. Three functions that all look like they swap two integers. Work out all three lines of output before you open the answer.

swaps.cpp
// swaps.cpp -- the three swaps: broken, reference, pointer
#include <iostream>
using namespace std;

void swap1(int u, int v)   { int t = u;  u = v;   v = t;  }
void swap2(int &u, int &v) { int t = u;  u = v;   v = t;  }
void swap3(int *u, int *v) { int t = *u; *u = *v; *v = t; }

int main() {
    int a = 3, b = 4, c = 5, d = 6, e = 7, f = 8;

    swap1(a, b);
    swap2(c, d);
    swap3(&e, &f);

    cout << "swap1: " << a << " " << b << endl;
    cout << "swap2: " << c << " " << d << endl;
    cout << "swap3: " << e << " " << f << endl;
    return 0;
}
swap1: 3 4
swap2: 6 5
swap3: 8 7
FunctionWhat the parameter isEffect on main
swap1Two fresh local ints holding copies of 3 and 4.None. It swaps its own locals perfectly, then they are destroyed.
swap2Two other names for main's c and d.c and d really change.
swap3Two addresses. *u names main's e.e and f really change — but the call had to say swap3(&e, &f).

The thing to carry into the exam: the call site of swap1 and swap2 is spelled identically. swap1(a, b) and swap2(c, d) look the same. Whether the caller's variables change is decided entirely by two ampersands in the parameter list, which is why a trace question can hinge on a single character you have to go back up the page to find.

Worked Example— the same point without the swap

Three one-line functions that each try to set their argument to 99, and one that only reads. Predict all four lines.

params.cpp
// params.cpp -- the four ways to hand a variable to a function
#include <iostream>
#include <string>
using namespace std;

void byValue(int n)        { n = 99; }
void byReference(int &n)   { n = 99; }
void byPointer(int *n)     { *n = 99; }
int  lengthOf(const string &s) { return s.size(); }   // read-only, no copy

int main() {
    int a = 1, b = 1, c = 1;

    byValue(a);
    byReference(b);
    byPointer(&c);

    cout << "a = " << a << endl;
    cout << "b = " << b << endl;
    cout << "c = " << c << endl;

    string title = "Object-Oriented Programming";
    cout << "length = " << lengthOf(title) << endl;

    return 0;
}
a = 1
b = 99
c = 99
length = 27

a is untouched because byValue was handed a copy. b and c both change, by two different mechanisms that reach the same place. And lengthOf never copies the 27-character string at all — the const string & gives it read access to main's own object, with a compile-time guarantee that it will not scribble on it.

That last one is the form to reach for by reflex when a parameter is a string, a vector, or an object of a class you wrote. It is faster than a copy and safer than a plain reference.

Quick Check 11.2

For each function below, give the parameter list you would write on the exam, and one sentence of justification.

(a) A function that takes a vector of test scores and returns their average. It must not modify the vector.

double average(const vector<int> &scores)

Read-only, and a vector can be arbitrarily large, so a const reference: no copy, and the const documents and enforces the promise. Passing it by value, vector<int> scores, is not wrong — the professor's own model answers sometimes do exactly that — but it copies every element for no reason.

(b) A function that adds one more score to a vector the caller owns.

void addScore(vector<int> &scores, int s)

A plain reference, because the whole point is to modify the caller's vector. const here would be a compile error the moment you called push_back. The int goes by value: it is small and it is only read.

(c) A function that fills an array of n integers that the caller allocated with new[].

void fill(int *a, int n)

An array reaches a function as a pointer to its first element — you can write int a[] instead, which means exactly the same thing. Either way the array is not copied, so the function writes straight into the caller's storage. And the length has to come along as a separate parameter, because a pointer does not carry one.

(d) A function that returns the product of two Rational objects, where Rational has private data and public getters.

Rational product(Rational x, Rational y)

This is the signature from the Fall 2023 paper itself, and it takes both objects by value. const Rational &x would be better style, but it needs the getters to be const member functions — and on that exam they are not, so the const reference version would not compile. Match the stem you are given.

The wrap-up for all four parts: the parameter list is worth points on its own. Get the return type, the names and the & right, and you have banked the signature credit before writing a single statement of the body.

3.Vectors, and the write-a-program question

Definition— vector, compressed from Classes 5 and 6

A vector is a generalized array: it stores a sequence of same-typed elements, it knows its own length, and it can grow while the program runs. It needs #include <vector>, and the element type goes in angle brackets.

The only members this exam has ever used are push_back, pop_back, size(), back() and the subscript []. It has never asked for an iterator, insert, erase, at() or resize().

Worked Example— the four declaration forms, and the ends

Four ways to declare a vector, and what each one puts in the elements. Predict all four lines of output — the last one is printed with no separator, which is exactly how the exam does it.

vecrecall.cpp
// vecrecall.cpp -- everything about vector that Exam 1 can ask for
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> empty;              // size 0
    vector<int> sized(4);           // 4 elements, all 0
    vector<int> filled(3, 7);       // 3 elements, all 7
    vector<int> listed{1, 2, 4};    // exactly these three

    cout << empty.size()  << " " << sized.size()  << " "
         << filled.size() << " " << listed.size() << endl;
    cout << sized[0] << " " << filled[0] << " " << listed[2] << endl;

    empty.push_back(10);
    empty.push_back(20);
    empty.push_back(30);
    cout << empty.size() << " " << empty.front() << " " << empty.back() << endl;

    empty.pop_back();
    cout << empty.size() << empty.back() << endl;

    return 0;
}
0 4 3 3
0 7 4
3 10 30
220

Line by line:

  • Sizes 0, 4, 3, 3. Parentheses describe the vector; braces list its contents. vector<int> filled(3, 7) is three sevens; vector<int> listed{1, 2, 4} is those three numbers, and its size is 3, not 4.
  • sized[0] is 0 — the sized form value-initializes every element. filled[0] is the fill value 7. listed[2] is the third element, 4.
  • After three push_back calls the size is 3, the front is 10 and the back is 30.
  • The last line is the exam's favorite spelling: size() and back() printed with nothing between them. Size 2, back 20, so it reads 220. Not "two hundred and twenty" and not "2 20."
Common Mistake— assigning to an index that does not exist

v[i] = x; on an empty vector does not create an element. It writes into memory the vector does not own — undefined behavior, which on a good day crashes and on a bad day silently keeps going and corrupts something else. The only way to create elements is push_back, or a declaration that sizes the vector up front.

The anatomy of Question 1

Every "write a complete C++ program" question in this course is the same program with different nouns. Fall 2023 asked for the evens and odds of a list terminated by 0. Winter 2025 asked for the average and the values above it, terminated by 0. Summer 2025 asked for the maximum and the values below half of it, terminated by -1. One recipe covers all three.

Procedure— the write-a-complete-program pattern
  1. The standard beginning. #include <iostream>, #include <vector>, using namespace std;, int main() {. Write it before you think about anything else — it is worth a point or two on its own.
  2. Declare the input variable and the container: int x; and vector<int> v;. If the question asks you to "set up just enough space to store those inputs," a vector is the answer — or a dynamic array, if you would rather do the new[]/delete[] bookkeeping.
  3. Prompt, then read the first value, then loop: this is the sentinel pattern, and its shape matters. 
        cout << "Enter some integers until 0 to stop: ";
    cin >> x;
    while (x != 0) {
        v.push_back(x);
        cin >> x;
    }
    One cin >> x; before the loop, one at the bottom of the body. The sentinel is tested, never stored.
  4. Compute whatever the question wants — a running total, a running maximum — either inside the input loop or in a second pass over the vector.
  5. Print, walking the vector with an ordinary indexed for loop and an if for the filter.
  6. The standard ending. return 0; and the closing brace.

Things to notice.

  • Two passes over the same vector is the simplest correct plan and it is the one the rubric's first model answer uses. The rubric also shows a two-vector version that sorts the numbers as they arrive. Both get full marks; pick whichever you can write without hesitating.
  • v.size() returns an unsigned type, so comparing it to an int i makes -Wall complain. The cast (int)v.size() silences that. On paper nobody will mark you down for i < v.size() — the professor's own answers write it that way — but knowing why the warning appears is worth a moment.
  • Test x != 0 at the top, push_back inside. If you write the read at the top of the loop body instead, you will store the sentinel and print a stray 0.
  • % 2 != 0 rather than % 2 == 1: for a negative odd number, % in C++ yields -1, so the == 1 version silently drops negatives. The exam's sample data is all positive, but this is a free correctness point.
Quick Check 11.4

A student's program for the Winter 2025 version — print the average, then every input above it — declares int total = 0; and int average;, sums correctly into total, and then writes average = total / v.size();. For the sample input 3 1 4 1 5 9 2 6 the correct average is 3.875.

(a) What does the program print for the average, and why?

It prints 3. The sum is 31 and the size is 8, and both are integer types, so total / v.size() is integer division: 31 divided by 8 is 3, remainder discarded. Storing the result in an int would have thrown away the fraction even if the division had produced one.

(b) Fix it with the smallest possible change.

Declare the accumulator as a double:

    double total = 0;
    ...
    double average = total / v.size();

One operand is now floating point, so the division is floating point and 31.0 / 8 is 3.875. Casting at the point of division, (double)total / v.size(), works just as well.

Then a second trap follows immediately: the filter must compare with the double average, if (v[i] > average). Compare against an int copy of it and 4 would be excluded from a list that should contain it.

(c) The Summer 2025 version of this question asks for the inputs "less than half the maximum," and its sample run has a maximum of 12 with 6 among the inputs — and 6 is not printed. What does that tell you about the comparison the model answer uses, and how would you write it?

6 is exactly half of 12, and it is excluded, so the comparison is strictly less than, not <=. The model answer writes:

        if (v[i] < maximum / 2.0) cout << v[i] << " ";

Two things at once here. The 2.0 forces floating-point division, so an odd maximum like 13 gives a half of 6.5 rather than 6. And the < rather than <= is what the sample run tells you. Read the sample run: on this professor's papers it is the specification, and it settles boundary questions the prose leaves open.

Quick Check 11.5

The same loop discipline, one class earlier. No past Exam 1 paper has read from a file, but the reading loop is the input loop with the stream swapped, and it is on the syllabus — so it is worth ninety seconds tonight. A file scores.txt holds a name and a score per line.

(a) Write the loop that reads every record into two vectors, opening the file and checking the open succeeded.

readfile.cpp
// readfile.cpp -- the standard read loop
#include <iostream>
#include <fstream>
#include <string>
#include <vector>
using namespace std;

int main() {
    ifstream ifs("scores.txt");
    if (!ifs.is_open()) {
        cout << "could not open scores.txt" << endl;
        return 1;
    }

    vector<string> names;
    vector<int> scores;
    string name;
    int score;

    while (ifs >> name >> score) {      // the read is the loop condition
        names.push_back(name);
        scores.push_back(score);
    }
    ifs.close();

    cout << "records read: " << names.size() << endl;
    cout << "last record:  " << names.back() << " " << scores.back() << endl;
    return 0;
}
records read: 3
last record:  Cleo 91

#include <fstream> gives you ifstream. An input file that does not exist opens unsuccessfully — unlike an output file, which is created — so the is_open() check is not optional. And note how closely this mirrors the exam's input loop: the same push_back into the same kind of vector, with ifs in place of cin.

(b) A student writes while (!ifs.eof()) { ifs >> name >> score; ... } instead. On this three-record file, what goes wrong?

It processes the last record twice:

1: Ana 88
2: Ben 74
3: Cleo 91
4: Cleo 91

After reading Cleo 91 the file still has a newline left in it, so eof() is still false and the loop goes round again. The extraction on that pass fails, name and score keep their previous values, and the body prints them a second time.

eof() reports a read that has already failed; it never predicts the next one. That is why the read itself belongs in the condition: while (ifs >> name >> score) tests the result of the read that just happened.

The wrap-up: exactly the same reasoning applies to cin. Test the thing you just did, not the thing you are about to do.

4.Pointers and dynamic memory

This is the biggest topic on the paper and the one with its own dedicated question. Everything in Classes 7 and 8, compressed to what the exam asks for.

Definition— the vocabulary, compressed from Classes 7 and 8
  • A pointer is a variable that holds the address of another variable. int *p; declares one; the star attaches to the name, so int *p, q; gives one pointer and one plain int.
  • &x is address-of: it produces a pointer to x. *p is dereference: it names the variable p points at, and may sit on either side of an assignment.
  • Dynamic allocation is memory taken from the heap at run time by new, and it lives until you call delete. It has no name — the only way to reach it is through the pointer.
  • A memory leak is heap memory that no pointer can reach any more. A leaking program does not crash and does not warn.
  • A dangling pointer is a pointer to memory that has already been released. Dereferencing or re-deleting it is undefined behavior.
Worked Example— the five basic pointer operations

Quick Check 11.6

Given int a = 5, b = 9; int *p = &a, *q = &b;, say what each of these does and what a, b end up as. Treat each part as starting from the original state.

(a) p = q;

(b) *p = *q;

(c) *p = q;

error: invalid conversion from 'int*' to 'int' [-fpermissive]

This is a good error to have seen once. It means you put a star on exactly one side too few or too many.

(d) Why is p1 = p2; a disaster in a question like Fall 2023 Problem 2, even though it compiles?

Because both pointers now name the same block, and the block p1 used to own has become unreachable — a leak. Worse, the later delete p1; delete [] p2; now deletes the same memory twice, which is undefined behavior.

The wrap-up for all four parts: one star is the difference between moving an arrow and changing a value. Say the statement out loud in those words before you write it down — "copy the address" or "copy the value" — and this question stops being tricky.

5.Classes: private data and the way in

Definition— compressed from Classes 9 and 10
  • A class is a type you write yourself; an object is an instance of it. The declaration ends with a semicolon after the closing brace.
  • A variable declared inside the class is a data member; a function declared inside it is a method. The dot operator reaches both: r1.set(2, 3).
  • public members are reachable from anywhere; private members are reachable inside the class only. That one keyword is what makes encapsulation real.
  • An accessor ("get") returns a data member and should be const; a mutator ("set") changes one and cannot be.
  • With no constructor, a new object's members are indeterminate, not zero. Constructors arrive in Class 13 — after this exam.

Quick Check 11.8

Three short questions about the class you just wrote.

(a) add1 changes the numerator but not the denominator. Why is numerator += denominator; correct, and what would numerator + denominator; on its own do?

Adding 1 to p/q means adding q/q, which gives (p+q)/q — a new numerator over the same denominator. So numerator = numerator + denominator;, or the shorter numerator += denominator;.

numerator + denominator; on its own computes the sum and throws it away. It compiles, it does nothing, and -Wall warns about a statement with no effect. This is a real exam answer that students write under time pressure.

(b) Could product have been written as a member function instead, Rational Rational::product(Rational y)? What would change at the call site?

Yes, and as a member it would be allowed to read numerator and denominator directly on both objects — access control is per class, not per object. The call site would change from product(r1, r2) to r1.product(r2).

But the exam's main is printed for you and it calls product(r1, r2). Match the call you are given. Changing the design to one that does not compile against the supplied main is the expensive way to be clever.

(c) The main says Rational p = product(r1, r2);. Nothing here has a constructor. Why does that line work anyway, and what would break if product returned before calling set on answer?

It works because the compiler writes the four basic operations for you — create, copy, assign, destroy — and the copy it generates copies the object member by member. Rational p = product(...) copy-initializes p from the returned object, member by member, and for two plain ints that is exactly right.

If product returned answer without ever calling set, answer's members would be indeterminate, not zero. The copy would faithfully copy the garbage, and p.print() would print two arbitrary numbers — different ones on different runs, with no crash and no warning. Every object in this course is born with garbage until Class 13 gives us constructors.

The wrap-up: a class body ends with };. Every year the rubric hands out points for that semicolon, and every year people lose them.

6.The output-prediction traps

Question 3 is ten points in about five minutes of writing, and it is the question that decides grades. There are four traps in it and they are the same four traps every term.

Key Idea— two questions per operator

For each of ++x, x++, --x, x--, ask two separate questions:

  1. What does the variable become? Always the same answer: up or down by one.
  2. What does the expression hand to cout? The prefix forms hand over the new value; the postfix forms hand over the old one.

Write the variable's running value in the margin as you go. The exam's second line always depends on what the first line left behind.

Problem 1 — Write a complete C++ program (from the Fall 2023 Exam 1)

[10 points] · about 12 minutes

Write a complete C++ program that does the following. (Programs that correctly carry out some of the tasks will receive partial credit.)

  1. The program asks the user to enter some integers until 0 to stop.
  2. Stores those numbers into a vector or vectors.
  3. Then prints the even and odd numbers separately.

An example run of the program follows.

Enter some integers until 0 to stop: 2 4 3 1 5 8 9 6 7 0
Evens: 2 4 8 6
Odds: 3 1 5 9 7

Plan. Three stages, and the point split follows them exactly: 1 point for the standard beginning and ending, 5 points for declaring the vector, prompting and reading the inputs into it, then 2 + 2 for the two printing loops. Read one value before the loop and one at the bottom of the body, so the sentinel is tested but never stored. Then walk the vector twice, once with % 2 == 0 and once with % 2 != 0. Two passes is simpler to get right under time pressure than one pass with two vectors, and the rubric accepts either.

evenodd.cpp
// evenodd.cpp -- Fall 2023 Exam 1 Problem 1
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int x;
    vector<int> v;
    cout << "Enter some integers until 0 to stop: ";
    cin >> x;
    while (x != 0) {
        v.push_back(x);
        cin >> x;
    }

    cout << "Evens: ";
    for (int i = 0; i < (int)v.size(); i++) {
        if (v[i] % 2 == 0) cout << v[i] << " ";
    }
    cout << endl;

    cout << "Odds: ";
    for (int i = 0; i < (int)v.size(); i++) {
        if (v[i] % 2 != 0) cout << v[i] << " ";
    }
    cout << endl;

    return 0;
}

  • The published rubric offers two model answers: this one, and a version with vector<int> evens, odds; that sorts each value as it arrives. The second needs only one pass but two containers. Both are full marks.

Problem 2 — Write C++ statements (from the Fall 2023 Exam 1)

[10 points, 2 per part] · about 8 minutes

Write C++ statements to carry out the following tasks. Do not write complete programs, just give a single line, or a few lines of C++ instructions. Assume that the following declarations have been made and the declared variables have been set to have legal values.

    int x = 7, y[3] = {3, 1, 4};
    int *p1 = new int, *p2 = new int[3];

(a) Declare a pointer px that points to the variable x.

    int *px = &x;

& is the address-of operator, and x is a scalar, so this is the straightforward case. The declaration and the initialization are one statement; int *px; px = &x; is equally correct.

(b) Declare a pointer py that points to the array y.

    int *py = y;

No & here. An array name already is a pointer to its first element, so y is exactly the int * you need. Writing int *py = &y; is a type error: &y is a pointer to an array of three ints, a different type, and g++ rejects it. This distinction — &x for a scalar, plain y for an array — is the whole reason parts (a) and (b) are two separate questions.

(c) Copy the data in x into the dynamic variable p1 points to.

    *p1 = x;

"Copy the data into the thing p1 points to" means dereference p1 and assign. p1 = &x; would be the wrong answer twice over: it copies an address rather than a value, and it abandons the block new int handed you, which then leaks and cannot be deleted.

Warning— the published key is wrong here

Both the distributed rubric and the distributed solution give this part as *py = x;. That writes 7 into y[0], using the pointer from part (b), and never touches p1 at all. Compiled and run, the key's version leaves the array as 714 and part (d) then copies the damage into p2. The correct answer is *p1 = x;. If you wrote that, you were right.

(d) Copy the data in the array y into the array the dynamic pointer p2 points to.

    for (int i = 0; i < 3; i++) p2[i] = y[i];

Arrays are copied element by element. p2 = y; compiles and does something entirely different: it repoints p2 at y, leaks the three-int block, and makes the later delete [] p2; undefined behavior. This part and part (e) are the only two on this question that the rubric allows a point of partial credit on, "for answers that are almost correct except for a tiny error" — an off-by-one in the loop bound, for instance.

(e) Release the memory for p1 and p2.

    delete p1;
    delete [] p2;

One new, one plain delete. One new[], one delete [] — with empty brackets. delete [3] p2; does not compile, and delete p2; for an array is undefined behavior.

Things to notice, across all five parts.

  • Assembled into a driver and run, the five answers leave *px as 7, *p1 as 7, and both y and p2 as 314. Under valgrind: 4 allocations, 4 frees, no leaks.
  • Say each task out loud as "copy the address" or "copy the value" before writing it. Every wrong answer on this question is the other one of those two.
  • Adding p1 = nullptr; p2 = nullptr; after the deletes is good practice and costs nothing, though the rubric does not require it.

  • The paper. Four questions, 40 points, 50 minutes: write a complete program, write five pointer statements, predict the output of five lines, implement three class members. Every question is code in or code out. Nothing on it is prose.
  • The marking. Output prediction is 2 points per line with no partial credit. Write-code questions pay 1–2 points for the standard beginning and ending and 2 points for a correct signature, before any logic. Never leave one blank.
  • Parameters. int n copies; int &n is another name for the caller's variable; const string &s is read-only access with no copy; int *n is an address and needs & at the call site. The call sites of the first two look identical — read the declaration.
  • Vectors. v; is empty, v(n); is n zeros, v(n, 7); is n sevens, v{1,2,4}; is those three. Parentheses describe, braces list. push_back is the only way to create elements. size() and back() printed adjacently give 14 for "size 1, back 4."
  • The program question is always the same recipe: standard beginning, declare, prompt, read one value, while (x != sentinel) with the next read at the bottom, compute, print with a filtered loop, return 0;.
  • Pointers. &x for a scalar, plain y for an array. p = q; moves an arrow; *p = *q; changes a value. Arrays are copied element by element, never by assignment. One new per delete, one new[] per delete [], brackets empty.
  • Classes. private data, public methods, }; at the end. Accessors are const, mutators are not. . for an object, -> for a pointer, and a free function must go through the getters — which is worth two of the six points on that question.
  • The traps. Prefix hands back the new value, postfix the old. Line (b) prints what line (a) left behind. break abandons the loop; continue runs the update and the test. And with no formatting instructions, cout prints a double to six significant digits and drops trailing zeros, so 4.0 appears as 4.
