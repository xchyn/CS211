1.Two out of three is not enough

Class 14 left you with a class that looked finished. PStringsDC owns a new'd array of strings; it has a constructor that allocates, a destructor that releases, and a copy constructor that performs a deep copy. Pass one to a function by value and nothing breaks any more. Build a second object from a first with PStringsDC b(a); and the two objects have separate arrays.

Now write one more line and watch it fall over.

Worked Example— a class with a destructor and a copy constructor, crashing anyway

This is the professor's Lecture 13 opening program. The class is exactly the one from Class 14 — construct, destroy, copy — with no assignment operator written. The only new line in main is ps1 = ps2;. Two objects, two different lengths, two separate arrays. Predict what the program prints, and predict whether it exits normally.

Both objects print the same thing, which is what you asked for. And then the shell reports:

The four printed lines are correct and the program still dies. The crash happens after the last statement of main, when ps2 and ps1 go out of scope and their destructors run.

Here is why. You never wrote an assignment operator, so the compiler generated one, and the generated one does exactly what the generated copy constructor did before you replaced it — it copies each data member across, one at a time:

That second line is the whole disaster. It does not copy the array; it copies the address of the array. After it runs, ps1.pstr and ps2.pstr hold the same address. Two objects, one array.

Definition— the Big Three

The Big Three are the three member functions that a class owning a resource — heap memory, a file handle, a network connection — must write for itself:

  1. the destructor — releases the resource (Class 14);
  2. the copy constructor — gives a brand-new object its own copy of the resource (Class 14);
  3. the assignment operator — replaces an existing object's resource with its own copy of another's (today).

The rule of thumb, and it is worth memorizing: if you need one of the three, you need all three. Each of them exists for the same reason — the compiler-generated version copies pointers rather than what the pointers point at — so writing one and not the others just moves the crash to a different line.

Quick Check 15.1

The program above has a working deep-copy constructor. Answer each part about why it does not save us here.

(a) Why does the copy constructor not run on the line ps1 = ps2;?

Because ps1 already exists. A constructor — any constructor, copy included — runs exactly once per object, when the object is being brought into being. By the time control reaches ps1 = ps2;, ps1 was constructed three lines earlier and has been sitting there holding its own array. There is no new object to construct, so no constructor is called. What C++ calls for on this line is an assignment, and assignment is a different function.

(b) The compiler generated an assignment operator for us. Why is the one it generated wrong?

Because it does the only thing it can do without understanding your class: it copies each data member. Copying length is fine. Copying pstr copies an address, which is a shallow copy, and now two objects believe they own the same array.

The compiler is not being lazy. It has no way to know that pstr points at memory the object owns rather than at memory somebody else owns. In the professor's phrasing from the destructor slide: "How could it know to do such a thing?"

(c) The crash happened at the closing brace of main, not on the assignment line. Why is that especially dangerous?

Because the symptom is nowhere near the cause. The four lines of output were all correct; the program did everything you asked and then died on the way out. A student debugging this will stare at print, which is innocent.

Worse, this class of bug is not reliably fatal. Whether a double free crashes depends on the allocator, the sizes involved, and what else the program has done. The same source can run perfectly on your laptop and segfault on the grader's machine. That is precisely why we run these programs under valgrind: it reports the error at the moment it happens, whether or not the program crashes.

2.The this pointer

Before we can write the assignment operator we need one piece of machinery, and it is a piece that has been quietly promised since Class 1. Back then we asked how a single shared copy of a method knows which object it is working on. Here is the answer.

Definition— the this pointer

C++ automatically generates, for every object, a pointer named this.

  1. this points to the object itself — the one the member function was called on.
  2. It is accessible only inside the class's own methods. An outside application cannot write obj.this; there is no such thing.
  3. It is available in both public and private methods, and in constructors and the destructor.
  4. Since this is a pointer to the object, *this is the object, and this->member is that object's member.

Every non-static member function has one. (The exception, static member functions, is Class 16's material — a static function is not called on any particular object, so there is nothing for this to point at.)

You have been using this all semester without typing it. When you write a method like

    void print() const {
        cout << "length = " << length << endl;
    }

the bare name length is not a global and it is not a local. The compiler reads it as this->length — the length of whatever object we were called on. That substitution is the entire mechanism by which one compiled copy of print serves a thousand different objects.

Worked Example— looking at this directly

Two Counter objects, built with the same starting value. One of them is bumped. report prints the value of this, and sameObjectAs compares this with the address of another object. Before you open the answer, decide what the last two lines print — the interesting question is whether a.sameObjectAs(b) is true, given that a and b started out holding identical data.

this_demo.cpp
// this_demo.cpp -- what "this" is, and what it is for
#include <iostream>
using namespace std;

class Counter {
public:
    Counter(int start) {
        count = start;
    }
    void bump() {
        count = count + 1;          // the compiler reads this as this->count
    }
    void report() const {
        cout << "the object at " << this << " holds count = " << count << endl;
    }
    bool sameObjectAs(const Counter &other) const {
        return this == &other;      // compare addresses, not contents
    }
private:
    int count;
};

int main() {
    Counter a(10);
    Counter b(10);

    a.bump();
    a.report();
    b.report();

    cout << "&a inside main is " << &a << endl;
    cout << "a.sameObjectAs(a) = " << a.sameObjectAs(a) << endl;
    cout << "a.sameObjectAs(b) = " << a.sameObjectAs(b) << endl;
    return 0;
}

the object at 0x7ffce379e2b4 holds count = 10
&a inside main is 0x7ffce379e2b0
a.sameObjectAs(a) = 1
a.sameObjectAs(b) = 0

The four addresses are of course different on every machine and on every run — the values printed here are representative, not something to memorize. What matters is the pattern between them:

  • The address this holds inside a.report() is exactly the address &a printed from main. this is not a copy of the object and not a handle to it; it is its address, the same address the outside world sees.
  • a and b print different addresses. Every object has its own this, and that is the whole point — a.bump() incremented a's count because this pointed at a.
  • sameObjectAs answers 1 (true) for a against itself and 0 (false) for a against b, even though the two objects held equal values when they were built. Comparing this == &other asks "are these the same object?", not "do these hold the same data?". Hold on to that distinction — the self-assignment test in §4 is exactly this comparison.
Key Idea

this cannot be reassigned. Inside a member function of class C, the type of this is C* const — a constant pointer. You may read it, dereference it, compare it and return it. You may not point it somewhere else. An object cannot decide to become a different object.

Quick Check 15.2

Inside a member function of a class called Widget:

(a) What is the type of this, and what is the type of *this?

In a non-const member function, this has type Widget* const — a constant pointer to a Widget. Dereferencing it, *this has type Widget& — it is the object, so you can pass it, return it, or call methods on it.

In a const member function — one written void print() const — the type is const Widget* const and *this is a const Widget&. That is the machinery behind the error message you met in Class 10: a const method has a pointer to a const object, so it cannot change anything through it.

(b) Are x, this->x and (*this).x three different things?

No — all three name the same data member of the same object, and all three compile to identical machine code. this->x and (*this).x are two spellings of the same dereference-then-select, exactly as they are for any other pointer (Class 7). The bare x is what the compiler expands to this->x when nothing else named x is in scope.

So writing this-> everywhere is legal but noisy. Write it when you need it — which is the subject of the next part — and leave it off otherwise.

(c) Why is this = &other; never legal?

Because this is not a variable you own. It is fixed at the moment the method is called, to the address of the object it was called on, and its type carries a const that says so. Reassigning it would mean "from here on, treat this call as if it had been made on a different object," which is meaningless.

The compiler's phrasing is blunt. This is the real g++ 13.3 message for that line:

error: lvalue required as left operand of assignment
   38 |     if (this = &rhs) return *this;
      |         ^~~~

Remember that message. It is going to come back in §4, when a single missing = turns the self-assignment test into an attempted assignment.

The classic use: a parameter with the member's name

Class 1 warned you about this and told you the fix was coming in Class 15. Class 10 said the same thing. Here it is.

When you write a setter, the natural name for the parameter is the name of the thing it sets. But inside the function body, a parameter hides a data member of the same name — the local name wins. So the honest-looking line width = width; assigns the parameter to itself and never touches the object at all.

Worked Example— the setter that does nothing

setBroken and setWorking have identical parameter lists and are called with identical arguments. The only difference is four characters. Predict both printed lines.

this_shadow.cpp
// this_shadow.cpp -- a parameter with the same name as a data member
#include <iostream>
using namespace std;

class Rectangle {
public:
    Rectangle() {
        width = 0.0;
        height = 0.0;
    }
    // The parameter names hide the data members.  width = width; assigns the
    // parameter to itself and never touches the object.
    void setBroken(double width, double height) {
        width = width;
        height = height;
    }
    // this->width is unambiguous: it is the member of the object we were
    // called on.  The bare width is the parameter.
    void setWorking(double width, double height) {
        this->width = width;
        this->height = height;
    }
    void print() const {
        cout << "Rectangle " << width << " x " << height << endl;
    }
private:
    double width, height;
};

int main() {
    Rectangle r;
    r.setBroken(3.0, 4.0);
    cout << "after setBroken:  ";
    r.print();

    r.setWorking(3.0, 4.0);
    cout << "after setWorking: ";
    r.print();
    return 0;
}

3.Overloading operator=

Now we can write the missing function. In C++ an operator is a function with an odd name: the keyword operator followed by the operator symbol. When the compiler sees ps1 = ps2; and ps1 is a class object, it looks for a member function called operator= and calls it, with ps1 as the object and ps2 as the argument. Class 17 does operator overloading properly; today we need exactly one of them.

Definition— the assignment operator

The assignment operator of a class C is a member function declared like this:

    C& operator= (const C &rhs);

Read the three parts:

  • C& — the return type: a reference to an object of the same class. §5 explains why.
  • operator= — the name.
  • const C &rhs — one parameter: a const reference to an object of the same class. It is conventionally named rhs because the source of an assignment sits on the right-hand side.

Defined outside the class, the same function is written with the scope resolution operator:

    C& C::operator= (const C &rhs) { ... }

The professor lays the assignment operator side by side with the copy constructor, because they do a similar job and students mix them up constantly. Here is the comparison, and it is worth reading slowly — every difference in the right-hand column has a consequence.

Why operator= cannot be a free function

Almost every operator in C++ can be overloaded either as a member function or as an ordinary free function outside the class — you will use both forms in Classes 17 and 18. Assignment is one of a short list of exceptions. Try it and the compiler stops you flat.

#include <iostream>

class Simple {

    int get() const { return value; }
    void put(int v) { value = v; }

    int value;
};

    lhs.put(rhs.get());
    return lhs;
}

    Simple a(1), b(2);
    a = b;
    cout << a.get() << endl;
    return 0;
}

   15 | Simple& operator= (Simple &lhs, const Simple &rhs) {
      |         ^~~~~~~~

Four operators are required by the language to be non-static member functions: operator=, operator[], operator() and operator->. There is a reason behind the rule and it is worth understanding rather than memorizing.

Every class already has an assignment operator — if you do not write one, the compiler generates one, and it is a member. A free operator= could never replace it; it would merely sit alongside it, and every a = b; would then be ambiguous or would silently pick the member and ignore yours. Requiring the member form guarantees that a class has exactly one assignment operator and that writing yours replaces the generated one.

The practical consequence for exams: in the signature line, the class name appears once as the return type and once after const in the parameter, and nowhere as a first parameter. Box& operator=(const Box &rhs) — two mentions, not three.

4.The self-assignment test

Here is the body of the function, and here is the step you will forget.

Procedure— writing operator= for a class that owns memory
  1. Test for self-assignment: if (this == &rhs).
  2. If it is true, return *this; and exit — there is nothing to do.
  3. Otherwise, deallocate the memory the destination object is currently holding.
  4. Allocate fresh memory, sized to match the source object.
  5. Perform the deep copy, element by element.
  6. return *this; and exit.

Steps 3 and 4 are what makes this function different from the copy constructor. A brand-new object has nothing to release; an existing one does.

Definition— self-assignment

Self-assignment is an assignment whose source and destination are the same object. The obvious spelling is ps1 = ps1;, which looks pointless and which nobody writes on purpose. The dangerous spellings are the ones you cannot see:

    a = b;                  // and somewhere earlier, b is a reference bound to a
    list[i] = list[j];      // when i happens to equal j
    *p = *q;                // when p and q hold the same address

The test if (this == &rhs) compares the address of the destination with the address of the source. It answers "are these the same object?" — not "do these hold equal data?", which is a completely different and much more expensive question.

Why does it matter so much? Because step 3 — deallocating the destination's memory — also deallocates the source's memory when they are the same object. You then allocate a new empty array and copy the source into it, except the source is gone.

Quick Check 15.5

A student argues: "Self-assignment is silly. Nobody writes a = a;, so the guard is a waste of a line."

(a) Give a realistic three-line program in which self-assignment happens without anyone writing the same name twice.

Any situation where two names reach the same object. A reference parameter is the commonest:

...

An array or vector of objects does it too:

        list[i] = list[pick[i]];    // self-assignment whenever pick[i] == i

In neither case can the author of operator= see the call site. The function has to defend itself, because it is the only place that knows how.

(b) Does a class whose members are all ints and doubles need the guard?

Strictly, no. Assigning length = rhs.length; when rhs is the same object just copies a value onto itself — harmless. The guard only becomes necessary when the operator deallocates something before copying.

Write it anyway, for two reasons. First, the exam rubrics award a point for if(this == &rhs) return *this; on every assignment-operator question, including the ones on plain-value classes such as Box. Second, classes grow: the day somebody adds a string* member, the guard you wrote a year ago is the reason the program does not quietly lose data.

(c) What does if (this == &rhs) compare, exactly? Would if (*this == rhs) do the same job?

this == &rhs compares two addresses. It is true only when the destination and the source are one and the same object in memory.

*this == rhs would compare two objects, which is a different question entirely — and for our class it does not even compile, because nobody has written an operator== for PStringsDC. Even if you wrote one, using it here would be wrong: two distinct objects holding equal data would compare equal, the operator would skip the copy, and the assignment would appear to work while leaving the destination pointing at its own old array. It would also be far slower — comparing contents means walking the whole array, while comparing addresses is one instruction.

5.Returning *this, and chained assignment

Why does the assignment operator have a return type at all? Nothing in main uses the result of ps1 = ps2;. The answer is a habit you have had since your first week of C++.

    i = j = k;          // legal for int
    x = y = z;          // legal for double

Assignment in C++ is not a statement; it is an expression, and an expression has a value. If a user-defined class is going to behave like a built-in type — and that is the whole ambition of operator overloading — then ps1 = ps2 = ps3 = ps4; has to work too.

Key Idea

Assignment groups right to left, unlike most operators. a = b = c; means a = (b = c);. So the value of an assignment must be something you can assign from — and the natural choice is the object that was just assigned to, which inside the function is *this.

Quick Check 15.6

Suppose the assignment operator were declared to return the class by value instead of by reference: PStringsDC operator= (const PStringsDC &rhs); with the body unchanged, still ending in return *this;.

(a) Does ps1 = ps2 = ps3; still compile and produce the right values?

Yes. return *this; with a by-value return type copy-constructs a temporary PStringsDC from the object, and that temporary is a perfectly acceptable source for the next assignment. The three objects end up holding the right data.

Which is exactly why this bug survives testing.

(b) What does it cost?

A whole extra object per assignment. Every a = b; now runs the deep-copy constructor to build the temporary (one new plus a copy loop) and then the destructor to destroy it (one delete []). For a class holding a large array that can easily double the cost of an assignment, and it happens on every assignment, not only on chained ones.

(c) Find a line whose meaning actually changes.

Anything that uses the result of the assignment as an object rather than as a value:

    (ps1 = ps2).set(0, "changed");

With the correct PStringsDC& return type, this assigns to ps1 and then calls set on ps1 — the object is modified.

With the by-value return type, the assignment produces a temporary copy, set modifies the temporary, and the temporary is destroyed at the semicolon. ps1 is untouched by the set. Same source text, silently different behavior.

Things to notice. This is the general argument for returning a reference from an operator that modifies its object: the caller should get back the object, not a picture of it. Built-in types behave that way — (i = j) = 5; is legal for ints and leaves i equal to 5 — and matching the built-in behavior is the point.

6.Syntactic sugar: copy or assign?

Now the trap. Look at these three lines and decide, for each, which function runs.

    PStringsDC ps1(n, s);       // 1
    PStringsDC ps2(ps1);        // 2
    PStringsDC ps3 = ps1;       // 3

Line 1 is a non-default constructor; that is settled. Line 2 is the copy constructor; you met it in Class 14. Line 3 has an equals sign in it, so it must be the assignment operator.

It is not. Line 3 calls the copy constructor.

Definition— syntactic sugar

Syntactic sugar is a convenience: an alternative spelling the language provides for something you could already write, which means exactly the same thing.

PStringsDC ps3 = ps1; is syntactic sugar for PStringsDC ps3(ps1);. The two are equivalent. Despite appearances, the first is not an assignment at all: ps3 is a brand-new object being brought into existence on that very line, and bringing an object into existence is a constructor's job. The = here is part of a declaration, not an assignment expression.

Key Idea

Ask one question, and only this question: is the object on the left being created on this line?

  • Yes — a type name appears — then it is a constructor. If the initializer is another object of the same class, it is the copy constructor.
  • No — the object already existed — then it is operator=.

  • Trace d; d = a; — two lines, "default constructor" then "assignment operation".

On an output-prediction question that difference is worth two points and there is no partial credit. It is the single most common way to lose them.

Quick Check 15.8

Using the Trace class above, say which special member (if any) runs for each line, and how many lines of output it produces.

(b) A function void show(Trace t) { } is called as show(a);

Two lines: Trace: copy constructor when the parameter t is initialized from a, and Trace: destructor when t dies at the closing brace of show.

A by-value parameter is a brand-new object initialized from another object of the same class — which is the definition of a copy-constructor call. This is exactly the situation that crashed the class in Class 14 before the copy constructor existed.

(c) Trace f; f = f;

Two lines: Trace: default constructor, then Trace: assignment operation.

The self-assignment guard does not suppress the message, because in this class the cout is the first statement of operator= and the guard is the second. Move the guard above the print — as several of the professor's own rubrics do — and f = f; prints nothing at all.

So on a trace question, read the stem's wording carefully: "prints ... as its first instruction" and "as its last instruction" produce different answers for a self-assignment, and the professor's exams use both wordings in different terms.

(d) Trace *p = new Trace(3); delete p;

Two lines: Trace: non-default constructor from the new, and Trace: destructor from the delete.

As Class 14 put it: new invokes a suitable constructor, and delete invokes the destructor. The pointer p itself is not an object of the class and prints nothing.

Things to notice. Across all four parts, the reliable method is to ask, for every line, how many objects of this class come into existence, and how many go out? Every birth prints a constructor line and every death prints a destructor line. Only lines where nothing is born and nothing dies can be assignments.

7.Forbidding copies

Everything so far has been about making copying work. Sometimes the right answer is to make it impossible.

Think about what an object might represent: a connection to a hardware device, a lock held on a file, a payroll record whose confidentiality is somebody's legal problem. For any of those, a program that quietly makes a second copy is not a convenience, it is a defect. And in C++ copies are made silently — pass an object to a function by value and you have made one without typing anything that looks like a copy.

Class 13 showed you how to control who may create an object: make the constructor private. The same move controls who may copy one.

Procedure— make a class non-copyable
  1. Declare the copy constructor and the assignment operator in the private section of the class.
  2. Do not define them. There is no body to write; nobody is allowed to call them.
  3. That is all. They always go together — forbidding one and allowing the other leaves a door open.

8.The six implicitly generated functions

We have now met, one at a time, every function the compiler will write for you if you do not. Here is the complete list.

Definition— implicitly generated member functions

If you do not declare them yourself, the compiler implicitly generates these six member functions for a class:

  1. the default constructor — Class 13;
  2. the destructor — Class 14;
  3. the copy constructor — Class 14;
  4. the assignment operator — today;
  5. the address-of operator, operator&;
  6. the address-of-const operator, operator& on a const object.

The first four are the ones programmers frequently write for themselves. The last two are almost never overloaded — they exist so that &obj yields a pointer to the object, and the versions the compiler provides simply return this.

Notice what is not on the list: sizeof. That is built into the language, which already knows how much memory any class needs, and it cannot be overloaded.

Worked Example— the professor's CDCEAC class

CDCEAC stands for create, destroy, copy, eq (assign), address, address const. It writes all six functions by hand, and each one does nothing but print its name, so the program is a live readout of which function fires for which statement. The class has no data members at all.

  • Its copy constructor and its operator= copy nothing. That is correct only because CDCEAC has no data members. Quick Check 15.10

You write a class Buffer that allocates an array with new in its constructor. You write only the constructor and a destructor that calls delete []. You write nothing else.

(a) Which of the six functions does the compiler still generate for Buffer?

Four of them: the copy constructor, the assignment operator, and the two address-of operators.

(b) Two of those four are time bombs. Which, and why?

The generated copy constructor and the generated assignment operator. Both do a member-by-member copy, which for a Buffer means copying the pointer. You then have two objects believing they own one array, and your correct destructor — the one you were careful to write — releases it twice.

This is the Big Three rule stated backwards, and it is worth holding on to in exactly this form: the moment you find yourself writing a destructor that frees something, you have just committed to writing the other two as well.

(c) Give two different one-word answers to "what should Buffer do about copying?", and say when each is right.

Implement — write a deep-copy copy constructor and a proper operator=. Right when copying a Buffer is a meaningful thing for a user of the class to want.

Forbid — declare both private (or = delete them). Right when a Buffer stands for something that should not be duplicated: a device, a lock, a unique record. Forbidding is a perfectly respectable design decision, not an admission of laziness — and it is far better than leaving the generated versions in place.

What is never right is the third option: leaving them generated and hoping nobody copies the object.

Problem 4 — The assignment operator for PStringsDC (from the course notes)

The course notes develop a class PStringsDC that stores length and a new'd array string *pstr, and give it a constructor, a destructor and a copy constructor. Write its assignment operator, in non-inline form, and then answer: what is the meaning of the test in the first line of the body, and why is such a statement required?

Plan. The class was introduced with its function bodies outside the class, so the definition needs the PStringsDC:: qualifier and the class body needs a matching declaration. Then follow the six steps.

// inside the class body:
    PStringsDC& operator= (const PStringsDC &rhs);
// outside the class body:
PStringsDC& PStringsDC::operator= (const PStringsDC &rhs) {
    if (this == &rhs) return *this;     // test for self-assignment
    delete [] pstr;                     // release the existing memory
    length = rhs.length;
    pstr = new string[length];          // allocate fresh memory
    for (int i = 0; i < length; ++i) {
        pstr[i] = rhs.pstr[i];          // deep copy
    }
    return *this;           // return a reference to the destination object
}

What the test means. this is the address of the object being assigned to; &rhs is the address of the object being assigned from. Comparing them asks whether the two are the same object. If they are, there is nothing to do, so the function returns immediately.

Why it is required. Because the very next statement deallocates the destination's memory. When the destination and the source are the same object, that statement has just destroyed the data the function is about to copy. The object ends up holding an array of empty strings — silently, with no crash and no warning.

Things to notice.

  • The declaration inside the class and the definition outside it must match exactly, including the const and the &. A mismatch produces "no declaration matches", which is a confusing message until you know to compare the two lines character by character.
  • The professor's slide writes length = rhs.length; before the delete []. It works, because delete [] does not need the length, but the order used above — release, then resize, then allocate — is the one that keeps working when the class changes.
  • return *this; appears twice: once in the guard and once at the end. Both are needed; a function with a return type must return on every path.

Summarize the class in one page. For a class C that owns a new'd array:

The copy constructor: class name, no return type, exactly one parameter which is a const reference to the same class. The assignment operator: named operator=, returns a reference to the class, one const reference parameter.

(b) Write the body of operator= from memory, in six lines, with no class-specific detail beyond delete [] and a copy loop.

C& C::operator= (const C &rhs) {
    if (this == &rhs) return *this;         // 1. guard
    delete [] data;                         // 2. release
    n = rhs.n;                              // 3. resize
    data = new T[n];                        // 4. allocate
    for (int i = 0; i < n; ++i)             // 5. deep copy
        data[i] = rhs.data[i];
    return *this;                           // 6. return the destination
}

If you can reproduce that shape under exam conditions you have most of the marks on the professor's signature question, whatever the class is called.

(c) In one sentence each: why the guard, why the delete [], and why return *this?

  • The guard — because when the source and the destination are the same object, releasing the destination's memory destroys the source's data before it can be copied.
  • The delete [] — because the destination already exists and already owns an array; overwriting the pointer without releasing it leaks that array.
  • The return *this — because assignment is an expression with a value, and returning a reference to the destination is what makes a = b = c; work and makes the class behave like a built-in type.

Things to notice. Those three sentences are the whole of today's class. Every program on this page is one of them going wrong.

Lecture Summary
  • A destructor and a copy constructor are not enough. Without an assignment operator, the compiler generates one that copies the pointer, so two objects own one array and both destructors free it — a double free, plus a leak of the array that was overwritten.
  • The Big Three are the destructor, the copy constructor and the assignment operator. If you need one, you need all three.
  • this is a pointer, generated automatically for every object, that points at the object a member function was called on. It is available only inside the class's own methods, in public and private ones alike, and it cannot be reassigned. *this is the object itself.
  • When a parameter has the same name as a data member, the parameter hides the member, and width = width; silently does nothing. Write this->width = width;.
  • The assignment operator is declared C& operator= (const C &rhs); and must be a member function — a free version does not compile.
  • The six steps: guard, release, resize, allocate, deep copy, return *this. Steps 1 and 2 are what distinguish it from the copy constructor.
  • Without if (this == &rhs) return *this;, a = a; frees the object's own data and then copies the wreckage back over itself — silently, with no crash.
  • The return type exists so that a = b = c; works. Assignment groups right to left, and every step hands back a reference to the object it just wrote into.
  • X a = b; calls the copy constructor, not operator=. The object on the left is being created, so it is a constructor; the = is syntactic sugar for X a(b);. Only an assignment to an object that already exists calls operator=.
  • Declaring the copy constructor and operator= private (and not defining them) forbids copying entirely — useful whenever duplicating an object would be a bug. The two always go together.
  • The compiler implicitly generates six member functions: default constructor, destructor, copy constructor, assignment operator, and the two address-of operators. The first four are the ones you write yourself. sizeof is built into the language, and an empty class has size 1.
