1.The payoff for class templates

In Class 26 you wrote a class template. You took a class that worked for one type, put template <typename T> in front of it, replaced the concrete type with T, and got a class that works for every type at once. That was a lot of machinery for one small container, and the honest question at the end of that class was: was it worth it?

Today is the answer. The C++ standard library ships with a whole collection of class templates that other people have already written, debugged and optimized for you. It is called the Standard Template Library, and you have been using it since Class 5 without being told its name.

Definition— the Standard Template Library

The Standard Template Library (STL) is a library that comes with every C++ compiler. As its name says, it is implemented entirely using templated classes. It has three parts:

  • Container classes — classes that hold data values. vector, set and map are containers. So is string.
  • Iterators — objects used to traverse a container and reach its elements. An iterator is a generalization of a pointer.
  • Algorithms — general-purpose functions, such as sort, that work on any container through its iterators.

Both string and vector are part of the STL. You already know two STL containers; today adds two more and the machinery that ties them all together.

Here is the thing worth pausing on. There is exactly one set class written in the library. It is a class template, so set<int>, set<string> and set<double> are three different classes that the compiler generates from the same source, at compile time, exactly the way your own class template worked last class.

Worked Example— one class template, three containers

Don't worry about what a set is yet — that's the next section. Look only at the shape of this program. Three declarations, three types, one library class. Predict the order in which the values print.

oneclass.cpp
// oneclass.cpp -- one class template, three completely different containers
#include <iostream>
#include <string>
#include <vector>
#include <set>
using namespace std;

int main() {
    set<int> a;
    a.insert(30); a.insert(10); a.insert(20);

    set<string> b;
    b.insert("pear"); b.insert("apple"); b.insert("fig");

    set<double> c;
    c.insert(2.5); c.insert(-1.25); c.insert(0.0);

    for (set<int>::const_iterator it = a.cbegin(); it != a.cend(); ++it) cout << *it << " ";
    cout << endl;
    for (set<string>::const_iterator it = b.cbegin(); it != b.cend(); ++it) cout << *it << " ";
    cout << endl;
    for (set<double>::const_iterator it = c.cbegin(); it != c.cend(); ++it) cout << *it << " ";
    cout << endl;
    return 0;
}

apple fig pear
-1.25 0 2.5

Every line came out sorted, even though nothing in the program says "sort". That is what a set does. Notice also that the three loops are identical apart from the type name. That is the whole promise of templates delivered: learn the interface once, use it for every element type you will ever have.

The -1.25 0 2.5 line is worth a second look. 0.0 printed as 0, because cout drops trailing zeros on a double — the same default formatting rule from Class 3.

Key Idea

You will almost never write a container class from scratch in real code. You wrote one in Class 26 so you would understand what the library is doing on your behalf — and so that when a template error message runs to forty lines, you know what it is talking about.

2.set: the index is the value

Start from what you know. In a vector, the data elements are ordered in a linear sequence, and you reach an element by its position: for a vector v, you write v[i], where i is a whole number from 0 up to v.size()-1. Position is everything. The value at position 3 got there because you put it there.

A set throws position away.

Definition— set

A set is a container class in the STL in which the "index" is the value itself. To use one, include the header #include <set>.

  • You insert elements into a set, and they are automatically sorted. Elements are therefore not pushed back onto the end of a set — there is no push_back, because there is no "end" you control.
  • The elements of a set are unique. If the same value is inserted several times, only one copy is kept.
  • The elements of a set cannot be reached with operator[].
Worked Example— inserting into a set

This is the course notes' set example, with the headers and the printing loop filled in so that it actually runs. Five calls to insert, one of them a repeat. Before you reveal: what is s.size(), and in what order do the strings appear?

setdemo.cpp
// setdemo.cpp -- inserting into a set of strings
#include <iostream>
#include <string>
#include <set>
using namespace std;

int main() {
    set<string> s;                  // set
    s.insert("cx");                 // "insert"
    s.insert("dyz");

    s.insert("aqt");                // elements are automatically sorted

    s.insert("aqt");                // elements are unique: this insert is IGNORED

    s.insert("bkmn");               // automatically sorted

    cout << "size = " << s.size() << endl;
    for (set<string>::iterator it = s.begin(); it != s.end(); ++it)
        cout << *it << endl;
    return 0;
}

bkmn

dyz

Five inserts, four elements. The second s.insert("aqt") changed nothing at all.

And the order is alphabetical, which is not the order they were inserted in. A set keeps its contents sorted at all times; that is not a service it performs when you ask, it is an invariant it maintains on every insert.

The traversal loop is the topic of §5. For now read it as "start at the beginning, stop at the end, step forward, print what the iterator points at."

Common Mistake— "inserting a duplicate replaces the old one"

The comment printed next to the repeated insert in the course notes says the second s.insert("aqt") replaces the previous entry. It does not. set::insert never overwrites. If the value is already there, the insertion is ignored and the element that was already in the set stays exactly as it was.

For a set<string> you cannot tell the difference, because the two strings are equal. You can tell for a class where two objects compare equal without being identical — and you will meet exactly that case in §8. Get the rule right now: insert into a full slot does nothing.

How do you find out whether the insert did anything? insert tells you. It returns a pair<iterator, bool> — an iterator to the element that is now in the set, and a bool that is true only if a new element was actually created.

Worked Example— what insert returns

A pair is another STL class template: two values glued together, reachable as .first and .second. You will see it again in the next section, because that is exactly what a map stores.

setinsert_return.cpp
// setinsert_return.cpp -- what insert actually returns
#include <iostream>
#include <string>
#include <set>
using namespace std;

int main() {
    set<string> s;
    pair<set<string>::iterator, bool> r1 = s.insert("aqt");
    cout << "first insert  of aqt: inserted = " << r1.second
         << ", element now = " << *r1.first << endl;

    pair<set<string>::iterator, bool> r2 = s.insert("aqt");
    cout << "second insert of aqt: inserted = " << r2.second
         << ", element now = " << *r2.first << endl;

    cout << "size = " << s.size() << endl;
    return 0;
}

second insert of aqt: inserted = 0, element now = aqt

r1.second is 1 — a new element was made. r2.second is 0 — nothing was made. A bool prints as 1 or 0 unless you ask for boolalpha, which is worth remembering on an output-prediction question.

The type name pair<set<string>::iterator, bool> is a mouthful, and it is a fair illustration of why the library's names get long. Read it inside out: an iterator into a set of strings, paired with a bool.

Asking a set questions: count, find, erase

Because a set has no positions, everything you do to it is phrased in terms of a value.

Procedure— the four set operations you need today
  1. s.insert(x) — put x in, unless it is already there.
  2. s.count(x) — returns 1 if x is in the set and 0 if it is not. (Never anything else: the elements are unique.) This is the simplest membership test.
  3. s.find(x) — returns an iterator to x, or s.end() if x is absent. Use it when you want the element and not just a yes/no.
  4. s.erase(x) — removes x and returns how many elements it removed: 1 or 0.

s.size() and s.empty() behave exactly as they do for a vector.

Worked Example— count, find and erase

Four values go in; two lookups hit, two miss; two erases, one of which has nothing to erase. Predict all seven lines.

setops.cpp
// setops.cpp -- find, count, erase, size on a set
#include <iostream>
#include <string>
#include <set>
using namespace std;

int main() {
    set<string> s;
    s.insert("cx");
    s.insert("dyz");
    s.insert("aqt");
    s.insert("bkmn");

    cout << "count(\"aqt\")  = " << s.count("aqt")  << endl;
    cout << "count(\"zzz\")  = " << s.count("zzz")  << endl;

    set<string>::iterator it = s.find("cx");
    if (it != s.end())
        cout << "find(\"cx\") found " << *it << endl;
    else
        cout << "find(\"cx\") found nothing" << endl;

    if (s.find("zzz") == s.end())
        cout << "find(\"zzz\") returned end()" << endl;

    cout << "erase(\"dyz\") removed " << s.erase("dyz") << " element" << endl;
    cout << "erase(\"zzz\") removed " << s.erase("zzz") << " elements" << endl;

    cout << "size = " << s.size() << " : ";
    for (set<string>::iterator p = s.begin(); p != s.end(); ++p)
        cout << *p << " ";
    cout << endl;
    return 0;
}

count("zzz")  = 0
find("cx") found cx

erase("dyz") removed 1 element

The pattern to memorize is the find idiom: compare the result against s.end(). end() is the library's way of saying "no such element", and testing against it is the only correct way to ask whether find succeeded. Never dereference the result before you have made that test — *s.find("zzz") is undefined behavior, exactly like dereferencing a dangling pointer from Class 8.

Erasing a value that is not present is not an error. It simply removes nothing and returns 0.

Quick Check 27.1

Consider set<int> s; followed by s.insert(7); s.insert(3); s.insert(7); s.insert(5);

(a) What is s.size(), and what does a traversal print?

s.size() is 3. The second insert(7) is ignored because 7 is already an element.

A traversal prints the values in sorted order: 3 5 7. The insertion order (7, 3, 5) is not recorded anywhere — a set has no memory of it.

(b) What are s.count(7) and s.count(4)?

s.count(7) is 1 and s.count(4) is 0. For a set these are the only two answers count can ever give, which is why it reads so naturally as a membership test: if (s.count(x)) { ... }.

(c) Rewrite s.count(7) using find instead.

    if (s.find(7) != s.end())
        cout << "7 is in the set" << endl;

find gives you more than count does: on success you also hold an iterator to the element, which you can dereference or pass to erase. When all you need is yes/no, count is shorter and reads better.

The one thing a set will not let you do

A vector element is reached by position, so v[0] makes sense. A set element has no position, so s[0] means nothing — and the compiler says so.

3.map: keys that need not be integers

Look again at what a vector really is. For a vector v, the element v[i] is found by the key i, and that key is an integer in the interval from 0 to v.size()-1. The key is forced on you: it must be a whole number, and the whole numbers must be consecutive starting at zero.

A map lifts that restriction.

Definition— map

A map is a container class in the STL holding (key, value) pairs, where the key is not necessarily an integer. To use one, include #include <map>.

  • You insert elements by specifying a key and a value. There are two template arguments: map<KeyType, ValueType>.
  • The elements are automatically sorted by key. As with a set, nothing is pushed back onto an end.
  • The keys of a map are unique. One key, one value.
  • The elements of a map can be reached with operator[] — but the subscript is the key, which need not be an integer.
Worked Example— a map<string,double>

The course notes' map example, with the headers and the printing loop supplied. Five assignments through operator[], one of which repeats a key. Predict the size and the order.

#include <iostream>
#include <string>
#include <map>
using namespace std;

int main() {

    m["xyz"]   = 3.4;           // key, value
    m["abcd"]  = 5.6;           // key, value, automatically sorted by key

    m["abcd"]  = 7.8;           // same key: this REPLACES the previous value
    m["bmnsy"] = 9.9;           // key, value, automatically sorted by key

    cout << "size = " << m.size() << endl;

    return 0;

Four keys, sorted alphabetically, and abcd carries 7.8 — the second assignment won. The first value, 5.6, is gone.

The loop body uses it->first and it->second. A map element is a pair<const Key, Value>: first is the key, second is the value. The arrow operator is the same one you met with pointers in Class 8 — §5 explains why it is the right one here.

Common Mistake— m[k] = v and m.insert(...) are not the same

The course notes describe putting a value into a map with the word "insert" throughout, and state that if you insert a (key, value) pair and then insert another pair with the same key, the first entry is erased. That is true of the code shown, which uses operator[] — but it is not true of the member function called insert:

  • m[k] = v; overwrites. If k is new the entry is created; if k is already there its value is replaced.
  • m.insert(make_pair(k, v)); does nothing at all if k is already present. Exactly like set::insert, it refuses to overwrite and silently keeps the old value.
  • m.insert_or_assign(k, v); (C++17) does what its name says, and returns whether it inserted.

This is the single most common bug students write with maps: a loop that "updates" entries with insert and then cannot work out why nothing changed.

Worked Example— overwrite versus refuse

One key, four attempts to set it. Work out what abcd maps to after each line.

mapinsert.cpp
// mapinsert.cpp -- operator[] overwrites; insert does not
#include <iostream>
#include <string>
#include <map>
using namespace std;

void show(const string &label, map<string,double> &m) {
    cout << label;
    for (map<string,double>::iterator it = m.begin(); it != m.end(); ++it)
        cout << " " << it->first << "=" << it->second;
    cout << endl;

    map<string,double> m;

    m["abcd"] = 5.6;
    show("after m[\"abcd\"] = 5.6 :", m);

    show("after m[\"abcd\"] = 7.8 :", m);

The surprise in m[k]

Here is the behavior that catches everyone, and it is worth ten minutes on its own.

Key Idea

m[k] inserts. If the key k is not already in the map, m[k] creates an entry for k, value-initializes it (0 for int and double, the empty string for string), and hands you back a reference to it. It does this even when you are only reading.

So cout << m["Carol"]; on a map that has never heard of Carol does not fail, does not warn, and does not print garbage. It prints 0 — and quietly makes the map one element bigger.

Worked Example— a lookup that changes the map

Two students go in. Then we ask about a third who was never enrolled. Watch size().

mapbracket.cpp
// mapbracket.cpp -- operator[] inserts even when you are only reading
#include <iostream>
#include <string>
#include <map>
using namespace std;

int main() {
    map<string,int> ages;
    ages["Alice"] = 20;
    ages["Bob"]   = 22;

    cout << "size before the lookup = " << ages.size() << endl;
    cout << "ages[\"Carol\"] = " << ages["Carol"] << endl;   // Carol was never inserted!
    cout << "size after  the lookup = " << ages.size() << endl;

    cout << "contents:";
    for (map<string,int>::iterator it = ages.begin(); it != ages.end(); ++it)
        cout << " " << it->first << "=" << it->second;
    cout << endl;

    // the safe way to ask "is this key present?"
    cout << "count(\"Dave\") = " << ages.count("Dave") << endl;
    if (ages.find("Dave") == ages.end())
        cout << "find(\"Dave\") returned end(), and nothing was inserted" << endl;
    cout << "size still = " << ages.size() << endl;
    return 0;
}

ages["Carol"] = 0
size after  the lookup = 3

Printing ages["Carol"] grew the map from 2 to 3. Carol is now a real entry with age 0, and she will show up in every subsequent traversal, in every count, in every total. Nothing in the program said "insert".

Why is operator[] built this way? Because it returns a reference to the value, and a reference has to refer to something. m[k] = v and ++m[k] both depend on that reference existing. The insert-on-read behavior is the price of making assignment work.

The lesson is a rule you should apply mechanically:

What you wantWhat to write
Set or update a valuem[k] = v;
Count occurrences++m[k]; — the auto-insert with value 0 is exactly what you want
Ask whether a key existsm.count(k) or m.find(k) != m.end() — never m[k]
Read a value you believe is therem.find(k), test against m.end(), then it->second

++m[k]; deserves the second row all to itself. On a brand-new key it creates the entry with value 0 and then increments it to 1; on an existing key it just increments. That one line is a complete word-frequency counter, as Practice Problem 1 shows.

Quick Check 27.3

Given map<string,int> m; and then m["a"] = 1; m["b"] = 2;

(a) After if (m["c"] == 0) cout << "absent"; runs, what is m.size()?

3. The condition looks like a pure test, but m["c"] inserted the pair ("c", 0) before the comparison happened. It then compared 0 == 0, so absent is printed — and the map now permanently contains a "c" that nobody meant to add.

This is why "check whether a key is present" must never be written with operator[].

(b) Write the correct membership test.

    if (m.count("c") == 0)
        cout << "absent";

or, equivalently:

    if (m.find("c") == m.end())
        cout << "absent";

Neither one modifies the map. count returns 0 or 1 for a map, just as for a set, because the keys are unique.

(c) m.insert(make_pair("a", 99)); — what is m["a"] afterwards?

Still 1. The key "a" is already present, so insert does nothing and keeps the existing value. To make it 99 you must write m["a"] = 99; or m.insert_or_assign("a", 99);.

Wrap-up. Three lines of code, three different behaviors: operator[] always writes, insert only writes into an empty slot, and find/count never write. Pick the one whose behavior you actually want; do not pick the shortest one.

4.Vector, set and map side by side

Vectors, sets and maps are all container classes. They all hold data, but in different ways, and there is one framing that makes the differences fall into place: think of every container as storing (key, value) elements.

ContainerWhat the key isWhat the value isKey type
vector<T>the position ithe element v[i]forced: consecutive integers 0 … size()-1
map<K,V>whatever you chose for Kthe V you stored with itanything with an operator<
set<T>the key is the value — one thing, playing both rolesanything with an operator<

Read the vector row carefully, because it is the row people gloss over. For a vector v, the key of the element v[i] is the integer i, and the set of keys is not up to you: it is exactly 0, 1, 2, ... up to v.size()-1, with no gaps. You cannot build a two-element vector whose only elements are v[3] and v[7]; a vector with two elements necessarily has elements v[0] and v[1]. If you want the numbers 3 and 7 to be the keys, you need a map.

Worked Example— what a key is allowed to be

Key Idea

Choose the container by asking what your key is.

  • Key is a position, and you care about order of insertion → vector.
  • Key is a meaningful value of its own (a name, an ID, a date) → map.
  • There is no separate value, you only care whether a thing is in the collection → set.

The value type of any of them can be anything at all, including a class you wrote. The key type of a map, and the element type of a set, are the ones with a requirement attached — §8.

5.Iterators

For a vector, you already know how to visit every element:

    for (size_t i = 0; i < v.size(); ++i)
        cout << v[i] << endl;

That loop does not work for a set or a map. There is no s[0], and m[0] on a map<string,double> would not even compile. So the library provides one mechanism that traverses every container in the STL, uniformly: the iterator.

Definition— iterator

An iterator is an object that marks a position in a container and can be moved along it. It is a generalization of a pointer: you dereference it with * to get the element it refers to, you advance it with ++, and you compare two of them with == and !=.

An iterator's type is specific to the container it walks, exactly as a pointer's type is specific to what it points at. For a vector<string> the type is vector<string>::iterator; for a vector<int> it is vector<int>::iterator; for a set<string> it is set<string>::iterator.

Procedure— the six parts of every iterator loop
  1. Declare an iterator of the container's own iterator type: vector<string>::iterator v_it;
  2. Initialize it to the start: v_it = v.begin();. Note that v.begin() is itself an iterator.
  3. Test with v_it != v.end(). v.end() is an iterator pointing one place beyond the last element.
  4. That test is the analogue of i < v.size(), because the last valid key is v.size()-1.
  5. Advance with ++v_it (the postfix form v_it++ also works).
  6. Dereference with *v_it to reach the element — the same notation as dereferencing a pointer.
Worked Example— a forward iterator over a vector

The same traversal you would write with an index, and then the same loop used to change every element. You can assign through an iterator by writing *v_it = value;.

One habit to build: the loop condition is !=, not <. For a vector you could get away with <, but a set or map iterator does not support < at all. Writing != everywhere means the loop shape you learn here transfers to every container without change.

Why end() is one past the last element

This looks like an off-by-one error waiting to happen, and it is the single most asked question about iterators. It is deliberate, and the reason is that it makes the empty container work.

Worked Example— the half-open range

A three-element vector, and an empty one. Look at what end() - begin() comes to, and at the last line.

Because end() sits one past the last element, the distance from begin() to end() is exactly the size. The range is half-open: begin() is included, end() is not. It is the same convention as for (i = 0; i < n; ++i), where i reaches n-1 and the loop stops when i equals n.

The payoff is the last line. For an empty container begin() and end() are equal, so the standard loop runs zero times and no special case is needed. Had end() meant "the last element", an empty container would have had nothing sensible to return.

end() must never be dereferenced. *v.end() does not point at an element; it is undefined behavior, just like reading v[v.size()]. *(v.end() - 1) is the last element, and that is legal — but the neater way to say it is v.back().

Quick Check 27.6

A student writes this loop over a vector<int> v and reports that it prints one extra garbage number at the end.

    vector<int>::iterator it;
    for (it = v.begin(); it <= v.end(); ++it)
        cout << *it << endl;

(a) What is wrong, and what is the fix?

The condition is <= where it must be != (or <). With <= the loop body runs one final time with it == v.end(), and *v.end() dereferences a position that holds no element. The "garbage number" is whatever memory happens to sit there; on another run it might crash instead.

    for (it = v.begin(); it != v.end(); ++it)
        cout << *it << endl;

(b) Why is != the better habit than <, even though both work for a vector?

Because < is not defined for set and map iterators. Those containers are trees, not blocks of contiguous memory, so "this position comes before that one" is not a cheap question and the library does not offer it. != is defined for every iterator in the STL, so the loop you learn with != is the loop you can use everywhere.

This is also the reason sort works on a vector but not on a set — see §9.

Iterators for a map: first and second

A map iterator has one extra wrinkle, because a map element is not one thing but two.

Definition— what a map iterator refers to

A map<K,V> iterator refers to a pair<const K, V>. That pair has two public data members:

  • first — the key. It is const, so you cannot change it.
  • second — the value. You may assign to it.

You reach them with the arrow operator: m_it->first and m_it->second. Since the iterator behaves like a pointer to the pair, m_it->first is shorthand for (*m_it).first — exactly the equivalence you learned for pointers in Class 8.

Warning— the iterator does not have first and second

You will see it said that "the map iterator contains two public data members first and second." That is a useful shorthand but it is not literally true, and the imprecision is exactly what makes students write m_it.first and then not understand the error.

The iterator points at a pair. The pair has first and second. That is why you need the arrow. Write m_it->first, or (*m_it).first — never m_it.first.

And note the variable name in the assignment: it is m_it->second = ..., using the iterator. m is the map itself; a map has no second.

6.Going backwards: reverse iterators

For a vector, running backwards with an index is easy enough:

    for (int i = v.size()-1; i >= 0; --i)
        cout << v[i] << endl;

Doing it with the iterators we have so far is a mess, and it is worth seeing the mess once so that the tool that removes it feels earned.

The obvious attempt is to start at end() and decrement until you hit begin(). Two things go wrong: end() is not a real element so you must not print it, and the loop stops at begin() — whose element you do want to print. The fix is a temporary iterator. Trace this on {A, B, C} before revealing.

Definition— reverse iterator

The iterators of §5 are all forward iterators. A reverse iterator is a different type that traverses a container from the last element to the first. The types are vector<string>::reverse_iterator, set<string>::reverse_iterator, map<string,double>::reverse_iterator, and it traverses from rbegin() ("reverse begin") to rend() ("reverse end").

Four things to fix in your head:

  1. The range is rbegin() to rend(), half-open exactly like the forward one.
  2. You increment with ++, not --. The word "reverse" describes the direction of traversal, not the operator. Don't be too clever here.
  3. Forward and reverse iterators are different classes. You cannot assign one to the other or compare them, any more than you can mix pointers of different types.
  4. rbegin() is not the same thing as end()-1, and rend() is not the same thing as begin()-1 — they are different types, and begin()-1 is undefined behavior anyway. They do refer to the same elements: *rbegin() is the last element.

#include <string>

Quick Check 27.8

A student wants to print a set<int> s from largest to smallest and writes:

    set<int>::iterator it;
    for (it = s.rbegin(); it != s.rend(); ++it)
        cout << *it << endl;

(a) Why does this not compile?

s.rbegin() returns a set<int>::reverse_iterator, and it is declared as a set<int>::iterator. They are two different classes, and there is no conversion between them — the compiler reports no matching operator=.

The fix is one word in the declaration:

    set<int>::reverse_iterator it;
    for (it = s.rbegin(); it != s.rend(); ++it)
        cout << *it << endl;

(b) Once the declaration is fixed, should the ++it become --it?

No. Reverse iterators are advanced with ++. The "reverse" is baked into the type: ++ on a reverse iterator moves it toward rend(), which is toward the front of the container. Writing --it would immediately walk off the wrong end.

This trips people up because it feels backwards. Read ++ as "advance to the next element of this traversal", not as "move right".

Yes, there are const iterators. And there are const reverse iterators.

8.Your own class in a set: operator<

Everything so far used int, double and string — types the compiler already knows how to order. Now put a class of your own into a set, and something has to give.

Take a minimal wrapper class:

class MyString {
public:
    MyString() {}
    MyString(const string &a) { str = a; }
    string str;
};

It is just a wrapper around a string. But it is missing something significant: there is no comparison operator< for MyString, so MyString objects cannot be sorted. And that one absence decides which containers you may build.

Key Idea
ContainerAllowed without operator<?Why
vector<MyString>YesA vector never sorts its elements; position is the key.
map<string, MyString>YesMyString is the value. Only keys are sorted.
set<MyString>NoA set is a sorted collection; the compiler does not know how to order two MyString objects.
map<MyString, int>NoMyString is the key, and keys are sorted.

The rule. You can build a set of a user-defined class, or use one as a map key, only if operator< is overloaded for that class.

Supplying operator<

This is Class 17 material, arriving with a purpose. Back then you overloaded operator+ and operator* as free functions taking two const references. operator< is the same job: a free function of two const references that returns bool.

bool operator< (const MyString &u, const MyString &v) {
    return (u.str < v.str);
}

Read the body carefully: the < inside is string's operator<, which already exists. You are not writing a comparison from scratch, you are delegating to one the library already has. That is the usual shape.

Common Mistake— comparing only one field

Suppose you write operator< for a Point that compares x only:

bool operator< (const Point1 &u, const Point1 &v) {
    return u.getx() < v.getx();          // WRONG for a set
}

Now (1,5) and (1,2) are equivalent — neither is less than the other — so a set<Point1> will keep only one of them and silently throw the other away. The comparison must use every field that distinguishes two objects. The standard shape is lexicographic: compare the first field, and only if it ties, move on to the next.

Worked Example— Class 17's Point1, now sortable

Here is the Point1 class you have been carrying since Class 17, given a lexicographic operator< and dropped into a set. Notice the operator uses the public accessors getx() and gety(), because the data is private — the same reason a free operator needed them in Class 17.

pointset.cpp
// pointset.cpp -- Class 17's Point1, given an operator< so it can go in a set
#include <iostream>
#include <string>
#include <set>
#include <vector>
#include <algorithm>
using namespace std;

class Point1 {
public:
    Point1() { x = 0.0; y = 0.0; }
    Point1(double a, double b) { x = a; y = b; }
    double getx() const { return x; }
    double gety() const { return y; }
    void print() const { cout << "(" << x << "," << y << ")"; }
private:
    double x, y;
};

// lexicographic: compare x first, and only if the x values tie, compare y
bool operator< (const Point1 &u, const Point1 &v) {
    if (u.getx() != v.getx()) return u.getx() < v.getx();
    return u.gety() < v.gety();
}

    set<Point1> s;
    s.insert(Point1(3.0, 1.0));
    s.insert(Point1(1.0, 5.0));
    s.insert(Point1(1.0, 2.0));
    s.insert(Point1(3.0, 1.0));          // duplicate: ignored

    cout << "set size = " << s.size() << endl;
    for (set<Point1>::const_iterator it = s.cbegin(); it != s.cend(); ++it) {
        it->print();
        cout << " ";
    }
    cout << endl;

    vector<Point1> v;
    v.push_back(Point1(3.0, 1.0));
    v.push_back(Point1(1.0, 5.0));
    v.push_back(Point1(1.0, 2.0));

9.Algorithms: sort

The third part of the STL is a collection of general-purpose algorithms — free functions that work on any container through its iterators. Include #include <algorithm> to use them. We will study exactly one: sort.

Definition— sort

sort takes three parameters:

  1. An iterator to the start of the collection to be sorted.
  2. An iterator to one place beyond the end of the collection to be sorted. (The same half-open range as every loop you have written today.)
  3. A comparison function.

The third parameter is optional. Leave it off and sort uses operator<, which is already defined for int, double and string — and for your own class too, once you have overloaded it.

Warning— sort does not work on a set or a map

sort needs to jump around inside the collection, so it requires random-access iterators. A vector has those; a set and a map do not. sort(s.begin(), s.end()) on a set fails to compile with a message about operator- not existing for the iterator type.

This is not a limitation you will ever feel, because a set and a map are already sorted. Sorting them would be asking for something you already have. Reach for sort when your data is in a vector.

Worked Example— sorting a vector of a user-defined class

The capstone program of the whole templates arc: a class of your own, an overloaded operator<, and one library call that puts three objects in order.

Common Mistake— passing operator< as the third argument

A very natural-looking version of that call appears in the course notes:

    sort(v.begin(), v.end(), operator<);        // does NOT compile

It does not compile. Writing the bare name operator< in an expression names an overload set, not a function — and with <string>, <vector> and using namespace std; in scope, there are dozens of candidates. The compiler cannot tell which one you mean, and reports:

sortorig.cpp:24:9: error: no matching function for call to 'sort(std::vector<MyString>::iterator, std::vector<MyString>::iterator, <unresolved overloaded function type>)'

unresolved overloaded function type is the phrase to recognize. There are two repairs:

  • Drop the third argument. sort(v.begin(), v.end()); — sort already uses operator< by default and finds yours. This is what the corrected program above does, and it is the right answer.
  • Pass a named function of your own, as in the next example. Give it a normal name, not operator<.

The same listing has a second error: its output loop writes cout << v[i] for a MyString, which has no operator<<. Both are fixed in sortfixed.cpp.

Worked Example— using the optional third parameter

When you want an order other than operator<, write a bool function of two const references and pass its name. Here: longest string first.

sortcmp.cpp
// sortcmp.cpp -- sort with an explicit third argument (a comparison function)
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

bool longerFirst(const string &a, const string &b) {
    return a.size() > b.size();
}

int main() {
    vector<string> v;
    v.push_back("Charlie");
    v.push_back("Al");
    v.push_back("Bobby");

    sort(v.begin(), v.end());               // default: operator< on string
    for (size_t i = 0; i < v.size(); ++i) cout << v[i] << " ";
    cout << endl;

    sort(v.begin(), v.end(), longerFirst);  // explicit comparison function
    for (size_t i = 0; i < v.size(); ++i) cout << v[i] << " ";
    cout << endl;
    return 0;
}
Al Bobby Charlie
Charlie Bobby Al

First alphabetical, then by decreasing length. Same vector, same sort, different third argument.

The comparison function must answer one question: does a come strictly before b? It returns bool, takes two const references, and must be consistent — if it says a comes before b it must not also say b comes before a. A comparison that returns true for two equal elements (for instance a.size() >= b.size()) breaks sort in ways that range from a wrong answer to a crash.

Note that longerFirst is passed without parentheses. You are handing sort the function itself, not calling it.

Problem 1 — Word frequency (added)

Write a complete C++ program that counts how many times each word appears in the sentence the cat sat on the mat the cat purred, and prints each word with its count, in alphabetical order, one per line. Plan. The key is a word, so the container is map<string,int>. The counting is one line: ++freq[word];. #include <string>
#include <sstream>
#include <map>

    istringstream in(text);

    map<string,int> freq;
    string word;
    while (in >> word)
        ++freq[word];                    // operator[] creates the entry with 0 if new

    for (map<string,int>::const_iterator it = freq.cbegin(); it != freq.cend(); ++it)

p2_uniquewords.cpp
// p2_uniquewords.cpp -- unique words, sorted, plus the repeats
#include <iostream>
#include <string>
#include <sstream>
#include <set>
using namespace std;

int main() {
    string text = "the cat sat on the mat the cat purred";
    istringstream in(text);

    set<string> seen;
    set<string> repeated;
    string word;
    int total = 0;
    while (in >> word) {
        ++total;
        if (seen.count(word) == 1)       // already there?
            repeated.insert(word);
        seen.insert(word);               // duplicates are simply ignored
    }

    cout << "words read   = " << total << endl;
    cout << "unique words = " << seen.size() << endl;
    cout << "sorted:";
    for (set<string>::const_iterator it = seen.cbegin(); it != seen.cend(); ++it)
        cout << " " << *it;
    cout << endl;
    cout << "repeated:";
    for (set<string>::const_iterator it = repeated.cbegin(); it != repeated.cend(); ++it)
        cout << " " << *it;
    cout << endl;
    return 0;
}

  • the appears three times but shows up once in repeated, because repeated is a set too. Uniqueness is doing double duty.
  • Swap the two statements in the loop and the program breaks: insert first and every word appears to be a repeat.
  • total has to be counted by hand — a set cannot tell you how many insertions were attempted, only how many elements it holds.
  • The map version of this from Problem 1 also answers it: every key whose value exceeds 1 is a repeat. Two containers, two routes, same information — choose the one whose shape matches the question.

Problem 4 — A gradebook, three ways (added)

Write a complete program that stores three students' averages in a map<string,double> and provides three functions:

(a) printForward — prints every student in increasing key order.

Take the map by const reference, and therefore use a const_iterator:

void printForward(const map<string,double> &g) {
    for (map<string,double>::const_iterator it = g.cbegin(); it != g.cend(); ++it)
        cout << it->first << " " << it->second << endl;
}

A plain iterator would not compile here. On a const map, begin() itself returns a const_iterator, so this is the case where const iterators stop being optional politeness.

(b) printBackward — the same list in decreasing key order.

void printBackward(const map<string,double> &g) {
    for (map<string,double>::const_reverse_iterator it = g.crbegin(); it != g.crend(); ++it)
        cout << it->first << " " << it->second << endl;
}

Identical body; only the iterator type and the two range functions changed. And still ++it.

(c) lookup(g, name) — prints the student's average, or "not enrolled", without adding anything to the map. Then assemble the whole program and verify that size() is unchanged after a failed lookup.

Plan. The whole point of part (c) is that g[name] is forbidden: it would insert the missing student. Use find, compare against end(), and read it->second only on the success branch. Taking the map by const reference makes the mistake impossible — operator[] is not even available on a const map, so the compiler enforces the rule for you.

p4_gradebook.cpp
// p4_gradebook.cpp -- walk a map forwards and backwards, and look keys up safely
#include <iostream>
#include <string>
#include <map>
using namespace std;

// print "name score" for every student, highest key last
void printForward(const map<string,double> &g) {
    for (map<string,double>::const_iterator it = g.cbegin(); it != g.cend(); ++it)
        cout << it->first << " " << it->second << endl;
}

// same list, in reverse key order
void printBackward(const map<string,double> &g) {
    for (map<string,double>::const_reverse_iterator it = g.crbegin(); it != g.crend(); ++it)
        cout << it->first << " " << it->second << endl;
}

// look up a name WITHOUT inserting it
void lookup(const map<string,double> &g, const string &name) {
    map<string,double>::const_iterator it = g.find(name);
    if (it == g.end())
        cout << name << ": not enrolled" << endl;
    else
        cout << name << ": " << it->second << endl;
}

int main() {
    map<string,double> grades;
    grades["Carol"] = 91.5;
    grades["Alice"] = 88.0;
    grades["Bob"]   = 74.25;

    printForward(grades);
    cout << "--- backward ---" << endl;
    printBackward(grades);
    cout << "--- lookups ---" << endl;
    lookup(grades, "Bob");
    lookup(grades, "Dave");
    cout << "size is still " << grades.size() << endl;
    return 0;
}

Problem 5 — A sortable Course class (added)

Write a class Course with private members dept (a string) and number (an int), a default constructor, a two-argument constructor, const accessors, and a const print(). Overload operator< so that courses order by department and then by number. Then, in main, put four courses into a set<Course> — one of them a duplicate — and print them; and separately sort a vector<Course> of the same courses.

Plan. Three pieces. (1) The class, written the way every class in this course is written: private data, public accessors marked const, a default constructor and a value constructor. (2) The free operator<, lexicographic on dept then number, using the accessors because the data is private — the same constraint that shaped the free operators in Class 17. (3) A main that exercises the two containers. Nothing about the sort call needs a comparison function, because operator< is already there.

p5_course.cpp
// p5_course.cpp -- a user-defined class with operator<, in a set and sorted in a vector
#include <iostream>
#include <string>
#include <vector>
#include <set>
#include <algorithm>
using namespace std;

class Course {
public:
    Course() { number = 0; }
    Course(const string &d, int n) { dept = d; number = n; }
    string getdept() const { return dept; }
    int getnumber() const { return number; }
    void print() const { cout << dept << " " << number; }
private:
    string dept;
    int number;
};

bool operator< (const Course &u, const Course &v) {
    if (u.getdept() != v.getdept()) return u.getdept() < v.getdept();
    return u.getnumber() < v.getnumber();
}

int main() {
    set<Course> catalog;
    catalog.insert(Course("CSCI", 211));
    catalog.insert(Course("MATH", 141));
    catalog.insert(Course("CSCI", 111));
    catalog.insert(Course("CSCI", 211));      // duplicate: ignored

    cout << "catalog size = " << catalog.size() << endl;
    for (set<Course>::const_iterator it = catalog.cbegin(); it != catalog.cend(); ++it) {
        it->print();
        cout << endl;
    }

    vector<Course> schedule;
    schedule.push_back(Course("MATH", 141));
    schedule.push_back(Course("CSCI", 211));
    schedule.push_back(Course("CSCI", 111));
    sort(schedule.begin(), schedule.end());
    cout << "--- sorted vector ---" << endl;
    for (size_t i = 0; i < schedule.size(); ++i) {
        schedule[i].print();
        cout << endl;
    }
    return 0;
}

Things to notice.

  • One operator, two payoffs. The same operator< made set<Course> legal and made sort work on the vector. It would also make map<Course, string> legal. Write it once.
  • Delete the operator and the program fails to compile in two places, with the std::less<Course> error from §8 for the set and a similar one from inside sort.
  • Comparing dept before number matters. Ordering by number first would interleave the departments — CSCI 111, MATH 141, CSCI 211.
  • The duplicate CSCI 211 was dropped. Equality was decided entirely by operator<: neither of the two is less than the other, so the set treats them as one element. Course has no operator== at all.
  • it->print() calls a member function through the iterator, and it compiles only because print() is marked const — a set's elements are always const. This is the payoff for the const-correctness habit from Class 10; skip the const on print() and this loop will not build.
Lecture Summary
  • The STL is built entirely from class templates and has three parts: containers (string, vector, set, map), iterators, and algorithms (sort).
  • A set (#include <set>) keeps its elements sorted and unique; the index is the value. Use insert, count, find, erase. There is no operator[] and no push_back.
  • A map (#include <map>) holds (key, value) pairs sorted by key, and the key need not be an integer. Keys are unique.
  • m[k] = v overwrites; m.insert({k,v}) does nothing if k already exists. And m[k] inserts even when you only read it — use count or find to test for a key, never operator[].
  • An iterator is a generalization of a pointer: *it to read the element, ++it to advance, it != c.end() to stop. Its type is the container's own, such as set<int>::iterator.
  • end() points one place past the last element, so the range is half-open and an empty container works with no special case. Never dereference end().
  • A map iterator refers to a pair<const Key, Value>: reach the key with it->first and the value with it->second. The key is const; the value is not.
  • Four flavors of iterator: forward (begin/end), reverse (rbegin/rend), const forward (cbegin/cend) and const reverse (crbegin/crend). All four advance with ++.
  • To put a class of your own in a set, or to use it as a map key, you must overload operator< — the Class 17 skill, now load-bearing. Compare every distinguishing field, lexicographically, or the container will treat different objects as duplicates.
  • sort from #include <algorithm> takes a start iterator, a one-past-the-end iterator, and an optional comparison function. It works on a vector, not on a set or map — which are sorted already.
