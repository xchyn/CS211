1.Four operators, two questions

C++ has specialized operators to increment or decrement the value of a variable by 1. There are four of them, and you have been typing them since your first for loop:

++x     // prefix increment
x++     // postfix increment
--x     // prefix decrement
x--     // postfix decrement

They look like a convenience — a shorter way to write x = x + 1. They are, but they are also the single most reliable source of confusion in this course, and the reason is that each of them does two things, and students learn only the first one.

Definition— value and side effect

Every expression in C++ has a value — the thing it evaluates to, which is what gets handed to whatever surrounds it. Some expressions additionally have a side effect — something they change in the program's memory on the way.

3 + 4 has a value (7) and no side effect. x = 9 has a side effect (it stores 9 in x) and a value (9, which is why y = x = 9 works). The four increment and decrement operators all have both, and the prefix and postfix forms have the same side effect but different values.

So there are always two questions to ask, and you must ask them separately:

ExpressionQuestion 1: what does the expression evaluate to?Question 2: what happens to x?
++xthe new value of x (after the step)increases by 1
x++the old value of x (before the step)increases by 1
--xthe new value of xdecreases by 1
x--the old value of xdecreases by 1
Key Idea

All four operators change the variable by exactly 1. What differs is which value the expression hands back. Read the operator position as a schedule: the ++ happens when you read it. ++x — the step comes first, so you get the new value. x++ — the x comes first, so you get the old value and the step happens afterwards.

Worked Example— the same step, two different answers

Both halves of this program start from 3 and both end with the variable holding 4. The only question is what lands in m1 and m2. Write down your four numbers before you open the toggle.

incr_increment.cpp
// incr_increment.cpp -- prefix vs postfix increment
#include <iostream>
using namespace std;

int main() {
    int n1 = 3;
    int m1 = ++n1;
    cout << "prefix: " << m1 << " " << n1 << endl;

    int n2 = 3;
    int m2 = n2++;
    cout << "postfix: " << m2 << " " << n2 << endl;
    return 0;
}
prefix: 4 4
postfix: 3 4

Trace it one statement at a time. The right-hand column is the whole point: the two n variables finish in the same state, and the two m variables do not.

StatementWhat the right-hand side evaluates toState afterwards

Notice what the postfix line means in practice: after int m2 = n2++; the two variables disagree. m2 is 3 and n2 is 4. That disagreement is exactly what exam questions are built on.

Why. --n3 steps n3 down to 2 and then hands back that new value, so m3 and n3 agree — both 2. n4-- hands back the old value 3 and then steps n4 down to 2, so the two disagree.

The pattern generalizes and is worth memorizing in this form: a prefix form always leaves the variable and the expression's value in agreement; a postfix form always leaves them one apart.

2.When the choice makes no difference

Before we chase the differences, let's be clear about where there are none — because that is where you have been using these operators all along, and it explains why the distinction never came up in CSCI 111.

If you write the operator as a complete statement, the value it produces is thrown away. Nothing reads it. All that survives is the side effect, and the side effect is the same for all four forms.

Worked Example— statement position: all four forms agree

Four variables, four different operator forms, each on a line of its own. Predict the line of output.

incr_statement.cpp
// incr_statement.cpp -- ++ and -- as standalone statements
#include <iostream>
using namespace std;

int main() {
    int a = 1, b = 2, c = 3, d = 4;
    ++a;
    b++;
    --c;
    d--;
    cout << a << " " << b << " " << c << " " << d << endl;
    return 0;
}
2 3 2 3

a went 1 to 2, b went 2 to 3, c went 3 to 2, d went 4 to 3. Swapping every ++a for a++ and every --c for c-- would print exactly the same line. When nothing reads the value, the two forms are interchangeable.

The same reasoning covers the third slot of a for header, which is where you meet these operators most often. That slot is executed as a statement and its value is discarded, so all of these loops are identical:

    for (int i = 3; i >= 0; i--) cout << i << " ";

Quick Check 3.2

Given that ++i and i++ behave identically in a for header:

(a) Is there any reason at all to prefer one of them?

For an int, no — the compiler generates identical machine code and you should write whichever you find easier to read. Most C++ programmers write ++i out of habit.

That habit has a real reason behind it, and it arrives later in this course. Once i is not an int but an object of a class you wrote, i++ has to produce the old value, which means it must first save a whole copy of the object before stepping. ++i has nothing to save. When we overload these operators ourselves in Class 17 the cost difference becomes visible in the code. Writing ++i now costs nothing and means you never have to change the habit.

(b) What about the second slot — would for (int i = 0; i++ < 4; ) also print 0 1 2 3?

No. The second slot is the loop test, and a test is an expression whose value is very much read — so the prefix/postfix distinction is live there, and on top of that the increment now happens once per test rather than once per iteration.

With i++ < 4 the test evaluates to the old i, so the body runs for i equal to 1, 2, 3 and 4 (the test compared 0, 1, 2, 3), and the loop prints 1 2 3 4. With ++i < 4 it would print 1 2 3. Neither prints 0 1 2 3.

The lesson is not that this is a puzzle to solve. It is that hiding the loop update inside the test is unreadable, and you should not write it. Keep the update in the third slot where a reader expects it.

3.When the choice makes all the difference

Now move the operator inside a larger expression, so that something actually reads the value it produces. This is where the two forms separate, and it is the form every exam question in this course uses.

Worked Example— the same four variables, inside one cout

Identical starting values to the last example — 1, 2, 3, 4 — and identical operators. The only change is that the operators now sit inside a cout chain instead of on lines of their own. There are two lines of output to predict, and they are not the same.

Quick Check 3.3

Two counting loops that differ by one operator position. Predict all four lines.

ex1_solution.cpp
// ex1_solution.cpp -- the same counter printed two ways
#include <iostream>
using namespace std;

int main() {
    int i = 0;
    while (i < 5) {
        cout << i++ << " ";       // print the old value, then step
    }
    cout << endl << "i ended at " << i << endl;

    int j = 0;
    while (j < 5) {
        cout << ++j << " ";       // step first, then print the new value
    }
    cout << endl << "j ended at " << j << endl;
    return 0;
}
0 1 2 3 4
i ended at 5
1 2 3 4 5
j ended at 5

Why. Both loops run exactly five times, and both counters finish at 5 — the side effect is identical. But cout << i++ prints the value before the step, so the printed run starts at 0 and stops at 4, while cout << ++j prints the value after the step, so it starts at 1 and stops at 5.

Things to notice. This is a genuinely useful idiom, not just a puzzle. When you want to print an item and advance a counter in one step, x[i++] is the standard way to write it — it means "use the current index, then move on." You will see it constantly once we reach arrays and pointers in Class 7.

4.Chains, and side effects that outlive the line

This professor's exams ask you to predict output for a numbered list of lines, not for a single line. The trap is deliberate: the first line contains increments, and the second line prints the same variables. If you forget to carry the side effects forward, you get the first line right and the second line wrong, and there is no partial credit on either.

Procedure— how to trace a cout chain by hand
  1. Write the current value of every variable in the margin. Keep this table alive for the whole program; do not restart it at each line.
  2. Work through the chain strictly left to right, one item at a time.
  3. For each item, ask the two questions from §1 in order: what does it print? then what does it leave behind? Write the printed character down and update your margin table before moving to the next item.
  4. When the line ends, your margin table is the starting point for the next line. Carry it forward.
  5. Remember that cout inserts nothing between items. If your chain has no spaces in it, neither does the answer.
Worked Example— the exam's own shape, two lines

This is exactly the format used in the "what is the output for each of the following lines" question. Note that there are no spaces anywhere in either chain, so each line of output is a run of digits jammed together. Predict both lines.

chain_exam.cpp
// chain_exam.cpp -- one cout chain mixing ++ and --, then the same variables again
#include <iostream>
using namespace std;

    cout << x++ << ++y << z-- << --w << endl;   // line (a)
    cout << x << y << z << w << endl;           // line (b)
    return 0;
}

So line (a) is 3, 6, 7, 8 printed with nothing between them: 3678.

Line (b) prints the margin table as it now stands — 4, 6, 6, 8 — giving 4668. Every one of those four digits was changed by line (a). A student who answers line (b) with the original 3579 gets zero for that part.

Key Idea

An output-prediction question is a simulation, not a series of independent puzzles. Keep one running table of variable values from the top of main to the bottom. Most lost points on this question type come from restarting the trace at each labelled line.

One more thing has to be said about the order, because it is the part students most often hear wrong. In a chain like cout << f() << g(), is the compiler allowed to run g() first? For operator<< in C++17, no: the left operand of each << is fully evaluated, side effects included, before the right operand is touched. That is why the trace above is reliable and not a guess.

Common Mistake— changing the same variable twice in one statement

The left-to-right guarantee applies to the operands of <<. It does not rescue a statement that writes to one variable twice through ordinary arithmetic. This line has no defined meaning in any version of C++:

ub_selfassign.cpp
// ub_selfassign.cpp -- DO NOT WRITE THIS. i is modified twice in one statement.
#include <iostream>
using namespace std;

int main() {
    int i = 5;
    i = i++ + 1;          // undefined behavior
    cout << i << endl;
    return 0;
}

i++ stores a new value into i, and so does the assignment, and the language does not say which happens first. This is undefined behavior: the standard imposes no requirement at all, so the compiler may print 6, print 7, or do something else entirely, and it is free to change its mind when you add an unrelated line elsewhere. There is no correct answer to "what does this print," and the right response on an exam or in a code review is to say so.

g++ tells you, if you asked for warnings:

ub_selfassign.cpp: In function 'int main()':
ub_selfassign.cpp:7:7: warning: operation on 'i' may be undefined [-Wsequence-point]
    7 |     i = i++ + 1;          // undefined behavior
      |     ~~^~~~~~~~~

This is the concrete payoff of adding -Wall to the compile command. Write i = i + 1; or ++i; and the question disappears.

5.How cout prints a double

Back in Class 1 a program computed the area of a circle of radius 3 and printed 28.2743, even though the stored value has far more digits than that. We promised to come back to it. Here it is, because it is worth points.

When you hand cout a double and give it no other instructions, it does not print the number. It prints a rendering of the number under a specific, fixed default rule, and the rule surprises people in three separate ways.

Definition— cout's default floating-point format

An output stream carries a setting called its precision, and for cout it starts at 6. In the stream's default mode that number means six significant digits — six digits counting from the first nonzero one, wherever the decimal point happens to fall — not six digits after the decimal point.

On top of that, the default mode:

  • drops trailing zeros, and drops the decimal point too if nothing is left after it; and
  • switches to scientific notation when the number is too large or too small to show in six significant digits without padding — roughly, when the exponent would be 6 or more, or less than -5.

This applies to double and float values only. Integers are printed in full, always.

Common Mistake— writing 4.0 when the program prints 4

Every version of this course's midterm contains at least one output-prediction part whose answer hinges on this. A program computes the area of a square of side 2.0, prints it, and the expected answer is:

4

not 4.0 and not 4.00. The value is a double; the printing rule is what it is. Get in the habit now: when you write down a predicted line of output, write what the stream will emit, not what the variable holds.

The mirror-image mistake is just as common in the other direction. cout << 10 / 4 prints 2, because that is integer division — the value never became 2.5 in the first place. Decide the type of the expression first, then apply the printing rule.

Rendering money as 149.1 instead of 149.10 is not acceptable, so C++ gives you a way to override the default. It lives in a second header.

Definition— fixed and setprecision

#include <iomanip> brings in a set of manipulators — values you can send to a stream that change how it behaves from that point on rather than printing anything.

  • fixed switches the stream out of its default mode into fixed-point mode. In fixed mode the precision means digits after the decimal point, and trailing zeros are kept.
  • setprecision(n) sets the precision to n.

Both are sticky: they change the stream and stay in force for every later output until you change them again. They are not per-value formatting.

Worked Example— taking control of the format

The same two values printed four times under four settings. Note that cout.unsetf(ios::fixed) is the way back to the default mode.

fmt_iomanip.cpp
// fmt_iomanip.cpp -- taking control of the formatting
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    double price = 4.0;
    double third = 1.0 / 3.0;

    cout << "default:                " << price << "  " << third << endl;

    cout << fixed << setprecision(2);
    cout << "fixed, 2 decimals:      " << price << "  " << third << endl;

    cout << setprecision(4);
    cout << "fixed, 4 decimals:      " << price << "  " << third << endl;

    cout.unsetf(ios::fixed);
    cout << setprecision(6);
    cout << "back to the default:    " << price << "  " << third << endl;
    return 0;
}
default:                4  0.333333
fixed, 2 decimals:      4.00  0.33
fixed, 4 decimals:      4.0000  0.3333
back to the default:    4  0.333333

Three things to take from this:

  • fixed is what makes 4.0 finally print as 4.00. Without it, setprecision alone would still drop the trailing zeros.
  • The third block only sends setprecision(4) — fixed is still in force from the previous block, because manipulators stick. That is a feature when you want it and a bug when you forget it.
  • setprecision changes meaning depending on the mode. In fixed mode it counts digits after the point; in the default mode it counts significant digits. Same call, two different rules.
Quick Check 3.7

A student wants every number in a table printed to exactly two decimal places, so they write cout << setprecision(2); at the top of main and nothing else. They then print 4.0, 1.0/3.0 and 149.1.

(a) What do they actually get, and why?

They get 4, 0.33 and 149.

Without fixed, the stream stays in its default mode, so setprecision(2) means two significant digits, and trailing zeros are still dropped. So 4.0 loses its zeros as before; 1.0/3.0 keeps two significant digits and becomes 0.33; and 149.1 rounded to two significant digits would be 150 — which prints as 149? No: two significant digits of 149.1 is 1.5e+02. Do not guess at this one — the point of the question is that the result is hard to predict and therefore the wrong tool. Reach for fixed.

(b) Write the one line that actually does what they wanted.

    cout << fixed << setprecision(2);

Send it once, before the table. Every double printed afterwards comes out with exactly two digits after the point, trailing zeros and all: 4.00, 0.33, 149.10.

6.break and continue

Suppose a program is executing a loop. It could be a for loop or a while loop — it does not matter. Two keywords let you cut a pass short.

Definition— break

break means exit the loop immediately.

  1. Do not execute the rest of the code in the loop, below the break statement.
  2. Do not perform the end-of-loop test, and do not update the loop counter.

Execution resumes at the first statement after the loop.

Definition— continue

continue means go to the next iteration through the loop immediately.

  1. Do not execute the rest of the code in the loop, below the continue statement.
  2. Do update the loop counter and do perform the end-of-loop test.
  3. If the test passes, begin execution of the next pass through the loop.
Key Idea

Both keywords skip the rest of the loop body. The difference is entirely in what happens next: break skips the update and the test and leaves; continue performs the update and the test and stays. If you can state that one sentence you can answer every break/continue question on this course's exams.

Both keywords apply to the innermost loop that encloses them. In a nested loop, a break in the inner loop ends the inner loop only; the outer loop carries on. We rely on that in §7.

Quick Check 3.9

Questions about the primes program above.

(a) Replace the break with a continue. Does the program still print the right answer?

Yes — the output is unchanged. Once b has been set to false it is never set back to true, so continuing to grind through the remaining candidate divisors cannot change the verdict. It only wastes time.

That is the honest answer, and it is worth knowing: break here is an optimization, not a correctness requirement. It matters when the loop is long. It would matter enormously if the inner loop had a side effect, such as printing.

(b) Delete the bool b entirely and print i right where the break currently is. What breaks?

You would be printing exactly the numbers that are not prime, since that is the branch the break lives in. Inverting it is not a one-line fix either: there is no statement inside the inner loop that runs "if no divisor was ever found," because that fact is only known after the loop finishes.

That is the general reason for the flag. A loop can tell you "I found one" the moment it happens, but it can only tell you "there was none" once it has ended. When you need the second kind of answer, you need a variable declared outside the loop to carry it out. You will use this pattern in nearly every search you write.

(c) The inner loop starts at j = 3. Why is it safe never to test j = 2?

Because the outer loop only ever produces odd values of i — it starts at 3 and steps by 2 — and no odd number is divisible by 2. Testing it would always leave a remainder, so it is guaranteed wasted work.

The same argument is what licenses j += 2 rather than j++: every even divisor is a multiple of 2, and we have just ruled 2 out.

8.From nested if to guard clauses

The last idea today is the reason continue earns its place in the language. Consider a program that loops over some integers i and:

Now watch what happens when you turn each test inside out. Instead of "if the condition holds, do the rest of the work inside here," say "if the condition fails, abandon this pass now." The work moves out of the braces and the braces disappear.

Definition— guard clause

A guard clause is a test at the top of a block whose only job is to bail out early when the block has nothing to do. Inside a loop the bail-out is continue (or break); inside a function it is return.

The transformation is mechanical. Any nesting of the form

if (P) {
    A;
    if (Q) {
        B;
    }
}

can be rewritten, when it is the whole body of a loop, as

if (!P) continue;
A;
if (!Q) continue;
B;

Each condition is negated, each { disappears, and each block of real work moves out to the left. The two versions execute the same statements in the same order.

Problem 4 — Write a complete C++ program (added)

Write a complete C++ program that finds the first ten integers between 100 and 999 that are divisible by 7 but not divisible by 5. Print them on one line separated by spaces. Then print how many were found and their average, with the average shown to exactly two decimal places. Use continue for the filters and break for the stopping rule.

Plan. Four separate jobs, and keeping them separate is what makes the program easy to write.

  • Two filters, each its own guard clause with a negated condition, at the top of the loop body. A number survives to the printing only if it passes both.
  • A counter and a running total, both declared outside the loop so they survive it.
  • A stopping rule after the work: once the counter reaches ten, break.
  • The average is total / count, and both of those are int, so it needs a cast to double or it will silently be integer division. Then fixed and setprecision(2) from <iomanip> to get two decimal places.
prac_filter.cpp
// prac_filter.cpp -- the first ten multiples of 7 above 100 that are not multiples of 5
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    int count = 0;
    int total = 0;

    for (int i = 100; i <= 999; ++i) {
        if (i % 7 != 0) continue;          // not a multiple of 7 -- skip it
        if (i % 5 == 0) continue;          // also a multiple of 5 -- skip it
        cout << i << " ";
        total += i;
        ++count;
        if (count == 10) break;            // we have all ten -- stop looking
    }
    cout << endl;

    cout << "count   = " << count << endl;
    cout << "average = " << total / count << endl;
    cout << "average = " << static_cast<double>(total) / count << endl;
    cout << fixed << setprecision(2);
    cout << "average = " << static_cast<double>(total) / count << endl;
    return 0;
}

Problem 5 — Flatten and fix (added)

A student wrote the loop below to report on a list of temperatures. It is meant to print reading for every value in the plausible range from -50 to 60, then warm for those at 25 or above, then hot for those at 35 or above. Rewrite the body using guard clauses, and say what it prints.

    const int n = 6;
    int t[n] = {18, 25, -80, 35, 60, 41};

    for (int i = 0; i < n; ++i) {
        if (t[i] >= -50) {
            if (t[i] <= 60) {
                cout << t[i] << ": reading" << endl;
                if (t[i] >= 25) {
                    cout << t[i] << ": warm" << endl;
                    if (t[i] >= 35) {
                        cout << t[i] << ": hot" << endl;
                    }
                }
            }
        }
    }

Plan. The nest is the entire loop body and there are no else branches and no work after it, so the mechanical transformation from §8 applies directly. Negate each of the four conditions and replace each { with a continue. Watch the boundaries: the opposite of >= -50 is < -50, and the opposite of <= 60 is > 60.

temps_guard.cpp
// temps_guard.cpp -- temperature report, guard-clause style
#include <iostream>
using namespace std;

int main() {
    const int n = 6;
    int t[n] = {18, 25, -80, 35, 60, 41};

    for (int i = 0; i < n; ++i) {
        if (t[i] < -50) continue;
        if (t[i] > 60)  continue;
        cout << t[i] << ": reading" << endl;
        if (t[i] < 25) continue;
        cout << t[i] << ": warm" << endl;
        if (t[i] < 35) continue;
        cout << t[i] << ": hot" << endl;
    }
    return 0;
}

Things to notice.

  • -80 produces nothing — the first guard removes it. 60 is kept, because the check is <= 60 and 60 is inside the range; the negated guard > 60 is false for it. That one character is the difference between five reported values and four.
  • 25 gets reading and warm but not hot; 35 gets all three. Both are boundary values and both are in the data on purpose.
  • The values come out in array order, not sorted order — 41 is printed last because it is last in the array. A loop over an array reports in the order the array holds, and nothing here sorts anything.
  • The flat version has one entry point and six statements you read top to bottom. The nested version has the same six statements and four closing braces you have to match up by eye. Both compile to the same thing; only one of them can be checked against the specification at a glance.
Lecture Summary
  • All four of ++x, x++, --x, x-- change the variable by exactly 1. What differs is the value the expression hands back: a prefix form gives the new value, a postfix form gives the old one.
  • As a standalone statement, or in the third slot of a for header, the value is discarded, so all four forms behave identically. Inside a larger expression the difference is everything.
  • In C++17 the operands of << are evaluated strictly left to right, side effects included, so a cout chain can be traced one item at a time. Carry the resulting values forward into the next line — that is what output-prediction questions are testing.
  • A statement that writes to the same variable twice, such as i = i++ + 1;, is undefined behavior. It has no correct answer. Compile with -Wall and g++ will tell you.
  • Output formatting — added to these notes, not in the original lecture: with no instructions, cout prints a double to six significant digits, drops trailing zeros and the bare decimal point, and switches to scientific notation outside roughly 1e-5 to 1e+6. So 4.0 prints as 4, 1.0/3.0 as 0.333333, 100.0/3.0 as 33.3333 and 1234567.0 as 1.23457e+06. Exam output-prediction parts depend on this and give no partial credit.
  • #include <iomanip> and send fixed and setprecision(n) to take control. They are sticky: they change the stream, not one value. Under fixed the precision counts digits after the point, so 4.0 finally prints as 4.00.
  • break exits the loop immediately — no more body, no update, no test. continue starts the next pass immediately — no more body, but the update does run and the test is performed. Both act on the innermost enclosing loop.
  • continue inside while (true) hangs the program unless something above it changes the state the condition depends on.
  • Deep if nesting inside a loop flattens mechanically into guard clauses: negate each condition, replace each block with continue, and the real work moves out to the left. Valid only when the nest is the whole loop body.
  • A character that looks like ! or ; but is not ASCII produces a compiler message quoting a \U0000xxxx escape you never typed. Retype the line rather than staring at it.
