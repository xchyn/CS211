1.Why an array is not enough

Start from something you already know. In CSCI 111 you stored a list of numbers in an array:

int a[10];

That one line makes ten integers, side by side in memory, reachable as a[0] through a[9]. It is fast, it is simple, and it has one property that quietly ruins it for real programs: the length is fixed at 10, a number you have to know in advance. Not "in advance" as in "before the loop starts" — in advance as in while you are typing the source code, before the program has ever run, before anyone has entered any data.

Definition— array

An array is a block of memory holding a fixed number of values, all of the same type, laid out one after another. The declaration int a[10]; reserves room for exactly ten ints. Individual values are reached by subscripting: a[0] is the first, a[9] the last.

Two facts about an array are going to matter all class:

  • Its length is baked in at compile time and can never change.
  • The array itself does not know its own length. If you pass a to a function, you must pass the number 10 along beside it, and if the two ever disagree, nothing in the language notices.

Here is the problem the course notes use to make the point, and it is worth sitting with for a moment because it is completely ordinary:

Key Idea— the motivating problem

Suppose we want to have arrays x and y of type double, to hold the (x, y) coordinates of the vertices of a polygon.

How big do you make them? A triangle needs 3. A pentagon needs 5. A traced outline of a coastline might need 40,000. The number of vertices is not known when you write the program — it is known when the user opens a file or finishes clicking. An array cannot express that.

Students usually reach for one of two workarounds, and both are bad. The first is to declare the array enormously large — double x[100000]; — and use only the front of it. That wastes memory, and it still fails on the polygon with 100,001 vertices. The second is to keep a separate counter variable that says how much of the array is really in use:

fixedarray.cpp
// fixedarray.cpp -- an array's length is fixed at compile time
#include <iostream>
using namespace std;

int main() {
    int a[10];               // exactly 10 ints, forever
    for (int i = 0; i < 10; ++i) {
        a[i] = i * i;
    }
    cout << "a[9] = " << a[9] << endl;

    int n = 3;               // suppose we discover we only needed 3
    cout << "we used " << n << " of the 10 slots" << endl;
    return 0;
}

That counter n is the tell. You are now carrying two things around — the data and the length — and hand-keeping them in agreement in every function that touches the array. Every bug in that bookkeeping is an out-of-bounds access, and out-of-bounds accesses in C++ do not politely stop your program. They corrupt it.

The C++ answer is a type that carries the length inside itself and that can change that length while the program runs. That type is vector, and it is the subject of today and Class 6.

Quick Check 5.1

Think about the array workarounds above before we look at any new syntax.

(a) A student writes int a[n]; where n is an ordinary int variable read from cin. Is that legal standard C++?

No. The length of an array must be a compile-time constant. A few compilers, g++ among them, accept this as a non-standard extension called a variable-length array, which is exactly why students get away with it and then are baffled when the same code is rejected elsewhere or crashes for large n.

Write it and compile with the flags this course uses and you are relying on an extension the language does not promise. Do not build habits on it. The two standard answers are a vector (today) and dynamically allocated memory with new (Class 8).

(b) Why is "just declare it big enough" not merely wasteful but actually unsafe?

Because "big enough" is a guess, and the program has no way to tell you when the guess was wrong. If you declare double x[1000]; and the data turns out to have 1,200 points, the loop that fills it writes x[1000] through x[1199] into memory that belongs to something else — other variables, the function's own bookkeeping, anything. The program does not stop. It keeps running with silently corrupted state, and the crash, if it comes at all, comes somewhere else entirely.

That is the failure mode this whole topic exists to avoid: a wrong answer is worse than an error message, because an error message tells you where to look.

2.The vector: a generalized array

The course notes give vector a name that is worth adopting: a vector is a generalized array. It behaves like an array — same subscripting syntax, same "all elements have the same type", same contiguous storage — and it adds information and abilities that a bare array does not have.

Definition— vector

A vector is a standard-library type that stores a sequence of values of one type, keeps track of how many it is holding, and can change that number while the program runs. The element type is written in angle brackets after the word: vector<int>, vector<double>, vector<string>.

Two words we will use constantly:

  • An element is one stored value.
  • The index (or subscript) of an element is its position, counting from 0, exactly as with an array.

The number of elements a vector currently holds is its size, and you ask for it by calling the method size().

Here is the property list from the course notes, which is the clearest statement of what you are getting:

  1. The length doesn't need to be specified in advance (default = 0).
  2. The length can be specified later, during program execution.
  3. The length can change, during program execution.
  4. We are permitted to "resize" a vector, and it can be resized to a smaller value if desired.
  5. As opposed to a C++ array, a vector knows its length.
  6. A vector contains internal information, including its length.
  7. This is part of the notion of a generalized array: a vector contains extra information.

Properties 5 and 6 are the ones that pay off immediately. Because the length travels with the data, a function that receives a vector does not need a separate length parameter, and the two can never fall out of step.

Warning— you need the header

Vectors do not come with #include <iostream>. You must include the vector header yourself:

#include <vector>

Leave it out and the message is a familiar one from Class 1 — a name the compiler has never heard of:

novector.cpp: In function 'int main()':

Before the syntax, one connection. You have used a class with methods already, probably without calling it that: string.

Worked Example— string is a class, and that is the pattern

This is the course notes' bridge into vectors. A string is not a built-in type like int — it is a class from the standard library, it carries its own data, and you operate on it by calling methods with the dot operator. Predict both lines.

  • string s("abcd"); constructs the object by passing an initial value in parentheses. Vectors are constructed the same way, and the parentheses will matter in §3.

Quick Check 5.2

Explain, in one sentence each, what goes wrong in the following two situations. Neither is a trick question; both are about the difference between an array and a vector.

(a) A function is declared double sum(double a[], int n); and a caller passes an array of 12 values but writes sum(a, 10).

The function happily adds up the first ten and reports that as the total — a silently wrong answer, with no error at compile time and none at run time. The array had no way to contradict the number 10, because an array does not know its own length.

Change the parameter to a vector and the bug becomes impossible to write: there is no second argument to get wrong, because the length rides along inside the vector.

(b) The same function is declared double sum(double a[], int n); and the caller writes sum(a, 20) for that same 12-element array.

The loop runs off the end of the array and reads eight doubles' worth of memory that was never part of it. What it finds there is whatever happened to be in those bytes, so the total is garbage — and if the function had been writing instead of reading, it would have overwritten unrelated variables.

Once again there is no error message. The C++ rule is uniform and it is the point of §5 below: subscripting outside the valid range is your mistake to prevent, not the language's to detect.

Common Mistake— parentheses, not square brackets

The course notes flag this explicitly, and it is worth the emphasis: note the syntax — it is parentheses, i.e. (n), not square brackets [n].

Write square brackets and the line still compiles, which is what makes this dangerous:

const int n = 10;
vector<int> vec_i[n];        // WRONG: an array of 10 empty vectors!

That declares an array of ten vectors, each one empty. Nothing complains until you try to use it as though it held integers, and then the message is a wall of template noise:

brackets.cpp: In function 'int main()':
brackets.cpp:8:16: error: no match for 'operator=' (operand types are 'std::vector<int>' and 'int')
    8 |     vec_i[0] = 5;
      |                ^

The useful part is in the parentheses at the end of the first line: operand types are std::vector<int> and int. The compiler is telling you that vec_i[0] is a whole vector, not an int. Whenever an error mentions a type you did not think you had written, go back and re-read the declaration.

What is in the elements?

An ordinary C++ array contains uninitialized memory when it is declared. A sized vector does not.

Worked Example— garbage versus zero

Two five-element containers, declared side by side and immediately printed. Predict both lines — and predict how confident you are about each one.

garbage.cpp
// garbage.cpp -- an array starts as garbage; a vector starts as zeros
#include <iostream>
#include <vector>

int main() {
    int arr[5];              // uninitialized: whatever bytes were already there
    vector<int> vec(5);      // length 5, every element initialized to 0

    cout << "array : ";
    for (int i = 0; i < 5; ++i) cout << arr[i] << " ";
    cout << endl;

    for (int i = 0; i < 5; ++i) cout << vec[i] << " ";

The array line is machine-dependent and the numbers above are only representative. Reading an uninitialized variable has no defined answer in C++; those five values are simply whatever bytes were sitting in that piece of the stack. Running the same executable a second time on the same machine produced a different last value. Never write a program that depends on them.

The vector line, by contrast, is guaranteed. vector<int> vec(5); value-initializes its elements, so every one of them is 0. For a vector<double> they would all be 0; for a vector<string>, empty strings. The course notes state the rule directly: if we do not specify data values, they will be defaulted to zero.

This is a real reason to prefer a vector even when you do know the length in advance. The array version has a whole class of bug the vector version simply cannot have.

Supplying an initial value

If zero is not the starting value you want, give the fill value as a second argument:

int n = 10;
vector<char>   vec_c(n, ' ');      // ten blanks
vector<int>    vec_i(n, 1);        // ten ones
vector<double> vec_d(n, 3.14);     // ten copies of 3.14

And if you know the actual values at the point of declaration, you can list them in braces, exactly as you would initialize an array with int a[] = {1, 2, 4, 8, 16};:

vector<int> powers{1, 2, 4, 8, 16};      // five elements, size 5

Quick Check 5.3

For each declaration, state the size of the vector and the value of every element. Assume int n = 4; is in scope.

(a) vector<double> v;

Size 0. There are no elements at all — not "four empty slots", none. Any subscript, including v[0], is out of bounds until something is pushed into it.

This is the normal way to start when the data is going to be read in, and it is the form every exam program in this course begins with.

(b) vector<int> v(n);

Size 4, elements 0 0 0 0. The length may be a variable, and with no fill value given the elements default to zero.

(c) vector<int> v(n, -1);

Size 4, elements -1 -1 -1 -1. The second argument is the value every element starts at, not an extra element.

(d) vector<int> v{n};

Size 1, the single element 4. Braces list contents, so this is a vector holding the current value of n.

Things to notice. Parts (b) and (d) differ by two characters and produce completely different objects. When you are reading someone else's code — or your own from last week — check the bracket shape before you assume you know the size. And when writing, prefer to make your intent obvious: vector<int> v(n, 0); says "n zeros" out loud, even though the , 0 is redundant.

4.Getting and setting elements

Now the good news, and it is genuinely the reason this type is easy to adopt: the syntax to get and set the values of elements is exactly the same as for a C++ array. No new notation to learn.

Definition— the subscript operator []

For a vector v and an integer i in range, the expression v[i] names the element at index i. It can be used on either side of an assignment:

  • cout << v[i]; gets the value.
  • v[i] = 2 * i; sets the value.

Valid indices run from 0 to v.size() - 1. Indices count from zero, just as they do for arrays, so a vector of size 10 has no element v[10].

5.Out of bounds: what really happens

Here is the sentence from the course notes, and it is the most important correction on this page:

Warning— correcting a claim you will see repeated

The course notes state:

  • "The C++ program above compiles successfully, but generates a run-time error."
  • "Attempts to get/set values which are out of bounds results in a run-time error."

That is not what the language guarantees, and relying on it will cost you. The subscript operator on a vector performs no bounds checking whatsoever. Indexing outside the valid range is undefined behavior: the standard says nothing at all about what happens next. In practice it may crash, and often does when the index is wildly wrong — but it may equally well read whatever bytes happen to be next in memory and carry on as if nothing were wrong. Writing out of bounds may silently corrupt an unrelated variable.

The corrected statement to memorize: an out-of-bounds subscript is undefined behavior — often a crash, never a promise. The method that does promise a run-time error is at(), which we meet below and which the course notes never mention.

Definition— undefined behavior

Undefined behavior means the C++ standard places no requirement at all on what the program does. It is not "an error", it is not "unspecified but one of a few options" — it is a blank check. A program with undefined behavior may crash, may produce wrong answers, may appear to work perfectly on your machine and fail on the grader's, and may behave differently at two different optimization levels.

Undefined behavior is why C++ is fast: the compiler is allowed to assume you never do it, and can therefore skip every check. It is also why C++ is dangerous, and why the discipline of checking your own indices is not optional.

Worked Example— reading v[10] from a three-element vector

A vector of size 3, so the only legal indices are 0, 1 and 2. Then we read index 10. Before you reveal, commit to an answer: does this program crash, print something, or refuse to compile?

The value 1634038304 is machine-dependent and shown here only as a representative result. It is not "the value of v[10]", because there is no such element; it is whatever bit pattern happened to be sitting seven ints past the end of the vector's storage on this run, on this machine, with this compiler. On a different machine it could be a different number, a zero, or a crash.

Now sit with the consequence. If v[10] had been on the left of an assignment, the program would have written that number into memory it does not own. Nothing would have printed. The damage would surface later — a different variable with an impossible value, a crash three functions away — and the line that actually caused it would look innocent.

So the notes' claim is true of this particular program on this particular machine, and that is exactly the trap. Two programs, both making the same category of mistake: one dies loudly, the other lies quietly. You cannot tell which you will get, which is why you must not rely on either.

The other half of the notes' advice is completely sound, though, and worth repeating: you must populate a vector before you attempt to get or set its elements. A vector declared with no length has size 0 and no valid indices at all. Populating it is §6.

The checked alternative: at()

C++ does offer a subscript that checks. It is a method called at(), it takes the index as an argument instead of putting it in brackets, and when the index is out of range it does something specific and reliable.

Definition— at() and std::out_of_range

v.at(i) means the same element as v[i] when i is in range, and can be read or assigned in exactly the same way. The difference is what happens when i is not in range: at() throws an exception of type std::out_of_range.

An exception that nobody catches terminates the program immediately, with a diagnostic message naming the problem. That is a genuine, guaranteed run-time error — the thing the course notes claim [] gives you, delivered by the method that actually gives it.

The cost is a comparison on every access, which is why [] exists and why it is what you will use in ordinary loops. The rule of thumb: use [] when the index provably comes from the loop bounds; reach for at() when the index came from somewhere you do not control, or when you are hunting a bug.

6.Growing a vector: push_back and size()

We have declared vectors of a length known when the line was written. The whole promise of this type, though, was that the length can be decided while the program runs. Here is how.

The course notes state the rules precisely:

  • New elements can be added to a vector only at the end of the vector.
  • Elements can also be removed from the end of a vector.
  • In other words, we can both increase and decrease the length of a vector during program execution.
  • To add extra elements to a vector, we employ the push_back() method.
Definition— push_back and size

v.push_back(value) appends value to the end of the vector, increasing its size by exactly one. It is the only way we will add elements this semester. There is no push_front on a vector, and you cannot create an element by assigning to an index that does not exist yet.

v.size() returns the number of elements currently stored. It is a question, not a command — it changes nothing. After k calls to push_back on a fresh vector, v.size() is k and the valid indices are 0 through k - 1.

Common Mistake— assigning to an index that does not exist

This is the number one vector bug and it looks completely reasonable:

vector<int> v;         // size 0
v[0] = 5;              // WRONG: there is no element 0 to assign to

It compiles. It is undefined behavior, for exactly the reasons in §5. The vector does not grow to accommodate you — growing is push_back's job, and nothing else's:

vector<int> v;         // size 0
v.push_back(5);        // size 1; v[0] now exists and equals 5
v[0] = 9;              // fine: element 0 exists, so this overwrites it

The rule to say out loud: push_back creates elements; [] only changes ones that already exist.

Common Mistake— the signed/unsigned warning

You will be tempted to skip the extra variable and write the call straight into the loop condition:

    cout << v[i] << " ";
}

This works, and you will see it in this course's own exam solutions. But compile with -Wall and:

signcmp.cpp: In function 'int main()':
signcmp.cpp:9:23: warning: comparison of integer expressions of different signedness: 'int' and 'std::vector<int>::size_type' {aka 'long unsigned int'} [-Wsign-compare]
    9 |     for (int i = 0; i < v.size(); ++i) {      // int compared with an unsigned size

size() does not return an int. It returns an unsigned type — a type that cannot represent negative numbers, because a length never is one. Comparing a signed int against an unsigned value forces a conversion, and the conversion goes the surprising way: the int becomes unsigned, so a negative i would turn into an enormous positive number.

It is a warning, not an error, and at the sizes in this course nothing goes wrong. Two clean ways to silence it, both used in this course's materials:

int n = v.size();                                  // capture it once, as an int
for (int i = 0; i < n; ++i) { /* ... */ }

for (size_t i = 0; i < v.size(); ++i) { /* ... */ } // or match the type

Prefer the first; it is the form the course notes themselves use, it reads well, and it makes the loop bound obvious. Never ignore a warning just because the program runs.

7.Passing a vector to a function

In Class 2 we took apart the two ampersands that made swap2 work and swap1 a no-op. That distinction — call by value versus call by reference — becomes much more consequential now, because a vector can be big.

ParameterCopy made?Can the function change the caller's vector?Use it when

Worked Example— by value, by reference, by const reference

Three functions, all with the same body apart from the parameter. The first takes a copy, the second a reference, the third a const reference and only reads. Predict all five lines of output.

passing.cpp
// passing.cpp -- a vector parameter taken by value is a COPY
#include <iostream>
#include <vector>
using namespace std;

// by value: v is a brand-new vector, initialized from a copy of the argument
void doubleAll(vector<int> v) {
    int n = v.size();
    for (int i = 0; i < n; ++i) {
        v[i] = 2 * v[i];
    }
    cout << "  inside doubleAll:    " << v[0] << " " << v[1] << " " << v[2] << endl;
}

// by reference: v is another name for the caller's own vector
void doubleAllRef(vector<int> &v) {
    int n = v.size();
    for (int i = 0; i < n; ++i) {
        v[i] = 2 * v[i];
    }
    cout << "  inside doubleAllRef: " << v[0] << " " << v[1] << " " << v[2] << endl;
}

// by const reference: no copy is made, and the compiler forbids writing to it
void printAll(const vector<int> &v) {
    int n = v.size();
    for (int i = 0; i < n; ++i) {
        cout << v[i] << " ";
    }
    cout << endl;
}

int main() {
    vector<int> nums;
    nums.push_back(1);
    nums.push_back(2);
    nums.push_back(3);

    cout << "before:                "; printAll(nums);

This is Class 2's swap1 and swap2 all over again, with a container instead of two ints.

  • doubleAll genuinely doubled everything — it printed 2 4 6 from the inside. Then it returned, its private copy was destroyed, and the caller's vector was exactly as it had been. The work was real and completely wasted.
  • doubleAllRef differs by a single & and the change survives the return, because v was never a copy — it was another name for nums.
  • printAll takes a const reference and is called three times without ever copying the data.

Now the part that does not show up in the output at all, and matters more than the part that does: every call to doubleAll copies the entire vector, element by element. With three elements that is invisible. With a vector of a million doubles it is eight megabytes of copying, per call, silently, because someone left out one character. That is why "pass by const reference" is the default advice for any parameter that is not a simple built-in type.

You will see exactly how that copy is made, and be asked to write the code that makes it, when we reach the copy constructor in Class 14.

Compile-time error, no executable produced — the same "assignment of read-only" phrasing you met in Class 1, now applied to an element reached through a const reference. The const does not merely apply to the vector object itself; it reaches through [] to the elements as well.

This is the payoff of the const in the signature. A reader of void printAll(const vector<int> &v) knows, without reading one line of the body, that calling it cannot change their data. The compiler has already checked.

Key Idea

For a vector parameter, pick in this order:

  1. Only reading it? const vector<T> &v.
  2. Modifying the caller's vector on purpose? vector<T> &v.
  3. Need a scratch copy you can wreck? vector<T> v — and say so in a comment, so the next reader knows the copy is deliberate.

Plain vector<T> v chosen by accident is the most expensive typo in the language.

Things to notice. Use this as a design check on your own code. Problem 1 — The polygon vertices (from the course notes)

The course notes pose this and move on: suppose we want to have arrays x and y of type double, to hold the (x, y) coordinates of the vertices of a polygon. Solve it. Write a program that reads vertex coordinates until the user enters the pair -1 -1, stores them in two parallel vectors, prints them back, and reports the perimeter of the polygon.

Plan. The reason an array cannot do this job is that the vertex count is not known until the user stops typing, so start with two empty vectors and push_back a coordinate into each on every reading. The two vectors stay the same length by construction, which is what makes them parallel: vertex i is (x[i], y[i]).

For the perimeter, add the distance from each vertex to the next, and wrap the last vertex back around to the first — that closing edge is what makes it a polygon rather than an open path. The index of "the next vertex" is (i + 1) % n, which is i + 1 everywhere except the last step, where it becomes 0.

The reading function needs to fill the caller's vectors, so its parameters are plain references. The perimeter function only reads, so its parameters are const references.

polygon.cpp
// polygon.cpp -- the polygon problem from the course notes, solved with vectors
#include <iostream>
#include <cmath>
#include <vector>
using namespace std;

// read vertices until the sentinel pair, into two parallel vectors
void readVertices(vector<double> &x, vector<double> &y) {
    double a, b;
    cout << "Enter x y for each vertex (-1 -1 to stop): ";
    cin >> a >> b;
    while (!(a == -1 && b == -1)) {
        x.push_back(a);
        y.push_back(b);
        cin >> a >> b;
    }
}

double perimeter(const vector<double> &x, const vector<double> &y) {
    int n = x.size();
    if (n < 2) return 0.0;

    double total = 0.0;
    for (int i = 0; i < n; ++i) {
        int j = (i + 1) % n;                 // wrap the last vertex back to the first
        double dx = x[j] - x[i];
        double dy = y[j] - y[i];
        total += sqrt(dx * dx + dy * dy);
    }
    return total;
}

int main() {
    vector<double> x;

Problem 2 — Evens and odds (from the Fall 2023 Exam 1)

Write a complete C++ program that does the following.

  1. The program asks the user to enter some integers until 0 to stop.
  2. Stores those numbers into a vector or vectors.
  3. Then prints the even and odd numbers separately.

An example run of the program follows:

Enter some integers until 0 to stop: 2 4 3 1 5 8 9 6 7 0
Evens: 2 4 8 6
Odds: 3 1 5 9 7

Plan. Three stages, and the grading rubric for this question pays for each separately: a standard beginning and ending; a read-into-a-vector loop; and the two filtered prints.

The input loop is the sentinel pattern: read one value before the loop, then loop while it is not 0, pushing and reading again at the bottom. That ordering is what keeps the sentinel out of the vector.

For the printing there are two equally acceptable designs. One vector plus two filtered passes is shown here; two vectors, sorting each input as it arrives, is the other, and the professor's own rubric gives both.

evensodds.cpp
// evensodds.cpp -- read integers until 0, then print the evens and the odds
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int x;
    vector<int> v;

    cout << "Enter some integers until 0 to stop: ";
    cin >> x;
    while (x != 0) {
        v.push_back(x);
        cin >> x;
    }

    int n = v.size();

    cout << "Evens: ";
    for (int i = 0; i < n; ++i) {
        if (v[i] % 2 == 0) cout << v[i] << " ";
    }
    cout << endl;

    cout << "Odds: ";
    for (int i = 0; i < n; ++i) {
        if (v[i] % 2 != 0) cout << v[i] << " ";
    }
    cout << endl;
    return 0;
}
Enter some integers until 0 to stop: Evens: 2 4 8 6
Odds: 3 1 5 9 7

The run above was fed the sample input from a file rather than typed, which is why the digits do not appear after the prompt. The two result lines match the exam's sample run exactly.

Things to notice.

  • The alternative design, straight from the rubric, sorts on the way in: 
    vector<int> evens, odds;
cin >> x;
while (x != 0) {
    if (x % 2 == 0) evens.push_back(x);
    else            odds.push_back(x);
    cin >> x;
}
    Two vectors, one pass, no filtering at print time. Either answer receives full credit; pick whichever you can write correctly under time pressure.
  • x % 2 == 0 is the even test. For possibly-negative input be careful: -3 % 2 is -1 in C++, not 1, so testing x % 2 == 1 would miss every negative odd number. Testing != 0 is safe.
  • The trailing space after each number matches the sample run. Prompt strings and spacing are part of the specification on this professor's exams — copy them from the sample run exactly.
  • Note what is not here: no array, no maximum size, no count-first pass over the input. The rubric's own wording is "stores those numbers into a vector or vectors", and this is the reason vectors are taught before the first exam.

Problem 3 — Average and above-average (from the Winter 2025 Midterm)

Write a complete C++ program that does the following.

  • The program asks the user to enter some positive integers until 0 to stop.
  • The program should set up just enough space to store those inputs.
  • Then print the average of those input values and all the inputs above the average.

An example run of the program follows:

Enter some positive integers (0 to stop): 3 1 4 1 5 9 2 6 0
Average of those inputs: 3.875
Inputs above the average: 4 5 9 6

Plan. "Set up just enough space to store those inputs" is the exam's way of saying do not declare a fixed array of 100. A vector grown by push_back holds exactly as many as arrive.

The average needs the total and the count. Accumulate the total inside the input loop so no second pass is needed, and take the count from size(). Declare the total as a double so that total / n is floating-point division — if both were int the answer would be 3, not 3.875.

Then one more pass compares each stored value against the average. Note that this pass is only possible because the inputs were stored; a running average alone would not let you go back and filter them.

average.cpp
// average.cpp -- read positive integers until 0, print the average and everything above it
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int x;
    vector<int> v;
    double total = 0;

    cout << "Enter some positive integers (0 to stop): ";
    cin >> x;
    while (x != 0) {
        v.push_back(x);
        total += x;
        cin >> x;
    }

    int n = v.size();
    if (n == 0) {
        cout << "No inputs." << endl;
        return 0;
    }

    double average = total / n;
    cout << "Average of those inputs: " << average << endl;

    cout << "Inputs above the average: ";
    for (int i = 0; i < n; ++i) {
        if (v[i] > average) cout << v[i] << " ";
    }
    cout << endl;
    return 0;
}
Enter some positive integers (0 to stop): Average of those inputs: 3.875
Inputs above the average: 4 5 9 6

Things to notice.

  • The average of 3, 1, 4, 1, 5, 9, 2, 6 is 31/8 = 3.875, and it prints as 3.875 — four significant digits, comfortably inside cout's default of six. An average like 31/7 would print as 4.42857, six digits and no more.
  • The comparison v[i] > average compares an int with a double. C++ converts the int to double and compares exactly, so 4 makes the cut and 3 does not.
  • total is double even though every input is an int. That single choice is what makes the division correct. Writing int total and then double average = total / n; is the classic error — the division happens before the conversion, so 31/8 becomes 3 and only then becomes 3.0.
  • The published rubric for this question contains several typos in its own solution code, among them a missing semicolon and a total variable that is never declared. Read exam solutions critically; compile before you trust.
  • The n == 0 guard is not in the rubric, but dividing by size() when the user types 0 immediately would divide by zero. It costs three lines.

Problem 4 — A function over two vectors (from the Fall 2023 Final)

Write a function called calc_grade that takes in an integer vector for grades and a double vector for weights on grades with equal size, and returns the weighted grade. If the sizes of the two given vectors do not match, return -1.

For example, a program that uses the function follows:

int main() {
    vector<int> grades{85, 90, 70, 65};
    vector<int> grades2{80, 80, 80};
    vector<double> weights{0.1, 0.2, 0.3, 0.4};

    cout << calc_grade(grades, weights) << endl;
    // prints 73.5, since 85*0.1 + 90*0.2 + 70*0.3 + 65*0.4 = 73.5

    cout << calc_grade(grades2, weights) << endl;
    // prints -1, since grades2 has size 3 and weights has size 4

    return 0;
}

Plan. Read the specification for the three things it is paying for. The title line comes first: the return type is double because a weighted average is fractional, and both parameters are const references because the function only reads them and neither should be copied. The professor's own rubric awards two points for that line alone.

Then the size check, which must come before any loop — if the sizes differ, there is no meaningful index range to loop over. Then the accumulation: a running double total, one pass, multiplying matching elements.

calcgrade.cpp
// calcgrade.cpp -- a weighted grade from two parallel vectors
#include <iostream>
#include <vector>
using namespace std;

double calc_grade(const vector<int> &grades, const vector<double> &weights) {
    if (grades.size() != weights.size()) {
        return -1;
    }

    double weighted_grade = 0;
    int n = grades.size();
    for (int i = 0; i < n; ++i) {
        weighted_grade += grades[i] * weights[i];
    }
    return weighted_grade;
}

int main() {
    vector<int>    grades{85, 90, 70, 65};
    vector<int>    grades2{80, 80, 80};
    vector<double> weights{0.1, 0.2, 0.3, 0.4};

    cout << calc_grade(grades, weights)  << endl;   // 73.5
    cout << calc_grade(grades2, weights) << endl;   // -1
    return 0;
}
73.5
-1

Things to notice.

  • The size check is what the vectors' self-knowledge buys you. With raw arrays the function would have to be told both lengths and could not detect the mismatch at all — it would read past the end of grades2 and return a garbage number.
  • grades[i] * weights[i] is int times double, so the product is a double and nothing is truncated. Had weighted_grade been declared int, 73.5 would have come out as 73.
  • return -1; returns the int -1 from a function declared to return double; it is converted to -1.0 and prints as -1, matching the specification. Using a sentinel value like this is common but fragile — if a legitimate weighted grade could ever be -1, the caller could not tell the two apart.
  • The professor's rubric accepts the by-value signature double calc_grade(vector<int> grades, vector<double> weights) as well. It is correct, and it copies both vectors on every call for no reason. Write the const reference version.
  • The braces in vector<int> grades{85, 90, 70, 65}; list the contents, so that vector has size 4 — the §3 rule, appearing on a real exam.

Problem 5 — What is the output? (adapted from the Fall 2023 Exam 1)

Consider the following program. State the exact output at each of the three labelled lines.

#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> v;
    for (int n = 1; n < 10; ++n) {
        if (n % 2 == 0) v.push_back(n);
        if (n % 3 == 0) v.push_back(n);
    }
    cout << v.size() << v[0] << endl;                  // line (a)
    cout << v[1] << v[2] << v[3] << endl;              // line (b)

    vector<double> w(3, 1.5);
    w[1] = 4;
    cout << w.size() << " " << w[0] << " " << w[1] << " " << w[2] << endl;   // line (c)
    return 0;
}

(a) What is the output at line (a)?

Plan. Build the vector one iteration at a time. The two ifs are independent, so a value of n divisible by both 2 and 3 is pushed twice.

2yesno2

5nono2 3 4

So the size is 7 and v[0] is 2, printed with nothing between them:

72

Not "seventy-two". This professor prints a size immediately followed by an element on purpose, and the whole point of the question is whether you notice that two separate numbers have been run together.

(b) What is the output at line (b)?

From the final contents 2 3 4 6 6 8 9: v[1] is 3, v[2] is 4, v[3] is 6.

346

The trap here is the double push at n = 6. If you assumed one push per iteration you would have the contents as 2 3 4 6 8 9, size 6, and would answer 62 for (a) and 346 for (b) — right for the wrong reason on (b) and wrong on (a). Track the vector, not the loop counter.

(c) What is the output at line (c)?

vector<double> w(3, 1.5); is the sized-and-filled form: three elements, all 1.5. Then w[1] = 4; overwrites the middle one. The 4 is an int literal converted to the double 4.0 on the way in.

Across all three parts, the discipline that gets you full marks is the same: keep an explicit written record of the container's contents after every statement that changes it, then read the cout chain left to right, printing only what is actually there. Parts like these carry no partial credit.

Problem 6 — Write five C++ statements (added)

Write C++ statements to carry out the following tasks. Do not write a complete program; give a single line, or a few lines, of C++ for each.

  1. Declare an empty vector of double called prices.
  2. Declare a vector of 4 ints called counts, every element equal to 1.
  3. Append the value 19.99 to prices.
  4. Change the third element of counts to 7.
  5. Print, on one line separated by spaces, the number of elements in counts, the third element of counts, and the first element of prices.

Plan. Only two of the five require thought. Task 4 says the third element, and indices count from zero, so that is counts[2] — the single most common way to lose the point on a question like this. Task 3 says append, which is push_back and never prices[0] = 19.99;, because prices is empty and element 0 does not exist yet.

Here are the five statements, wrapped in a program so they can actually be run:

fivestatements.cpp
// fivestatements.cpp -- the five statements, in a program so they can be run
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<double> prices;                          // (1)
    vector<int> counts(4, 1);                       // (2)
    prices.push_back(19.99);                        // (3)
    counts[2] = 7;                                  // (4)
    cout << counts.size() << " " << counts[2] << " " << prices[0] << endl;   // (5)
    return 0;
}
4 7 19.99

Things to notice.

  • The order of statements (3) and (4) is not interchangeable with the declarations. Statement (4) is legal only because counts was declared with four elements; the same line applied to prices would be undefined behavior.
  • counts.size() prints 4, not 3. Changing an element never changes the size; only push_back does, in this class.
  • 19.99 prints as 19.99 — four significant digits, inside cout's default of six. A price of 19.90 would print as 19.9.
  • On an exam that asks for five statements, write exactly five and number them in comments. This format is uniformly weighted and usually carries no partial credit, so a clearly labelled answer to four of the five still scores four fifths.
Lecture Summary
  • An array's length is fixed when you write the code and the array does not know its own length. A vector fixes both problems: think of it as a generalized array that carries its length inside itself and can change it while the program runs.
  • You need #include <vector>. The element type goes in angle brackets: vector<int>, vector<double>, vector<string>.
  • Four declaration forms: vector<int> v; (size 0), vector<int> v(n); (n elements, all zero), vector<int> v(n, 7); (n elements, all 7), and vector<int> v{1, 2, 4}; (exactly those three elements). Parentheses describe the vector; braces list its contents.
  • The length in parentheses may be a variable. It is parentheses, (n), never square brackets [n] — vector<int> v[n]; is an array of n vectors.
  • Get and set with [], exactly as for an array. Valid indices are 0 through size() - 1.
  • An out-of-bounds subscript is undefined behavior, not a guaranteed run-time error. It may crash, and it may just as easily read or write memory it does not own and keep going. at() is the checked alternative: it throws std::out_of_range and stops the program with a message naming the index and the size.
  • push_back(value) appends one element and increases the size by one — it is the only way to create elements. Assigning to an index that does not exist does not grow anything.
  • size() reports the current number of elements. Capture it as int n = v.size(); before a loop to keep -Wall quiet about the signed/unsigned comparison.
  • Pass a vector by const reference when the function only reads it, by plain reference when it must modify the caller's vector, and by value only when you deliberately want a scratch copy — a by-value vector parameter copies every element.
